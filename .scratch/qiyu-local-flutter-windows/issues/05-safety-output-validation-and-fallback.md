# 05 — 固化安全门、输出清洗与本地降级

**What to build:** 将栖语现有的安全前置判断、输入清理、人格边界、违禁话术验证和降级策略迁入 Dart 主链路，确保真实模型不能绕过产品行为约束。

**Blocked by:** 04「打通持久 Provider 配置与真实模型回复」

**Status:** ready-for-agent

- [ ] 危机、医疗等非 normal 输入在调用模型之前被分类，并只走本地安全回复。
- [ ] 危机回复保留中国大陆适用的求助信息和简短陪伴，不继续展开普通聊天任务。
- [ ] 用户输入中的类 XML 注入标签和控制结构在进入模型上下文前被剥离或转义。
- [ ] 模型输出必须经过结构清理、空回复检查、违禁话术检查和人格边界检查后才能展示。
- [ ] 任一验证失败、超时、网络错误或非法响应均产生可诊断的 fallback reason，并回到本地规则引擎。
- [ ] 日志、错误和诊断信息统一脱敏，不包含 API Key、完整敏感输入或 Provider 授权头。
- [ ] 共享契约样例在 Dart 实现上全部通过；测试证明安全输入不会产生任何外部模型请求。
