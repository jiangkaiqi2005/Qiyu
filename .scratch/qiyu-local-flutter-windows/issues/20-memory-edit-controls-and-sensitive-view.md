# 20 — 完成记忆编辑、控制与敏感查看

**What to build:** 在记忆中心提供经过确认的编辑、冻结、禁止提及、删除和敏感证据查看操作，使用户真正拥有本地记忆的控制权。

**Blocked by:** 18「让记忆控制贯穿聊天和整理管线」、19「提供四区只读记忆中心」

**Status:** done

- [x] 用户可以修正可编辑的记忆文本；修正作为用户声明保存，不伪装成原始会话证据。
- [x] 冻结、解除冻结和禁止提及操作立即反映在界面，并在下一轮聊天与后台整理中生效。
- [x] 删除前展示准确影响范围，包括会被重建或清理的索引和派生理解，不使用含糊的全部删除表述。
- [x] 查看敏感证据需要明确的临时揭示动作，离开页面或超时后重新遮罩，不写入日志或剪贴板。
- [x] 编辑或控制后只重建必要的派生层，原始会话除用户明确删除外保持不变。
- [x] 每次操作都有成功、部分失败和可恢复失败结果；失败时旧有效数据保持可用。
- [x] 测试覆盖编辑来源、冻结、禁止、删除范围、敏感遮罩、最小重建、失败回滚和跨重启一致性。

**Resolution（2026-08-19）：**

- Host 新增 `memory_actions.dart`：`POST /api/memory/action` 统一动作端点（edit / freeze / unfreeze / ban / unban / delete-preview / delete / reveal），复用会话 Cookie、Origin 与 CSRF，沿用记忆中心的 opaque ID（注册表解析在 `MemoryCenterService.resolveRef`）。
- 编辑即可编辑层：long-memory 条目（含「共同过往」）与 episode 条目。episode 修正按用户声明保存——条目标记 userEdited、原始摘录移除、sessions 原文不变；画像只能通过对话纠正，界面不提供画像编辑。
- 控制沿用 T24 定稿写入纪律：先写 memory-controls.md（origin `memory-center`）再动派生层；controls 不可写时一律拒绝动作（可恢复失败）。冻结/禁提经既有的读取时过滤在下一轮聊天与后台整理生效；禁提另清画像与未闭环事项，与聊天路径同一实现（LocalChatService 删除管线并入 MemoryActionService，聊天与界面共用）。
- 删除先走 delete-preview 返回逐层准确计数与用户语言影响清单（含索引重建与理解元数据过滤），确认后执行；sessions 保留，重复执行安全；状态包各行不是控制对象，只读展示。
- 揭示为明确临时动作：原文只返回一次、不落盘、不进诊断日志；Flutter 侧详情页 20 秒超时或离开页面自动重新遮罩，列表遮罩条目经一次性对话框查看，原文不可选择复制。
- 三态结果贯穿两端：success / partial（控制已生效、个别派生清理推迟，后续触发补齐）/ failed（retryable，旧数据保持可用）。
- 验证：Host 316 测试（新增 memory_actions_test 15 用例与 HTTP 动作集成用例）、Flutter 53 测试（新增编辑/冻结/禁提确认/删除预览/揭示超时/忙碌态等用例）全绿；verify:migration-baseline 全量通过。浏览器真实测试按用户安排归 ticket 25 打包验收。
- 双轴 code-review（Standards/Spec，基线 fbd1f92 起全部改动）后修复：
  - 客户端不再把无 status 字段的 4xx 错误体误判为成功（fromWire 只认显式三态，非 2xx 一律转可重试失败）；
  - 部分失败消息统一 `join('、')`，消除 List 直接插值的方括号；
  - 删除预览画像计数补上未归类叶，与 applyBan 实际清除范围对齐（定位扫描同步纳入）；
  - 揭示入口补齐画像根/中间理解详情页与「某一天」遮罩小结（day 引用传 summary 字段）；
  - 动作执行中呈现忙碌态：详情页「整理中」指示、列表菜单与详情页按钮禁用（T25「重建期间显示整理中」的落地形态——重建同步包含在请求内，响应返回即落盘确认）；
