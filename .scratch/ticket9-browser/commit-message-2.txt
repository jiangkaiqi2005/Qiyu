按定稿装配图重排 system prompt，人格宪法替换产品灵魂注入

此前实现把《栖语产品灵魂》全文（约 32KB）注入 prompt，并自造了
<recent_state> 块，与设计笔记《栖语system prompt具体实现》的 T11
定稿装配图不符。本次按定稿重排并统一命名：

- 新增 栖语人格宪法.md（设计笔记定稿的八节人格宪法，约 3.7KB），
  替换《栖语产品灵魂》全文注入；产品灵魂退回为纯设计文档，不再进
  prompt。加载链路（resolvePersonaConstitutionPath → runner →
  host → builder）与打包产物（persona-constitution.md）同步改名。
- 硬规则与优先级精简为四节核心：输出契约 / 首个可见回应速度 /
  事实来源优先级 / 安全与专业边界；原「默认少说、禁止客服式共情、
  晚安只收束」并入输出契约节。
- 隐藏块协议抽成独立常量，放在静态区（硬规则之后、动态块之前）：
  它是输出契约唯一授权的例外，需与之相邻；静态前缀在聊天轮与未来
  日终总结请求间逐字复用，便于前缀缓存与共享同一协议。尾部保留
  靠近生成位置的格式提醒。
- 命名对齐装配图：删除自造的 <recent_state>，动态块统一为
  <daily_state>【近况】/ <long_memory>【长期印象】/ <persona>
  【用户画像】，并预留 memoryContext 注入位；四块均遵循「空块不
  输出」，状态包与画像文件（tickets 10-13）落地后自动填充。
- 新增 model_prompt_builder_test 覆盖装配顺序、空块不输出、动态块
  中文小标题、检索结果只进本轮上下文与格式提醒位置；既有测试的
  命名与断言同步更新。
