# Spec：栖语 Web 前端「紫夜」视觉改造

日期：2026-08-28
状态：ready-for-agent（仓库无外部 issue tracker，按惯例发布于本目录）
设计依据：四轮设计定稿（含 2026-08-28 第四轮待定项收口），规范全文见 `docs/product/design-system.md`，决策清单见 `docs/product/frontend-design-decisions.md`，取舍理由见 ADR 0004；可交互视觉基准为 `.scratch/qiyu-prototype/index.html`。

## Problem Statement

栖语现在的 Flutter Web 界面还停在早期 Material 3 种子色直接派生的样子：界面整体发紫、组件各页各画、发送按钮粉嫩低对比、页面之间视觉语言不统一。它不像一个「深夜里安静陪着你」的产品，更像一个没做完的 demo。用户对它的直观评价是「不够高级」。

## Solution

按已定稿的「紫夜」设计系统对全部四个界面做一次完整视觉改造（只换皮，不动任何行为与信息架构）：建立唯一的设计 token 主题层，统一色板、字体、几何与组件形态；首页与对话合一；桌面常驻毛玻璃侧边栏、窄屏汉堡抽屉；历史、记忆中心、设置三页按定稿形态换皮。改造后界面遵循三色纪律——紫住强调、暗红住危险、其余全中性暗夜色。

## User Stories

1. 作为栖语用户，我打开应用看到一个虚化夜景背景上的居中问候语和输入框，所以我感觉走进的是一个安静的房间而不是一个工具。
2. 作为栖语用户，我发出第一句话后背景与问候淡出、消息流长出、输入框落底，所以开始聊天没有任何页面跳转的打断。
3. 作为栖语用户，我看到栖语的回复是没有气泡的宋体文字，所以读起来像一页书而不是群聊记录。
4. 作为栖语用户，我看到自己说的话有右对齐的深色气泡，所以回看时能一眼分清谁说的。
5. 作为栖语用户，我在桌面端始终看到左侧 240px 的毛玻璃侧边栏，所以我随时能去历史、记忆中心、设置而不迷路。
6. 作为栖语用户，我点侧边栏顶部的品牌图标就回到空状态首页，所以「回栖语那去」永远有一键。
7. 作为栖语用户，我在窄屏上看到左上角三条杠，点开后抽屉覆盖约三分之二宽度露出同样的三项导航，所以手机上导航不占常驻空间。
8. 作为栖语用户，我看到发送按钮是深鸢尾紫渐变的圆形、生成中变成停止钮，所以唯一的强调色出现在我最常用的动作上。
9. 作为栖语用户，我发现界面里除了发送按钮和键盘焦点外没有任何紫色，所以整个夜晚是安静的，颜色不吵。
10. 作为栖语用户，我在历史页看到按天分组的会话卡片，每张写着时间、消息数和第一句话，所以我知道哪晚聊过什么。
11. 作为栖语用户，我在最新一条历史上看到「继续这段对话」，所以接着昨晚说下去是零成本的事。
12. 作为栖语用户，我删除一段会话前有明确的影响说明和确认，而且删除按钮平时是低调的次要色，所以危险动作既安全又不扎眼。
13. 作为栖语用户，我在记忆中心用「最近发生 / 长期印象 / 关于你 / 我们的关系」四个区看栖语记得的东西，所以我理解它眼中的我。
14. 作为栖语用户，我看到每条记忆下面一直摆着编辑、冻结、禁提、删除，所以我随时能处置栖语记得的东西，不需要找菜单。
15. 作为栖语用户，我遇到涉及私密信息的记忆条目看到的是遮罩提示而不是原文，所以我的隐私在界面上就被守住。
16. 作为栖语用户，我做删除记忆、清除产品数据这类操作时看到的是暗红色按钮加确认弹窗，所以破坏性动作一眼可辨。
17. 作为栖语用户，我进入设置页看到的是一页清爽的分节标题列表而不是七八张卡片，所以我不会被一堆盒子吓到。
18. 作为栖语用户，我点设置分节标题就能展开或收起它，而且上次收起来的下次进来还收着，所以设置页永远是我离开时的样子。
19. 作为栖语用户，我进设置页默认只看到展开的「模型连接」和「本地数据」，所以最常用的两节永远在手边。
20. 作为栖语用户，我在设置里配置模型、语音转写、语音朗读、联网搜索时看到同一套表单语言和同一句「Key 只存本机」的承诺，所以我放心填密钥。
21. 作为栖语用户，我用键盘操作时焦点有清晰的亮紫描边，所以我不会丢失自己在哪。
22. 作为栖语用户，我开启系统的减少动态效果后所有过渡立即消失，所以动效不会让我眩晕。
23. 作为栖语用户，我在手机上输入框全程在底部，所以单手打字永远够得着。
24. 作为栖语用户，我横向滚动的区域看不到浏览器滚动条控件，所以界面没有外来杂音。
25. 作为栖语用户，我在侧边栏（窄屏在抽屉）底部看到一枚中性小圆点和「栖语在本机」，所以我安心——它没连远端服务器，我的对话没出这台机器。
26. 作为栖语用户，本机 Host 探测失败时那枚圆点和文案转成暗红并告诉我怎么了，我点一下就能重试，所以我不用猜是不是自己弄坏了什么。
27. 作为实现者，我拿到一个唯一的设计 token 主题层，所有颜色字体圆角都从那里取，所以我不需要也不允许在任何页面散写视觉值。

## Implementation Decisions

1. **建立唯一设计 token 主题层**：全部语义色值、字族、字阶、圆角（8 / 18 / 胶囊 / 圆形，气泡另定 20 水滴形）、间距 4px 网格收进一个主题模块，替换现有 ThemeData 的种子色派生方式；所有页面只准消费这一层。
2. **定稿色板**：底色 `#0f0e14`、面板 `#181719`、字色 `#ece9f2`、次要字 `#9a94a8`、强调交互玻璃紫 `rgba(75,64,146,.62)→rgba(51,43,97,.5)`（半透明 + 模糊，无描边无白色高光）、强调状态 `#9d8fe0`（不透明，仅用于键盘焦点环 2px / offset 3px；不要与输入框聚焦描边的紫度 0.13 混为一谈，那是 composer 专属）、图标近白 `#f5f3fa`、用户气泡 `#28272e`（水滴形、无描边）、描边 `#232227`、危险 `#cc9999`（仅破坏性操作）。三色纪律：紫住强调、暗红住危险、其余中性。
3. **字体**：全局换思源宋体（Noto Serif SC），OFL 授权；由一次性资产准备脚本用 node `subset-font` 从 Google Fonts 完整 TTF 裁出静态子集，产物 `apps/qiyu_flutter/assets/fonts/NotoSerifSC-QiyuSubset.ttf`（实测 13.3MB、覆盖 28,083 码点）随包入库——不做构建期子集化，子集化脚本留 `.scratch/` 不入库、不进发布门禁。子集必须覆盖：U+4E00–U+9FFF（中日韩统一表意文字）、U+3400–U+4DBF（扩展 A，保人名生僻字）、U+3000–U+303F（CJK 符号与标点）、U+FF00–U+FFEF（半角与全角形式）、U+2010–U+2027（破折号、引号、省略号等通用标点）、U+0020–U+007E（基本拉丁）。同提交删除旧 `NotoSansSC-QiyuBaseline.ttf`（17.7MB 完整字族）与其 OFL 文件；`pubspec.yaml` 中的 `Roboto` 别名必须保留并改指新宋体资产——它是 2026-08 修「字体回退卡死」时为防止未随包字族触发远程回退而设，删掉会重新引入同一 bug。字阶问候 22 / 标题 18 / 正文 15（栖语的话行高 1.9）/ 次要 13 / 极小 12；精美优先，宁小勿大。
4. **图标**：Material Symbols 系、outlined、24px、**1.2 细描边**，优先曲线图形；选型已定案：导航三件套沙漏 / 翻开的书 / 圆形旋钮滑杆，记忆四区时钟 / 山形 / 单人 / 双人，记忆操作铅笔 / 雪花 / 禁止圈 / 垃圾桶 / 眼睛（细节见 design-system.md 第 4 节）。
5. **合一页**：首页与对话页合并为同一页面的两种状态；空状态显示背景图 + 问候 + 输入框，发出第一句后背景与问候淡出、消息流生长；从历史打开旧会话是同一页面的已有消息状态。
6. **首页背景**：美术馆参考图虚化（模糊约 5px）、亮度约 0.45、饱和度约 0.55，左右深色渐变向中间过渡、暗角要足；暖黄与紫夜混色经用户裁定可接受，验收不得以色温不一致返工。入库资产由 `scripts/prepare-visual-assets.ps1`（纯 PowerShell + System.Drawing，不依赖 Node/npm）从源图（4096×3072、6.19MB）一次性生成：等比缩到宽 1600、JPEG 质量 85，产物 `apps/qiyu_flutter/assets/images/home-night-backdrop.jpg`（实测 1600×1200、110KB；质量 65 实测仅 66KB 且暗部明显发糊，故定 85）；入库图保持原构图，虚化/暗角/亮度/饱和度全部运行时施加，便于调参不重新出图。若 CanvasKit 全屏 `ImageFiltered` 掉帧，改用预烘焙模糊图资产——实现期决定，须记录。
7. **导航壳**：桌面常驻 240px 毛玻璃侧边栏（半透明近黑面板 + 背景模糊），顶部品牌图标、三项导航（历史 / 记忆中心 / 设置）、底部连接状态；窄屏（约 760px 以下）左上角三条杠打开约 2/3 宽抽屉，内容同源。
8. **连接状态（本轮定案）**：侧边栏**底部**一枚 6px 中性小圆点 + 一行 13px `muted` 文案「栖语在本机」；正常态不着紫、不用 danger。仅 Host 健康探测失败时圆点与文案同时转 `danger` `#cc9999`，文案改为可点重试的措辞，点击重新探测。窄屏同款形态收进抽屉底部，不另设降级形态。数据源为既有 `features/baseline/host_connection_probe.dart`。
9. **品牌图标（本轮不做图形）**：侧边栏/抽屉顶部保留「点击回空状态首页」槽位，本轮视觉为中性几何占位（不着紫、无渐变）；原型里的「紫色渐变圆 + 自造波纹」占位不作数，实现不得沿用；最终图形设计仍待定。
10. **输入框（composer）**：毛玻璃、胶囊全圆角、发丝描边、内边距 6px、图标按钮 34px；桌面两段式（空态居中、发出第一句落底），窄屏全程底部。
11. **消息区**：单侧气泡——用户消息右对齐气泡，栖语的话无气泡书页式宋体。
12. **选中态全站中性**：侧边栏导航、记忆中心 tab 一律近白文字 + 中性暗底（`rgba(255,255,255,0.04)`）或淡白下划线，不用紫色。
13. **历史页**：日期分组次要色小标题 + 会话卡片（时间 · 消息数 / 首句预览 / 最新会话「继续这段对话」/ 删除图标常驻次要色）；信息与行为不变。
14. **记忆中心**：四区 tab 保留；条目操作按钮（编辑/冻结/禁提/删除）常驻、次要色、悬停提亮；敏感遮罩与临时揭示行为不变；横向滚动隐藏原生滚动条。
15. **设置页**：阅读式（无卡片，小字距次要色标题 + 发丝分隔线）；分节顺序固定为模型连接 → 语音朗读 → 语音转写 → 联网搜索 → 本地数据 → 隐私与边界 → 体验与开发者选项；分节可折叠（点标题），默认展开「模型连接」「本地数据」，折叠状态本地持久化（仅 UI 状态，与朗读音量用 localStorage 的先例同款，不进主持久化链路）；不做吸顶子导航。
16. **组件清单冻结**：主按钮、次/文字按钮、圆形图标按钮、发送按钮、输入框、导航项、列表项、卡片、抽屉、对话框/轻提示共 10 件，全部 M3 底子 + token 换皮，零第三方 UI 依赖；对话框直接用 M3 Dialog / SnackBar 换 token。
17. **无障碍与动效**：键盘焦点 2px 亮紫描边（offset 3px），焦点环需自绘——Material 3 的 `focusColor` 画不出带 offset 的外环；支持 prefers-reduced-motion 全关动效；动效 150–250ms 轻缓动；深底文字对比度留足余量。
18. **行为不变量**：路由、API、Host 交互、危险操作确认流、记忆控制语义一项不动；本次是纯视觉层改造。

## Testing Decisions

1. **好测试的标准**：只测外部可观察行为与 token 契约，不断言实现细节（不测某个 widget 树结构、不测私有样式）。
2. **新接缝——设计 token 层测试**：对主题模块写断言，锁死色板每个语义值、字族为思源宋体、圆角与字阶档位；这是防「实现时又散出色值」的主要新测试面。
3. **既有接缝——现有 widget 测试**：`accessibility_test.dart`、`settings_view_test.dart`、`memory_view_test.dart`、`history_view_test.dart`、`voice_chat_view_test.dart`、`app_test.dart` 等中与旧颜色值绑定的断言（如 ticket 24 的焦点色）随 token 同步更新；行为断言一项不改、必须全绿。
4. **最高门禁**：交付前跑 `verify-release-baseline.ps1` 全绿（Dart/Flutter/Host 分析测试、Web 构建、bundle、preflight、launch smoke），不依赖 Node/npm 的门禁结构不变。
5. **视觉验收**：以 `.scratch/qiyu-prototype/index.html` 为视觉基准逐页人工对照（首页空态/对话态、历史、记忆中心四区、设置折叠与顺序、窄屏抽屉）。
6. **连接状态断言**：正常态圆点与文案取中性值，测试锁死「不得出现 `accent-*` 紫，也不得出现 `danger`」；探测失败态断言圆点与文案同转 `danger` 且该处可点击触发重探（三色纪律的可执行化）。
7. **字体资产断言**：Dart 侧测试断言 `pubspec.yaml` 声明的宋体子集 asset 存在（`assets/fonts/NotoSerifSC-QiyuSubset.ttf`）、`Roboto` 别名仍指向随包字族且改指新子集、旧 `NotoSansSC-QiyuBaseline.ttf` 与其 OFL 已删除；字区 cmap 覆盖在资产准备期一次性核对（凭据为 Implementation Decisions 第 3 条清单，缺段即重新出图），不进 Dart/Flutter 门禁。
8. **导航文案与定位约束**：三项导航文案（历史 / 记忆中心 / 设置）全站唯一，不做同义改写；侧边栏与抽屉会同时渲染同一批标签，widget 测试必须以 `Key` 定位导航项与连接状态，不用 `find.text`（文本命中两处即歧义）。

## Out of Scope

- 任何行为、信息架构、路由、API、Host 交互的改动（换皮优先原则；发现问题另开 ticket）。
- 移动端原生（iOS/Android）版本。
- 旧金色方向与霞鹜文楷的任何复活。
- 品牌图标的最终图形设计——仍挂待定，本轮以中性几何占位落地（见 Implementation Decisions 第 9 条）。
- 记忆中心图标、发送按钮质感已在细节打磨轮定案（见 design-system.md 第 4 节与决策日志第三轮），不再属待打磨项。

注：连接状态呈现形式、背景图入库资产工艺、字体子集化工艺与字区覆盖已于 2026-08-28 收口，**属本次范围**（Implementation Decisions 第 3、6、8 条），不再按「实现时以原型占位为准、另行验收」处理。

## Further Notes

1. **剩余待打磨项**：只剩品牌图标的最终图形设计——本轮用中性几何占位落地，图形另行设计。连接状态呈现形式、背景图入库资产工艺、字体子集化工艺均已收口，不再属待打磨项。
2. 原型 `.scratch/qiyu-prototype/` 不入库（在 `.scratch` 下），实现期间它是**视觉真相源**，但只在形态与观感这一层成立：**token 命名与个别数值以 `docs/product/design-system.md` 为准**，两侧不一致时以规范为准并回报。原「任一侧改动必须同步另一侧」的说法做不到，撤掉——不要为了「凑一致」去改规范，也不要照抄下面这些已知不符规范的写法：
   - `--accent-deep-a: #55489c` / `--accent-deep-b: #463a85`：历史命名与命名值都不在 §2 的 token 表里。§2 定稿的强调渐变是 `accent-glass` 的 `rgba(75,64,146,.62) → rgba(51,43,97,.5)`（半透明两端 + 背景模糊），实现一律取 `QiyuColors.accentGlassA/B`。
   - `.toggle.on` 的选中实底用紫渐变：与三色纪律（§1、§2）和 User Story 9「除了发送按钮和键盘焦点外没有任何紫色」冲突。开关选中态属中性档，实现在主题层 `switchTheme` 里压回中性，视觉验收不得按原型的紫底返工。
   - `.brand-btn:hover`、`.nav-item:hover`、`.icon-btn:hover`、`.text-btn:hover`、`.mem-action:hover` 的悬停底是 `rgba(157,143,224,.06–.10)` 淡紫：§8 组件 7 定的是「悬停轻提亮」，实现取中性提亮。
   - 品牌图标占位（紫色渐变圆 + 自造波纹）不作数，实现改用中性几何占位（不着紫、无渐变，见 Implementation Decisions 第 9 条）；它原先还带一层 `inset 0 1px 1px rgba(255,255,255,.25)` 白色高光，直接违反 §8 组件 4「无描边、无白色高光」，已于 2026-08-28 从原型 CSS 删除。
3. 本次改造会触碰大量现有视觉断言，提交分段（用户 2026-08-28 定）：commit 0 文档基准（本 Spec 与设计规范/决策日志/ADR/CONTEXT 先行入库，作为 review 基准点）→ token 主题层与字体、背景图资产 → 合一页与导航壳（含连接状态）→ 历史 → 记忆中心 → 设置 → 硬编码色值收口与门禁复核；每段独立可测。
