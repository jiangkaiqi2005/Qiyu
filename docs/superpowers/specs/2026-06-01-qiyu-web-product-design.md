# 栖语 Web 产品设计与执行路线

> 日期：2026-06-01  
> 分支：`develop`  
> 范围：完整 Web 产品 / PWA / LLM 接入产品化  
> 不含：具体代码实现、原生 iOS/Android、商业化支付系统

---

## 1. 产品目标

栖语不是一个通用聊天机器人，也不是一个心理咨询工具。它是一个睡前 AI 陪伴产品：用户在一天结束后打开网页，和一个稳定、真实、有记忆、有自己重心的存在说话。

第一版完整 Web 产品要达到三个目标：

1. 用户第一次打开就知道它是什么，并愿意立刻说第一句话。
2. 用户聊完一晚后感觉“她像同一个人”，而不是一个模板 AI。
3. 用户能清楚控制模型配置、记忆、隐私和安全边界。

产品标准不是“能用”，而是“别人看到这个网站就想试，试完愿意晚上再回来”。

---

## 2. 产品定位

### 一句话定位

在你栖息的时刻，有人跟你说说话。

### 核心场景

用户晚上准备睡觉前，想把今天发生的事说给一个不会评判、不会敷衍、不会突然变成客服的人听。

### 不是这些东西

- 不是 ChatGPT 套壳。
- 不是心理咨询师。
- 不是恋爱陪聊。
- 不是效率助手。
- 不是情绪打卡工具。
- 不是社交社区。

### 成功感觉

用户不是觉得“这个 AI 很强”，而是觉得：

- “她记得我。”
- “她说话不像客服。”
- “她不会每句话都端着。”
- “她有时候短短一句，比长篇安慰更像人。”
- “我晚上确实想打开她。”

## 3. 产品原则

### 3.1 首屏就是产品

首页不要做传统 SaaS 营销页。第一屏应该直接让用户进入一场轻量试聊。

错误方向：

- 大标题 + 三个卖点 + CTA 按钮。
- “AI 情绪陪伴解决方案”这种抽象话术。
- 把真实产品藏在登录后。

正确方向：

- 用户打开就看到栖语。
- 页面安静，像深夜。
- 栖语先说一句短话。
- 用户可以立即输入。

### 3.2 人格一致性高于功能丰富

可以少功能，但不能人格漂移。

所有功能都要问一句：它会不会让栖语更像同一个人？如果不会，优先级下降。

### 3.3 配置不打扰普通用户

普通用户不应该一进来就看到 API Key、模型、temperature。

配置中心要分层：

- 默认用户看到体验设置。
- 高级用户打开 AI 设置。
- 开发者打开 Prompt / Eval / Debug。

### 3.4 记忆必须可见、可控、可删除

“她记得我”是产品核心，但“她偷偷记我”会摧毁信任。

每条记忆都要能看到来源，用户可以编辑、删除、冻结。

### 3.5 安全边界不能破坏人格

危机、安全、医疗、法律、金融等边界必须处理，但不能突然变成系统警告或客服声明。

安全回应仍然要像栖语本人说出来的。

## 4. 产品信息架构

建议第一版完整 Web 产品包含 7 个页面。

### 4.1 `/` 首页 / 试聊页

职责：

- 让用户 5 秒内知道产品是什么。
- 让用户 30 秒内完成第一轮对话。
- 展示产品气质，而不是解释产品。

核心模块：

- 栖语开场。
- 输入框。
- 轻量说明：“睡前说说今天。”
- 未登录试聊限制。
- 登录/继续入口。

首屏文案方向：

```text
栖语
在你栖息的时刻，有人跟你说说话。

今天过得怎么样？
```

验收标准：

- 首屏不需要滚动就能开始输入。
- 不出现“AI 大模型”“效率”“解决方案”等抽象词。
- 未登录用户能试聊 3-5 轮。

### 4.2 `/onboarding` 首次引导

职责：

- 让用户和栖语建立第一层关系。
- 获取必要偏好，而不是填表。
- 明确记忆和隐私边界。

步骤：

1. 栖语自我介绍。
2. 询问称呼。
3. 询问常用睡前时间。
4. 询问用户希望栖语怎么陪。
5. 解释记忆：会记住什么、不会记住什么、怎么删除。
6. 进入第一次完整夜聊。

引导风格：

- 像聊天，不像表单。
- 每屏只问一个问题。
- 允许跳过。
- 不使用“下一步 1/6”这种工具感强的流程，改用柔和进度。

验收标准：

- 90 秒内完成。
- 每一步都能跳过。
- 完成后用户自然进入聊天，而不是回到仪表盘。

### 4.3 `/chat` 主聊天

职责：

- 承载每日睡前对话。
- 呈现栖语人格。
- 管理节奏、沉默、记忆引用、安全边界。

核心体验：

- 多气泡回复。
- 输入中状态。
- 思考停顿。
- 短回复。
- 沉默。
- 晚安收束。
- 关系阶段差异。
- 情绪惯性。
- 记忆自然引用。

界面原则：

- 没有复杂工具栏。
- 不做信息流。
- 不堆功能按钮。
- 输入区稳定，移动端键盘不遮挡。
- 深夜模式默认开启。

聊天状态：

- 空状态：第一次打开。
- 正常对话。
- 栖语正在想。
- 栖语沉默。
- 用户晚安后收束。
- LLM 失败本地兜底。
- 安全风险回应。

验收标准：

- 用户连续聊 10 分钟不会频繁感到客服感。
- 用户说“晚安”后，栖语不再问新问题。
- LLM 失败时体验不中断。

### 4.4 `/memory` 记忆中心

职责：

- 让用户理解栖语记住了什么。
- 让记忆可控。
- 建立信任。

核心模块：

- 已记住的事。
- 最近使用过的记忆。
- 记忆来源。
- 记忆编辑。
- 记忆删除。
- “不要再提”。
- 关系阶段说明。

记忆分类：

- 日常偏好。
- 作息习惯。
- 工作/学习。
- 家人/关系。
- 身体/睡眠。
- 敏感记忆。

敏感记忆规则：

- 不在页面大面积展示。
- 默认折叠。
- 使用前谨慎。
- 用户可禁止进入 prompt。

验收标准：

- 用户能在 10 秒内删除任意记忆。
- 每条记忆都能看到来源。
- 用户知道哪些记忆会进入 LLM 上下文。

### 4.5 `/settings` 设置中心

职责：

- 配置体验。
- 配置 LLM。
- 管理隐私。
- 提供恢复默认。

分区：

1. 基本设置。
2. 对话体验。
3. AI 模型。
4. 记忆与隐私。
5. 安全与边界。
6. 开发者模式。

基本设置：

- 昵称。
- 常用睡前时间。
- 语言风格强度。
- 主题。
- 是否启用 PWA 安装提示。

AI 模型设置：

- API URL。
- API Key。
- Model。
- Temperature。
- Timeout。
- 连接测试。
- 恢复推荐配置。

开发者模式：

- system prompt 预览。
- 注入上下文预览。
- 最近一次禁用语检查。
- LLM 原始错误。
- 本地兜底原因。

验收标准：

- 普通用户默认看不到复杂模型参数。
- API Key 不进入浏览器可读持久化区域。
- 连接测试失败时给人话错误。

### 4.6 `/lab` 质量实验室

职责：

- 给开发者评测人格一致性。
- 给产品迭代提供证据。

模块：

- Golden cases。
- 禁用语命中。
- 回复长度分布。
- 低信号回复测试。
- 晚安收束测试。
- 关系阶段测试。
- 记忆引用测试。
- 安全边界测试。

验收标准：

- 每次改 prompt 或模型配置后能一键跑回归。
- 结果能说明失败原因。
- 能导出评测报告。

### 4.7 `/privacy` 隐私与安全说明

职责：

- 解释数据如何使用。
- 解释 LLM 上下文注入。
- 解释删除与导出。
- 明确危机场景处理。

验收标准：

- 用户能看懂，不是法律文书。
- 明确说明 API Key、记忆、对话内容的边界。

## 5. 核心用户路径

### 路径 A：第一次来

1. 打开首页。
2. 看到栖语一句开场。
3. 输入“今天好累”。
4. 栖语短问“咋了”。
5. 用户继续说。
6. 系统提示“要不要让我记住你的称呼？”
7. 进入 onboarding。
8. 完成后进入正式聊天。

关键点：

- 先体验，再注册。
- 先建立感觉，再解释功能。

### 路径 B：每天晚上回来

1. 打开 `/chat`。
2. 栖语基于时间和记忆自然开场。
3. 用户聊今天。
4. 栖语在合适时引用旧记忆。
5. 对话后段变慢、变短。
6. 用户说晚安。
7. 栖语收束，不开启新话题。

关键点：

- 回访体验要像“她还在”。
- 不要每日打卡感。

### 路径 C：用户想知道她记住了什么

1. 打开记忆中心。
2. 查看记忆列表。
3. 点开某条记忆。
4. 看到来源对话。
5. 编辑或删除。
6. 设置是否允许进入 LLM 上下文。

关键点：

- 记忆是信任资产，不是隐藏机制。

### 路径 D：高级用户配置模型

1. 打开设置。
2. 进入 AI 模型。
3. 填 API URL、API Key、Model。
4. 点击测试连接。
5. 查看测试结果。
6. 保存。
7. 回到聊天。

关键点：

- API Key 只走服务端。
- 错误提示要能指导修复。

## 6. 视觉与交互方向

### 6.1 视觉关键词

- 深夜。
- 安静。
- 温暖。
- 克制。
- 有呼吸感。
- 不赛博。
- 不花哨。

### 6.2 避免方向

- 大面积紫色渐变。
- 科技蓝。
- 卡片堆叠。
- 夸张玻璃拟态。
- 营销页式大标题。
- 过多插画。
- 情绪 App 常见的可爱化贴纸风。

### 6.3 建议设计语言

颜色：

- 深灰/近黑背景。
- 低饱和暖色点缀。
- 高可读文本。
- 避免纯白刺眼。

字体：

- 中文优先保证可读性。
- 正文不小于 15px。
- 聊天气泡行高充足。

动效：

- 慢。
- 少。
- 为节奏服务。
- 不为炫技服务。

聊天气泡：

- 圆角不超过 8px。
- 不做大面积浮层卡片。
- 栖语气泡更安静，用户气泡更明确。

移动端：

- 输入框必须稳定。
- 键盘弹起不遮挡最后一条消息。
- 可单手操作。

## 7. LLM 与人格系统

### 7.1 调用结构

每次调用 LLM 时构造三层上下文：

1. `栖语产品灵魂.md` 生成 system prompt。
2. 当前关系阶段、相关记忆、最近对话、情绪惯性。
3. 禁用语、风格约束、安全边界。

### 7.2 输出后处理

LLM 输出不能直接展示。

必须经过：

- 禁用语检查。
- 长度检查。
- 晚安收束检查。
- 安全边界检查。
- 人格一致性启发式检查。

失败策略：

- 轻微失败：重写一次。
- 严重失败：使用本地规则引擎兜底。
- 安全失败：强制安全回应。

### 7.3 Debug 能力

开发者模式要能看到：

- system prompt。
- 注入的记忆。
- 关系阶段。
- LLM 原始输出。
- 被拦截原因。
- 最终展示回复。

## 8. 记忆系统

### 8.1 记忆类型

- 用户称呼。
- 作息。
- 饮食偏好。
- 工作压力。
- 家庭关系。
- 睡眠问题。
- 反复出现的情绪。
- 用户明确要求记住的事。

### 8.2 记忆生命周期

1. 候选记忆：从对话中提取。
2. 确认记忆：高置信或用户确认。
3. 活跃记忆：可进入 prompt。
4. 冷却记忆：很久未使用。
5. 冻结记忆：用户不想被提起。
6. 删除记忆：彻底移除。

### 8.3 记忆使用原则

- 不要每次都提。
- 不要为了展示记忆而展示记忆。
- 沉重记忆要谨慎。
- 记忆引用要像朋友自然想起。

## 9. Onboarding 设计

### 9.1 目标

Onboarding 不是功能介绍，而是第一次认识。

### 9.2 推荐流程

第一屏：

```text
嗨。我是栖语。
你晚上一般会什么时候来？
```

第二屏：

```text
我该怎么叫你？
```

第三屏：

```text
有些事我可以记住。
比如你不爱喝酒，或者你最近总是加班。
你也可以随时删掉。
```

第四屏：

```text
今晚先不讲太多。
今天过得怎么样？
```

### 9.3 验收标准

- 不超过 4 个主要问题。
- 每一步能跳过。
- 不出现功能清单式介绍。

## 11. 安全与边界

### 11.1 必须处理的风险

- 自伤/轻生表达。
- 医疗建议。
- 法律建议。
- 金融建议。
- 色情角色扮演。
- 恋人化依赖。
- 情绪操控。
- API Key 泄露。
- Prompt 注入。

### 11.2 安全回应原则

- 不冷冰冰。
- 不系统警告。
- 不逃避。
- 不假装专业。
- 不把责任推给用户。

### 11.3 技术边界

- API Key 不进浏览器。
- Prompt 不让用户直接覆盖。
- 用户输入进入 prompt 前做分隔。
- 服务端限制请求大小。
- 错误日志不记录 API Key。

## 12. SOTA 质量标准

这里的 SOTA 不是论文意义上的最先进模型，而是 Web 产品体验标准：视觉、性能、可用性、可信度、AI 行为都达到高水准。

### 12.1 性能

目标：

- LCP 小于等于 2.5s。
- INP 小于等于 200ms。
- CLS 小于等于 0.1。
- 首屏 JS 尽量轻。
- 聊天输入永远不被长任务卡住。

参考：Google web.dev Core Web Vitals。

### 12.2 无障碍

目标：

- WCAG 2.2 AA 作为基础目标。
- 键盘可操作。
- 焦点顺序正确。
- 色彩对比达标。
- 动态消息对屏幕阅读器友好。
- 减少动画模式可用。

参考：W3C WCAG 2.2。

### 12.3 安全

目标：

- 按 OWASP Top 10 做基础审查。
- 防止 API Key 暴露。
- 防止 prompt 注入绕过安全规则。
- 防止本地配置被静态服务器暴露。
- 错误信息不泄露敏感数据。

参考：OWASP Top 10。

### 12.4 PWA

目标：

- 可安装。
- 有 manifest。
- 有 app icon。
- 有离线兜底页。
- 移动端体验接近 App。

参考：web.dev PWA installation。

### 12.5 AI 行为

目标：

- 禁用语 0 命中。
- 晚安后 0 次重新打开话题。
- 危机表达 100% 进入安全处理。
- 低信号消息不过度回应。
- 关系阶段行为可区分。
- 记忆引用自然，不炫耀。

## 13. 执行路线

### Phase 1：产品规格与视觉基线

产出：

- 页面地图。
- 核心用户路径。
- 视觉基线。
- 组件清单。
- 质量标准。

验收：

- 不写代码也能明确产品长什么样、怎么走。

### Phase 2：首页与试聊

产出：

- `/` 首页。
- 未登录试聊。
- 首屏对话体验。
- 轻量登录入口。

验收：

- 用户 30 秒内完成第一轮试聊。

### Phase 3：主聊天体验

产出：

- `/chat`。
- 多气泡回复。
- 输入中状态。
- 晚安收束。
- LLM 失败兜底。

验收：

- 核心夜聊可连续使用 10 分钟。

### Phase 4：LLM 产品化

产出：

- 服务端 `/api/chat`。
- system prompt。
- 上下文注入。
- 输出后处理。
- API 配置。

验收：

- API Key 不进浏览器。
- 无 key 时仍可使用。

### Phase 5：Onboarding

产出：

- 首次引导。
- 称呼、睡前时间、记忆授权。
- 引导后进入第一场对话。

验收：

- 90 秒内完成。

### Phase 6：设置中心

产出：

- 普通设置。
- AI 设置。
- 隐私设置。
- 开发者设置。

验收：

- 普通用户不被高级配置干扰。
- 高级用户能完整配置模型。

### Phase 7：记忆中心

产出：

- 记忆列表。
- 来源查看。
- 编辑、删除、冻结。
- 是否允许进入 prompt。
