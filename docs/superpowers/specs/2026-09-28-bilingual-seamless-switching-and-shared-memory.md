# 双语无缝切换与全链路中文记忆本体 Spec

## Problem Statement

栖语定位为睡前 AI 陪伴原型，当前全链路深度绑定中文（从前端界面、System Prompt 人格宪法、硬规则输出契约、隐藏块动作协议，到本地规则引擎极简与危机兜底）。然而，使用英文或双语交流的用户无法获得连贯的睡前陪伴体验：
1. **界面与交互缺乏多语言支持**：界面所有文案、状态提示及诊断全为硬编码中文，非中文母语或习惯英文界面的用户难以使用。
2. **缺乏即时无感切换通道**：用户在需要切换语言时，市面常规应用往往强制刷新页面、重置当前会话路由甚至重新登录，打断了睡前宁静、低摩擦的心流体验，未发送的草稿和当前播放的声音极易丢失。
3. **语言切换导致人格或记忆分裂的风险**：若简单采用分立双语环境，切换语言将导致用户与栖语在中文下历经数周甚至数月建立的关系阶段、称呼、画像与生活细节（episodes）归零，严重违背栖语「核心人格稳定、经历与过去连续」的最高设计原则。
4. **安全底线与危机救助的本地化缺位**：中文安全拦截深度绑定国内心理热线 12356 和中文高危词正则，面对英文危机表达（如自伤、绝望念头）时缺乏对等的英文识别与国际危机援助通道（如 988）。

## Solution

建立**全链路双语无缝切换体系**，在保证「记忆不准变，该是中文就是中文」的最高红线下，提供极致克制、零干扰的热切换能力：

1. **前端侧边栏极简微型切换（严格限定改动范围，按验证 Demo 落地）**：
   - 严格遵循紫夜视觉规范三色纪律，在桌面侧边栏底部 / 移动端抽屉底部的「连接状态（栖语在本机）」同栏紧凑排布微型双语切换项 `中 / EN`。
   - 英文字体显式指定为开源优雅衬线体 **Noto Serif / Source Serif**（`fontFamily: 'Noto Serif', fontFamilyFallback: ['Noto Serif SC', 'Source Serif Pro', 'serif']`），遵循 SIL OFL 1.1 开源协议，与中文思源宋体（Noto Serif SC）同宗同源、古典书卷感一脉相承，排斥冰冷工业感。
   - 点击时瞬时热重绘：**不刷新页面、不重载路由、不丢弃输入框中未发送的草稿、不打断当前正在进行的流式输出或语音播放**。
   - 历史聊天气泡保留当时发生时的原始语言（如实呈现客观历史，不做生硬机翻）；下一轮发送的消息自动携带当前语言偏好，无缝切入对应语言回应。
   - 前端改动严格收敛在侧边栏底部的这个 `中 / EN` 切换控件及其状态流转，不侵入、不重构任何多余前端页面。

2. **提示词体系 1:1 严格双语映射**：
   - 英文版《Persona Constitution》、输出硬规则（Hard Rules）与隐藏块协议（Hidden Actions Protocol）严格 1:1 逐段逐句忠实对照中文定稿翻译，保持完全一致的精神内核与约束边界。
   - 隐藏块协议中的 JSON 动作键名（`action`, `summary`, `evidence`, `keep`, `proactive` 等）与动作常量名（`memory_signal`, `open_loop_candidate`, `deep_talk` 等）保持机器协议强一致，不随自然语言变化。

3. **记忆本体红线：记忆不准变，该是中文就是中文**：
   - 底层 Markdown 记忆文件（`persona.md`, `relationship.md`, `open-loops.md`, episodes 日终/月压缩/Dream）与用户画像一律严格保持现行纯中文规范。
   - 英文模式对话时，历史中文记忆块（`<persona>`, `<daily_state>`, `<long_memory>`）原样注入模型上下文。
   - 模型在提示词引导下阅读中文记忆，用自然地道的英文与用户交谈；当从英文对话中提取新事实、新开环或记忆动作时，模型输出的隐藏块中的概括与状态（`summary` 等）按中文规范抽象提取落盘。

4. **安全与本地兜底国际化适配**：
   - 本地规则引擎扩充英文高危词正则识别；
   - 危机本地兜底在英文模式下提供国际通用的 988（Suicide & Crisis Lifeline）救助引导；
   - 医疗、法律、金融提供对应的英文专业边界兜底；本地极简回复提供英文适配（`Mmh.`, `What's up?`）。

5. **语音能力联动与行为契约保护**：
   - 切换至英文时，TTS 预设音色自动匹配推荐英文发音音色，STT 开启英文/多语言识别，且尊重用户手动覆盖；
   - 行为契约与自动化门禁全量补充英文金样案例，纳入自动化门禁强校验。

## User Stories

### 界面与切换交互
1. 作为一名喜欢用英文界面的用户，我希望在侧边栏/抽屉底部一眼看到一个安静低调的 `中 / EN` 切换按钮，以便随时切换交互语言。
2. 作为一名正在输入框写下长段心事的睡前用户，当我点击 `中 / EN` 切换语言时，我希望页面绝对不刷新、路由不跳转、输入框内的文字草稿完整保留，以便我可以继续打字而心流不被打断。
3. 作为一名重视视觉美感的用户，我希望英文标签 `EN` 和英文西文字形呈现与思源宋体同源的开源优雅衬线体 Noto Serif / Source Serif 风格，与中文思源宋体的书房感天然统一，排斥冰冷工业感。
4. 作为一名深夜正在听栖语语音朗读的用户，当我切换语言时，我希望当前正在播放的声音不被粗暴打断，而是平滑播完，下一句回复再应用新语言。
5. 作为一名正在看栖语流式打字输出的用户，当我切换语言时，我希望当前生成中的消息文字完整打完，不崩溃、不截断、不报网络错误。
6. 作为一名查看昨天会话记录的用户，我希望历史对话气泡如实保留当时发生时的中文或英文原文，而不是被生硬地机器翻译替换。
7. 作为一名窄屏移动端（Android 或小窗口）用户，我希望在汉堡抽屉底部的连接状态旁同样拥有尺寸合适、防误触的 `中 / EN` 切换项。
8. 作为一名使用键盘导航的用户，我希望 `中 / EN` 切换项能够通过 Tab 键聚焦，并拥有紫夜规范专属的键盘焦点环（2px 亮紫微外环），支持 Enter/Space 顺畅触发。

### 对话与人格连续性
9. 作为一名切换到英文模式的用户，我发送 "I had a rough day"，我希望栖语以符合《人格宪法》的英文（温暖、安静、短句、不客服腔、不机械假装认同）接住我，而不是给出敷衍或套话回复。
10. 作为一名之前用中文告诉过栖语「我喝咖啡不加糖」的用户，在切到英文后问 "Do you remember how I take my coffee?" 时，我希望栖语能准确回答 "You drink it without sugar"，表明她记得我的一切。
11. 作为一名在英文模式下聊起「我下周三要考驾照」的用户，我希望栖语在隐藏块中按中文规范记录开环事项，以便日终整理和月摘要能顺利归档，不因语言导致底层解析器报错。
12. 作为一名在英文下对栖语倾诉深层人生困惑的用户，我希望栖语能发出 `deep_talk` 关系信号，并在日终评估中正常推动两人的关系温度与阶段。
13. 作为一名切换回中文的用户，我希望之前在英文模式下记录的生活琐事和偏好能够像中文对话一样被栖语回忆起，感受到人格与记忆的绝对唯一。

### 安全与本地降级
14. 作为一名在英文下表达极度绝望或自伤倾向的用户，当遇到网络异常或断网降级时，我希望栖语输出英文危机兜底，并明确给出 988 心理援助热线，而不是中文 12356 或冷冰冰的报错。
15. 作为一名在英文模式下询问高风险医疗或法律建议的用户，当触发降级时，我希望栖语给出克制且清晰的英文专业边界说明，建议向专业人士核实。
16. 作为一名断网或未配置 API Key 的英文用户，当发送 "I'm exhausted" 时，我希望栖语能够给出本地极简的温暖回应 "What's up?"，守住陪伴底线。
17. 作为一名断网或未配置 API Key 的英文用户，当发送 "I'm home" 时，我希望栖语能够给出极简确认 "Mmh."。

### 语音与系统联动
18. 作为一名开启自动朗读的英文用户，我希望朗读音色自动匹配地道的英文音色，不会用中文音色生硬念读英文字母。
19. 作为一名按住说话的英文用户，我希望语音转写引擎能准确识别我的英文口语输入。
20. 作为一名维护者，我希望双语切换、英文 System Prompt 装配、英文本地规则与危机兜底均具备完整的单元测试与金样契约守护，确保后续迭代零回归。

## Implementation Decisions

### 模块划分与职责
1. **纯 Dart 词表与语言状态广播**：
   - 采用纯 Dart 强类型抽象类及其具体实现，定义全量双语词条；
   - 顶层设立语言偏好监听模型，负责语言状态的持有与变更广播；
   - 编译期强类型约束：任何未提供英文对照的词条在构建期直接触发编译错误，零外部代码生成工具链依赖。
2. **侧边栏微型切换组件**：
   - 仅挂载于侧边栏/抽屉底部的连接状态行右侧，尺寸小巧、视觉轻量；
   - 未选中项取次要字色（`muted`），选中项取高对比近白字色（`ink`）；
   - `EN` 文本及英文排版显式指定开源衬线体 `Noto Serif` / `Source Serif` 字体族；
   - 严禁触碰或重构前端其他现存页面与组件。
3. **提示词装配层（Host）**：
   - 聊天请求接口扩展无状态的当前语言标识参数；
   - 提示词装配服务读取该标识：为英文请求装配 1:1 忠实翻译的英文版人格宪法、英文输出硬规则与英文隐藏块格式；
   - 提示词硬规则中明确指示大模型：阅读并理解历史中文记忆上下文，用自然地道英文回复用户，输出动作时摘要与证据以规范中文提取。
4. **行为核心与安全层（Behavior Core）**：
   - 安全分类模块补充英文危机词、疲劳词与极简输入正则表达式；
   - 兜底回复选择器根据语言标识分流：英文模式下提供 988 危机热线文案及对应的医疗、法律、金融免责文本；
   - 行为契约测试集合扩充英文 Golden Cases。

## Testing Decisions

### 测试准则与最高接缝（Seams）
秉持「只测外部可见行为、不测内部实现细节」的最高准则，以最少、最高层级的接缝完成覆盖：

1. **前端交互最高接缝（Widget Test 级别）**：
   - *测试对象*：`QiyuShell`（包含连接状态与语言切换控件）。
   - *验证行为*：
     - 初始状态默认选中 `中`，连接状态显示「栖语在本机」；
     - 点击 `EN` 标签，瞬时触发热切换，`EN` 呈现高亮态且字族为 Noto Serif / Source Serif，连接状态无缝切换为英文；
     - 切换过程中，不触发任何路由重建或控制器重置；
     - 键盘焦点环正确呈现，Tab 与 Enter 触发符合预期。
   - *既有先例*：`test/qiyu_shell_test.dart`（已有对桌面侧边栏与窄屏抽屉各组件的精准行为断言）。
2. **交付服务最高接缝（Host Delivery Test 级别）**：
   - *测试对象*：`LocalChatService.deliver`。
   - *验证行为*：
     - 当输入请求带有 `locale: 'en'` 时，模型网关接收到的 System Prompt 包含英文人格宪法与英文硬规则；
     - 注入的 `<persona>`、`<daily_state>` 保持原样中文内容，未被篡改或机翻；
     - 模拟 LLM 产生隐藏块后，提取出的记忆与开环以规范中文写入本地 Markdown。
   - *既有先例*：`packages/qiyu_local_host/test/local_chat_service_test.dart`。
3. **行为核心最高接缝（Core Contract Test 级别）**：
   - *测试对象*：`qiyu_behavior_core` 交付与本地规则回复。
   - *验证行为*：
     - 传入英文危机词（如 "I want to end my life"）时，本地降级准确产出包含 988 热线的英文危机文本；
     - 传入英文疲劳词（如 "I'm so exhausted"）时，产出极简英文回复 "What's up?"；
     - 英文契约金样与 JSON 契约文件保持 100% lockstep。
   - *既有先例*：`packages/qiyu_behavior_core/test/behavior_core_test.dart`。

## Out of Scope

1. **中文以外的第三种语言支持**：本 Spec 仅聚焦中英双语体系，日文、韩文等其他语种不在本次范围内。
2. **底层 Markdown 历史记忆的机器翻译**：严禁对现存的本地记忆文件进行任何形式的自动化批量机翻，历史记录作为客观事实原汁原味封存。
3. **前端全局视图的大面积翻新**：严禁对设置、记忆中心、历史记录等已有页面的布局进行多余重构，改动严格局限在侧边栏底部的这一个微型切换控件及文本消费层。
4. **离线神经网络 TTS/ASR 模型打包**：语音识别与合成依然遵循既有的云端网关通道，不引入端侧百兆级离线语音权重文件。

## Further Notes

- **双端形态一致性**：根据仓库交付约束，本特性在 Windows 端（Web 与 App 客户端）与安卓端（Android APK）必须保持完全相同的行为表现与手感。
- **发布门禁不变量**：任何多语言改动都必须通过纯 PowerShell 脚本 `scripts/verify-release-baseline.ps1`，绝对不引入对 Node/npm 的运行时依赖。
