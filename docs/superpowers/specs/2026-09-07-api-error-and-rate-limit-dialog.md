# 接口限流与 40x 异常提示弹窗 Spec

## Problem Statement

栖语当前在云端大模型调用失败（如 429 限流、401/403 鉴权失败、404 模型未找到等）时，Windows Host 会依照安全降级原则自动回退为本地规则引擎回复。由于本地规则引擎是设计基准且能生成自然委婉的短句，用户在主聊天界面看到的是正常生成的文字气泡，界面没有给出任何显式的异常说明或配置排查引导。

这导致两个严重的用户痛点：
1. **静默降级造成误解**：当用户的云端 API Key 过期、欠费或被限流（429）时，用户误以为栖语发生了人格故障、遗忘了记忆，或者回答变得极其简单，无法感知真实原因是外部接口异常。
2. **缺乏即时修复通路**：在主界面打字聊天或使用语音时，一旦 401（Key 填错）或 404（模型名拼错），用户得不到任何明确指引，不知道应当去「设置」页面检查并修正 API Key 与模型。

## Solution

在主聊天会话以及主界面的语音输入（STT 转写）与语音朗读（TTS 合成）链路中，引入**服务异常提示弹窗**与**状态行联动机制**（设计方案与手感经高保真暗夜风原型验证锁定）：

1. **聊天链路保留本地兜底回复，流式落定后弹出**：
   - 发生 429 限流或 40x 异常时，栖语依然生成本地规则回复，守住睡前陪伴「不断流、不瘫痪」的基调。
   - 文字正常流式逐字输出；在整句生成完毕并完整落盘（`done` 事件）后约 300ms，向用户弹出居中暗夜风模态对话框（`AlertDialog`），绝不在打字中间生硬截断打扰。
2. **精准语义分流与极简双按钮引导**：
   - **429 限流**：
     - *标题*：服务请求受限
     - *正文*：模型服务返回请求过于频繁（429）。本次已为您切换为本地基础模式回复，建议稍后再试或检查服务商用量额度。
   - **401 / 403 鉴权失败**：
     - *标题*：API Key 鉴权失败
     - *正文*：服务商未通过验证（401/403），通常是 API Key 填写错误、已失效或未开通权限。本次已为您切换为本地基础模式回复。
   - **404 模型未找到**：
     - *标题*：模型名称不存在
     - *正文*：服务商未找到当前配置的模型（404）。请检查模型名称拼写，或前往设置确认服务商是否支持该模型。
   - **语音链路（STT / TTS）**：分别精准标明「语音服务受限」或「语音朗读受限」。
   - **弹窗操作按钮（右下角）**：
     - 【知道了】：次要文字按钮，点击立即关闭弹窗，焦点返还输入框。
     - 【前往设置】：深鸢尾紫强调色按钮，点击立即关闭弹窗、执行无条件语音停播并平滑导航至 `/settings`，**严禁展示任何额外的模拟提示字、浮层或中间确认框**。
3. **会话级去重频控（Frequency Capping）与状态行联动**：
   - 同类错误在当前会话（同一 `sessionId`）内**仅弹窗打扰一次**。
   - 第二次及后续再次触发同类错误时，**不再弹出全屏模态遮罩**，避免“弹窗轰炸”；转而在 composer 输入框上方状态行展开暗红底轻量提示条：`⚠️ 接口频繁受限 (429)，当前保持本地基础回复`，并附带可直接点击的内联链接 `去设置检查`。
4. **严格遵守三色纪律与设计内降级边界**：
   - `safety`（危机/敏感拦截）和 `no_llm_config`（未配置模型）属于设计内降级，绝不弹出异常窗口。
   - 偶发网络超时（`model_timeout`）和断网属于网络瞬态，不弹大窗，仅在状态条呈现。

## User Stories

1. 作为在深夜与栖语聊天的用户，当云端模型因用量耗尽或突发高频返回 429 限流时，我希望先看到栖语平缓打出本地温柔回复，并在打字结束后看到明确的限流提示弹窗，从而不会误以为系统崩溃。
2. 作为刚填入 API Key 的用户，如果 Key 权限不足或失效（401/403），我希望栖语在回复后弹窗提醒我鉴权失败，并提供直达设置页的按钮，以便我当场修正密钥。
3. 作为在设置中自定义了模型名称的用户，如果手抖拼错了模型名称（404），我希望在对话后收到提示窗口告知模型不存在，从而快速发现拼写错误。
4. 作为点击了【前往设置】的用户，我希望弹窗立即关闭并直接平滑打开设置页，不出现任何额外的中间提示文字或悬浮条，同时自动停止后台正在朗读的语音。
5. 作为遭遇模型错误但今晚不想调配置的用户，我希望点击【知道了】后弹窗直接关闭并回到输入框，继续以本地模式与栖语轻度交流。
6. 作为连续多次遭遇 429 限流的用户，在第一次点击弹窗中的「知道了」后，我希望后续再次发消息时**不再被全屏遮罩弹窗打断**，而是在输入框上方看到带有「去设置检查」链接的轻量提示，避免遭遇恼人的弹窗轰炸。
7. 作为使用语音输入（STT 转写）的用户，当转写服务遭遇 429 限流或 40x 鉴权错误时，我希望立即收到语音服务异常弹窗，从而清楚知道为什么刚才说的话没有转写出来。
8. 作为开启了自动语音朗读（TTS）的用户，当文本已生成但朗读合成遇到 429 或 40x 错误时，我希望收到语音朗读受限弹窗，明白为何没有声音播报。
9. 作为输入了涉及危机安全或敏感内容的用户，我希望栖语触发既有的本地安全规则回复，且**绝对不弹出** API 异常弹窗，遵守安全边界设计。
10. 作为尚未配置任何云端模型的全新用户，我希望栖语以纯本地规则模式正常对话，且**绝对不弹出** 40x 错误弹窗，尊重「无配置即是本地形态」的产品契约。
11. 作为遭遇暂时网络波动超时（Timeout）的用户，我希望仅在输入框上方看到轻量网络提示，而不被弹出全屏配置修复窗口，避免误导我改动正确的 Key。
12. 作为使用屏幕阅读器的视障用户，我希望错误弹窗获得焦点并正确播报标题与操作按钮，符合无障碍可访问性规范。
13. 作为维护者，我希望弹窗逻辑、频控去重以及状态条联动拥有健全的自动化 Widget 测试覆盖，验证全链路行为与边界排除。

## Implementation Decisions

### 模块划分与职责
- **`apps/qiyu_flutter` 表现层**：
  - 弹窗视图组件（`QiyuApiErrorDialog`）：
    - 结构遵循 Material 3 `AlertDialog`，宽度上限适配 `QiyuLayout.dialogContentMaxWidth`（~380px）。
    - 视觉采用暗夜毛玻璃实底（`panel`）、发丝边框（`line`）、`ink` 标题文案与降饱和暗红 `danger` 图标。
    - 按钮布局：右下角水平排列，次要按钮【知道了】（文本按钮），主要按钮【前往设置】（深鸢尾紫渐变胶囊圆角，强调位）。
  - 聊天视图（`LocalChatView`）：
    - 维护当前会话已弹窗错误类别集合 `_alertedErrorCategories`（以 `sessionId` 为作用域）。
    - 流式时序挂钩：在 `_send` 与 `_sendTranscribed` 完成 `await sending`（即 `done` 交付落定）后，检查本轮交付的 `fallbackReason`：
      - 若属于 429 或 40x，且尚未在该会话弹窗：调用 `showDialog` 展示模态弹窗，并将其记入 `_alertedErrorCategories`。
      - 若已在该会话弹窗：**不调用 showDialog**，直接将轻量文案设置到输入框上方的 `noticeBars` 中，并附带 `去设置检查` 按钮。
  - 导航行为：
    - 点击【前往设置】执行：`Navigator.of(context).pop()` 关闭弹窗 → `_chatViewModel.voiceOutput.stopAll()` 无条件停播 → `context.push('/settings')` 平滑跳转，无任何中间浮层。
    - 点击【知道了】执行：`Navigator.of(context).pop()` 关闭弹窗，焦点重置到输入框。

### 语音链路集成
- **语音输入控制器（`VoiceInputController`）**：在 STT 转写抛出异常且识别为 429 或 40x 时，通知视图层触发语音转写异常弹窗。
- **语音输出控制器（`VoiceOutputController`）**：在 TTS 合成拉取遇到 429 (`tts_rate_limited`) 或 40x 时，通知视图层触发语音朗读异常弹窗。

### 错误归类与判定逻辑
- **触发弹窗的 FallbackReason 集合**：
  - `FallbackReason.modelRateLimited`（429 限流）
  - `FallbackReason.modelAuthentication`（401/403 鉴权失败）
  - `FallbackReason.modelNotFound`（404 模型未找到）
  - `FallbackReason.modelProvider`（当伴随 4xx 客户端错误特征时）
- **严格排除的集合（不弹窗）**：
  - `FallbackReason.safety`（设计内安全，绝不弹窗）
  - `FallbackReason.noLlmConfig`（设计内无模型，绝不弹窗）
  - `FallbackReason.modelTimeout`、`modelNetwork`、`modelDns`、`modelTls`（网络瞬态，维持就地轻提示）
  - `FallbackReason.forbiddenPhrases`、`personaBoundary`、`invalidModelResponse`、`emptyModelReply`（输出清洗机制，维持自动兜底）

## Testing Decisions

### 良好测试判准
- 仅断言外部可见的用户行为：弹窗是否出现、弹窗标题与正文语义、按钮点击后的直接跳转与关闭（断言无中间 toast/浮层）、多次触发时的频控去重（第二次仅状态条出现「去设置检查」）、以及输入框焦点的转移。

### 核心测试 Seams
1. **主聊天 Widget 测试（`apps/qiyu_flutter/test/local_chat_view_test.dart` / `app_test.dart`）**：
   - 注入模拟网关，模拟 Provider 返回 429 限流，验证流式输出完毕（`done`）后弹出「服务请求受限」对话框。
   - 验证弹窗内仅包含【前往设置】与【知道了】按钮；点击【前往设置】直接推入 `/settings` 且无多余提示。
   - 在同一次会话中再次触发 429，验证**不再弹出模态对话框**，输入框上方状态行展示 `⚠️ 接口频繁受限 (429)` 与 `去设置检查` 链接。
   - 点击状态行里的 `去设置检查`，验证同样能正常跳转 `/settings`。
   - 模拟 401 鉴权失败，验证弹出「API Key 鉴权失败」对话框。
   - 模拟 `safety` 与 `noLlmConfig`，验证**绝对不弹出**任何异常对话框。
   - 模拟 `modelTimeout`，验证仅有状态行提示，不弹出模态对话框。
2. **语音链路 Widget / 单元测试（`apps/qiyu_flutter/test/voice_chat_view_test.dart`）**：
   - 模拟 STT 转写返回 429/40x，验证触发对应语音异常弹窗。
   - 模拟 TTS 合成返回 429/40x，验证触发朗读异常弹窗。

### 门禁回归
- 运行 `apps/qiyu_flutter` 的 `flutter analyze` 与 `flutter test`。
- 运行 `packages/qiyu_behavior_core` 与 `apps/qiyu_windows_host` 测试，确认协议与契约未被破坏。
- 运行全量 Release 1 门禁 `verify-release-baseline.ps1`。

## Out of Scope

1. **设置页测试按钮重复弹窗**：设置页（Provider / STT / TTS）现有就地内联错误提示保持原样，不在此处重复叠加全局模态弹窗。
2. **自动切换 Provider / 自动重试策略**：本次不实现复杂的自动重试回退网络或多 Provider 故障转移机制，错误由用户知情后决定是否去设置修改。
3. **弹窗持久化跨进程记住**：频控去重仅作用于当前运行会话期，应用关闭重启或刷新后重新开始计数，避免用户永久漏看新的配置错误。
