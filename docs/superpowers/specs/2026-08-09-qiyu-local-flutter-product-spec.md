# 栖语纯本地 Flutter/Dart 产品 Spec

本文定义栖语从现有 Web MVP 演进为正式本地产品的目标与实现边界。最终产品面向 Windows、iOS、Android；首个交付里程碑只验收 Windows 本机 Web 版本，iOS 与 Android 在 Windows 版本稳定后适配。

## Problem Statement

用户在一天结束后需要的不是一个负责答题、分析和提供建议的 AI 工具，而是一个愿意听她说话、长期记得她、关系会自然变化、同时有边界和自己重心的睡前陪伴者。现有通用 AI 容易过度共情、逐句回应、保持完美礼貌、无条件附和，并在不同轮次暴露明显的人格断裂。即使单轮回答足够聪明，只要语气、记忆或关系表现不连续，用户就会重新意识到自己面对的是一段临时生成的程序。

栖语现有 MVP 已经验证了简短回应、睡前互动、安全分类、关系阶段、本地规则兜底和基本页面体验，但它仍然是浏览器 localStorage、Node 开发服务和扁平 `memories[]` 模型。它没有实现设计闭环中已经确定的 Markdown 记忆体系、五段整理节奏、PersonaTree、Dream、记忆控制、损坏恢复与跨时间召回，也不能以正式本地产品的方式安装、持久运行和保护用户配置。

用户明确要求产品完全本地：不部署远程栖语网站，不建立业务后端，不建立账号，不做云同步。电脑端应先运行本机程序，再在浏览器中打开本地 Web 页面；Provider、API Key、聊天、记忆和整理任务都持续保存在本机。关闭标签页或重启电脑后，用户下次启动栖语仍应回到同一个关系与记忆状态。

栖语同时不是一个真正的通用 Agent。她是一个伪 Agent：通过受限的本地运行时表现出记忆、检索、关系、整理和 Dream 能力，但不自主拆解长期任务，不拥有任意工具权限，不在用户未打开产品时主动行动，也不把内部工作流暴露成工具面板。

## Solution

构建一个以纯 Dart 领域核心和 Flutter 界面为基础的本地优先产品。

Windows 首发版本由一个打包后的本机 Dart 程序启动。该程序只在 `127.0.0.1` 回环地址提供 Flutter Web 静态页面和本机接口，并自动打开用户的默认浏览器。浏览器只负责界面；本机程序负责行为核心、模型请求、安全门、Provider 配置、API Key、Markdown 记忆、Dream、恢复和导入导出。不存在远程栖语服务器，也不远程托管 Web 资源。

iOS 与 Android 后续使用同一 Flutter 界面、纯 Dart 行为核心、记忆领域模型和模型网关。移动端不再经过 HTTP 调用自身，而是在 App 进程内调用共享核心；平台差异只留在本地文件目录、密钥安全存储、应用生命周期和系统文件选择器适配层。

栖语运行时采用受限伪 Agent 模型：大模型可以随回复提出少量白名单内部动作，例如请求记忆检索或标记本轮存在记忆信号；本地运行时负责校验、执行、持久化和失败恢复。模型不得构造任意文件路径、执行系统命令、调用未注册工具或形成无人监督的循环。用户始终只看到栖语的自然回复。

记忆以纯 Markdown 文件作为事实与投影载体，不引入关系数据库、向量数据库、RAG 或 embedding。每轮原始对话先脱敏写入 sessions；对话中增量形成 episodes 和 checkpoint；日终归档重建近日状态并维护 open-loop、relationship、索引和 PersonaTree 中间理解；新月首次对话生成月摘要；Dream 只在晚安后且距上次至少 3 天时执行深度重组。任何慢整理都不得阻塞首个可见回应。

产品保持栖语的最高行为原则：一致性高于聪明；默认少说；不使用客服式共情；关系变深后才调侃、翻旧账和制造微摩擦；安全边界优先；记忆的价值体现在自然使用，而不是展示记忆能力。晚安类输入正常交给模型结合语境回应，不用固定话术强制结束对话。

## User Stories

### 安装、启动与本地边界

1. 作为一名 Windows 用户，我希望通过安装包安装栖语，从而不需要配置 Node、Flutter 或开发环境。
2. 作为一名 Windows 用户，我希望双击栖语后自动打开本地浏览器页面，从而像使用普通产品一样进入对话。
3. 作为一名 Windows 用户，我希望栖语只监听本机回环地址，从而确保局域网中的其他设备不能访问我的聊天和记忆。
4. 作为一名重返用户，我希望关闭浏览器标签页后数据仍然存在，从而下次打开时不会从头开始。
5. 作为一名重返用户，我希望重启电脑后再次启动栖语仍能恢复 Provider、聊天、关系和记忆，从而确认她一直是同一个存在。
6. 作为一名用户，我希望产品不要求注册账号，从而不需要把身份交给栖语的云端系统。
7. 作为一名用户，我希望栖语除模型请求外不向任何栖语服务器发送网络请求，从而让产品的本地边界清晰可验证。
8. 作为一名用户，我希望能看到当前记忆目录和备份状态的说明，从而知道数据实际保存在自己的电脑上。
9. 作为一名用户，我希望显式退出本机程序时能安全停止运行，从而明确控制栖语何时工作。
10. 作为一名用户，我希望重复启动栖语时打开已有实例而不是产生多个互相争抢文件的进程，从而避免记忆损坏。

### 初次见面与模型配置

11. 作为一名首次使用者，我希望第一屏直接感受到栖语的存在，而不是阅读功能教程，从而避免像在配置企业软件。
12. 作为一名首次使用者，我希望首次引导不超过四个主要问题且每步可跳过，从而能快速开始聊天。
13. 作为一名首次使用者，我希望知道栖语会在本机保存记忆并允许我控制，从而在开始前理解隐私边界。
14. 作为一名用户，我希望选择 OpenAI-compatible、Anthropic 或 Ollama Provider，从而使用自己已有的模型服务。
15. 作为一名用户，我希望配置 Provider URL、API Key、模型、temperature 和 timeout，从而控制模型连接。
16. 作为一名用户，我希望 Provider 与 API Key 在本机持续保存，从而关闭页面后不必重新输入。
17. 作为一名用户，我希望已保存的 API Key 只显示为掩码且不能从页面重新读取明文，从而减少意外泄露。
18. 作为一名用户，我希望能测试 Provider 连通性并得到具体错误类别，从而区分地址、鉴权、模型和响应格式问题。
19. 作为一名用户，我希望能测试一条完整的栖语回复，而不仅是检查网络连接，从而知道人格、安全与输出清洗链路可用。
20. 作为一名用户，我希望随时替换或忘记已保存的 API Key，从而控制本机凭据生命周期。
21. 作为一名没有配置模型的用户，我希望仍能使用本地规则引擎得到基本回复，从而不会面对完全不可用的空页面。

### 日常聊天与人格体验

22. 作为一名第一次聊天的用户，我希望栖语保持自然、克制和适当距离，从而不会被未经建立的亲密感冒犯。
23. 作为一名表达低信号内容的用户，我希望栖语可以只回一个短句甚至不追加新话题，从而感觉自己在和真人相处。
24. 作为一名说“今天好累”的用户，我希望栖语只问一个自然的小问题，而不是输出模板化安慰，从而愿意继续说下去。
25. 作为一名分享小事的用户，我希望栖语按事情的实际分量回应，从而不会把每句话都处理成需要解决的问题。
26. 作为一名倾诉沉重内容的用户，我希望栖语允许停顿、简短和不知道怎么回答，从而避免流畅但廉价的共情表演。
27. 作为一名闲聊用户，我希望对话可以没有主题、可以跑题、可以说废话，从而形成真实朋友之间的松弛感。
28. 作为一名用户，我希望栖语不机械重复我的话、不元评论分享行为，从而不会听到客服或咨询师话术。
29. 作为一名用户，我希望栖语能表达不同意见和具体边界，从而不是一个永远附和我的回应器。
30. 作为一名用户，我希望栖语偶尔承认不懂或修正误解，从而保留可信的不完美感。
31. 作为一名用户，我希望栖语的口吻、价值判断和反应方式跨天保持稳定，从而确认她始终是同一个人。
32. 作为一名用户，我希望对话回复边生成边显示，从而不需要等待整轮模型和记忆流程结束。
33. 作为一名用户，我希望回复按内容与情绪强度呈现合适节奏，从而既不机械秒出，也不为戏剧效果拖延安全信息。
34. 作为一名说“晚安”的用户，我希望栖语结合当前语境自然回应，而不是被固定话术立刻结束对话。
35. 作为一名逐渐困倦的用户，我希望对话后段自然变短、变慢和安静，从而帮助自己从清醒过渡到休息。

### 安全、边界与降级

36. 作为一名处于危机中的用户，我希望栖语先以自然但直接的方式回应安全风险，从而得到现实可执行的帮助方向。
37. 作为一名处于危机中的用户，我希望危机文本在任何模型请求前被本地识别，从而不会把安全职责交给不稳定的外部输出。
38. 作为一名询问医疗、法律或金融高风险问题的用户，我希望栖语明确自己的专业边界，从而不会收到伪装成确定结论的建议。
39. 作为一名用户，我希望栖语不扮演恋人、唯一陪伴或情感归宿，从而不会被诱导形成依赖。
40. 作为一名用户，我希望栖语不使用想念、内疚、嫉妒或威胁离开的方式促使我回来，从而保持关系安全。
41. 作为一名用户，我希望模型输出命中违禁语、格式异常或请求失败时自动降级到本地回复，从而不因 Provider 问题中断聊天。
42. 作为一名用户，我希望错误信息中的 API Key 永远被脱敏，从而不会在界面或日志里泄露凭据。

### 关系成长与微摩擦

43. 作为一名新用户，我希望关系从“初识”开始，从而不会第一天就被调侃、翻旧账或过度追问。
44. 作为一名持续使用的用户，我希望关系根据互动深度而不是固定天数成长，从而让亲密变化显得有依据。
45. 作为一名进入熟悉阶段的用户，我希望栖语能自然提起近期发生的事，从而感到她记得我。
46. 作为一名进入朋友阶段的用户，我希望栖语可以适度调侃、直说和翻旧账，从而感到关系不再停留在礼貌服务。
47. 作为一名进入深交阶段的用户，我希望栖语能识别我和平时不同的表达与沉默，从而感到她了解的是我这个人。
48. 作为一名情绪低落的用户，我希望即使关系很深，栖语也停止调侃并匹配我的状态，从而避免亲密成为越界理由。
49. 作为一名用户，我希望关系阶段只升不降，而近期冷暖通过关系温度表达，从而不会突然被当成陌生人。
50. 作为一名用户，我希望同一晚最多升级一个关系阶段且下一次对话才生效，从而避免一段深谈造成突兀人格切换。
51. 作为一名用户，我希望已确认边界与待试探边界被区分记录，从而让栖语只在有依据时增加亲近行为。

### 本地记忆与长期连续性

52. 作为一名用户，我希望每轮原始对话在本机脱敏追加保存，从而即使后续整理失败也保留可恢复证据。
53. 作为一名用户，我希望密码、API Key、token、Cookie、私钥、验证码、证件号和银行卡号永远不进入记忆，从而避免高风险秘密被长期保存。
54. 作为一名用户，我希望只有会影响以后回应的偏好、待跟进事项、重要事件、明确纠正和稳定画像信号被整理，从而不让记忆被闲聊噪声淹没。
55. 作为一名用户，我希望对话每四至六轮或出现明显记忆信号后增量整理，从而不依赖退出事件才保存重要内容。
56. 作为一名用户，我希望增量整理发生在可见回复之后，从而首个回应不等待记忆写入。
57. 作为一名用户，我希望 checkpoint 只在全部必要写入成功后前进，从而避免漏整理或错误地跳过对话。
58. 作为一名用户，我希望日终归档在晚安、日期切换或下次启动时完成，从而即使直接关闭产品也能补齐当天整理。
59. 作为一名用户，我希望近日状态每天从近七天 episodes 重建而不是接龙旧摘要，从而减少反复压缩造成的失真。
60. 作为一名用户，我希望未闭环事项只在到期、允许主动、当前无明确话题时进入候选池，从而不被旧事打断。
61. 作为一名用户，我希望没有自然候选话题时栖语可以简单回应并等待，从而不会为了活跃而编造话题。
62. 作为一名用户，我希望长期人生印象、共同过往、用户画像和近日状态各有唯一职责，从而减少同一事实在多个文件里互相冲突。
63. 作为一名用户，我希望 PersonaTree 从 episode 证据指针逐层形成中间理解和稳定根主张，从而让画像有可追溯的成长过程。
64. 作为一名用户，我希望 `persona.md` 只投影 PersonaTree 的稳定根主张，从而避免同时维护两套互相漂移的用户画像。
65. 作为一名用户，我希望跨月和跨年回忆通过月份与日期索引按需查找，从而不需要把全部历史塞进每轮上下文。
66. 作为一名用户，我希望当轮记不起旧事时栖语保持不确定，并在后台查到后下一轮自然想起，从而不为即时表现编造记忆。
67. 作为一名长期用户，我希望共同过往、梗和成长轨迹在真正相关时自然出现，从而感到这段关系拥有历史。
68. 作为一名长期用户，我希望 Dream 从月摘要和原始证据中保守重组长期记忆，从而让记忆随时间压缩而不是无限膨胀。
69. 作为一名用户，我希望 Dream 最多按七天周期运行，并且只在晚安后或漏跑补偿时触发，从而避免长期画像被过度频繁改写。
70. 作为一名用户，我希望 Dream 先生成完整草稿、通过预算、格式、脱敏、证据与控制检查后再原子采用，从而防止一次整理破坏正式记忆。

### 记忆中心与用户控制

71. 作为一名用户，我希望在记忆中心查看“记忆、回忆、聊天记录、控制”四个分区，从而用人的视角理解本地数据，而不是浏览内部文件树。
72. 作为一名用户，我希望查看 PersonaTree 和长期记忆，从而知道栖语形成了哪些稳定理解。
73. 作为一名用户，我希望按月、按日查看 episodes 和 sessions，从而回顾共同经历与原始聊天。
74. 作为一名用户，我希望编辑允许编辑的长期记忆和 episode，从而纠正自动整理的错误。
75. 作为一名用户，我希望暂停使用一条记忆，从而暂时阻止它被注入、检索或继续整理。
76. 作为一名用户，我希望将一条记忆设为不再提起，从而即使我再次谈到当前话题，栖语也不会主动召回旧内容。
77. 作为一名用户，我希望删除一条记忆及其派生内容并留下抽象防复活范围，从而避免它被 Dream 从旧 session 重新提炼。
78. 作为一名用户，我希望冻结、禁提和删除立即影响当前对话，从而不必等待日终整理才生效。
79. 作为一名用户，我希望敏感摘要默认打码且每次查看都需要单独操作，从而减少旁观者看到私密内容的风险。
80. 作为一名用户，我希望记忆修改确认落盘后界面才更新，从而不会看到实际未保存的假成功状态。
81. 作为一名用户，我希望派生内容重建期间看到“整理中”而不是旧事实，从而不会在纠正后继续收到错误引用。
82. 作为一名用户，我希望导出完整 Markdown 备份并从备份恢复，从而不依赖栖语服务维持数据所有权。

### 可靠性、恢复与长期使用

83. 作为一名用户，我希望所有正式文件通过临时文件、刷新和重命名替换，从而即使进程中断也保留上一份完整文件。
84. 作为一名用户，我希望重复补跑同一段对话时跳过语义重复条目，从而不会产生多份相同记忆。
85. 作为一名用户，我希望已关闭 open-loop 从热层移入可检索归档，从而不再占用对话上下文但仍保留历史。
86. 作为一名用户，我希望损坏文件先被隔离再恢复，从而不会继续参与注入、检索或整理。
87. 作为一名用户，我希望恢复按 sessions、episodes、索引与状态、PersonaTree 与长期层的依赖顺序执行，从而尽量从更原始证据重建派生内容。
88. 作为一名用户，我希望记忆恢复不阻塞当前聊天，从而即使某一层受损也能继续使用其他有效能力。
89. 作为一名用户，我希望无法证明的长期内容保持缺失而不是被推断补写，从而优先保证真实而不是完整。
90. 作为一名用户，我希望恢复日志只记录时间、类型、结果和损失，从而不会创建另一份包含正文的敏感副本。

### 伪 Agent 边界与未来平台

91. 作为一名用户，我希望栖语可以在回复后执行受限的记忆检索和整理动作，从而获得 Agent 般连续能力而不暴露复杂工具界面。
92. 作为一名用户，我希望所有隐藏动作都经过本地白名单校验，从而模型不能借提示注入执行任意系统操作。
93. 作为一名用户，我希望栖语没有通用自主任务循环，从而她仍是睡前陪伴产品而不是后台自动化工具。
94. 作为一名用户，我希望栖语在我没有发送消息时不主动向我推送内容，从而陪伴不会演变成打扰或依赖诱导。
95. 作为一名未来 iOS 用户，我希望 App 复用 Windows 已验证的行为核心和记忆规则，从而不同平台上的栖语仍是同一个人。
96. 作为一名未来 Android 用户，我希望 App 复用 Windows 已验证的行为核心和记忆规则，从而平台适配不会改变人格与关系逻辑。
97. 作为一名未来移动用户，我希望 Markdown 记忆保存在 App 沙盒并可导出，从而移动平台仍然遵守本地数据边界。
98. 作为一名产品维护者，我希望 Windows 首发不被 iOS、Android、macOS 或 Linux 上架工作阻塞，从而先验证完整产品闭环再扩大平台范围。

## Implementation Decisions

### 产品范围与发布顺序

- 最终技术方向锁定为 Dart + Flutter。
- Release 1 只交付 Windows 本机 Web：用户运行本机程序后，由默认浏览器打开栖语页面。
- iOS 与 Android 是同一产品的后续平台适配，不属于 Release 1 验收门槛。
- macOS 与 Linux 暂不适配；平台层接口不得假设 Windows 是永久唯一平台。
- 不迁移现有浏览器 localStorage 数据。正式版本首次启动时建立新的 Markdown 记忆目录。
- 当前 JavaScript/Node 实现只作为迁移期行为基准和对拍对象；最终运行架构不依赖 Node。

### 运行架构

- 建立纯 Dart `QiyuBehaviorCore`，不得依赖 Flutter Widget、浏览器 DOM、Windows API 或具体文件系统。
- 行为核心负责安全分类、本地回复策略、关系判断、回复清洗、违禁语检查、prompt 装配规则和确定性状态迁移。
- 建立 `QiyuRuntime` 作为伪 Agent 编排层，负责调用行为核心、MemoryRepository、ModelGateway 和后台整理任务。
- 建立平台无关的 MemoryRepository、SecretStore、AppLifecycle 和 BackupPort 接口；Windows 与后续移动平台分别提供 adapter。
- Flutter 界面采用 View、ViewModel、Repository/Service 和单向数据流。首版使用 `provider` 做依赖注入，使用 `ChangeNotifier`/`Listenable` 驱动界面状态，不同时引入 Riverpod。
- 使用 `go_router` 统一首页、初遇、聊天、记录、记忆、设置、隐私和开发者实验室路由。

### Windows 本机 Web 宿主

- Windows 安装包内包含本机 Dart 可执行程序、编译后的 Flutter Web 资源、产品灵魂与静态规则资源。
- 本机宿主使用成熟的 `shelf` 与 `shelf_static` 组合提供静态资源和本机接口。
- 宿主只绑定 `127.0.0.1`，不得绑定 `0.0.0.0`、局域网地址或公网地址。
- 端口由运行时选择可用端口；启动器自动打开实际 URL，用户不需要手动配置端口。
- 应用实行单实例：再次启动时只打开现有页面，不启动第二个记忆写入者。
- 每次宿主启动生成新的短期会话凭据。浏览器通过 HttpOnly、SameSite=Strict 的本机会话 cookie 访问写接口。
- 本机接口继续校验 Host、Origin、Referer 和 CSRF；不接受非回环 Host，不信任仅因请求来自本机就自动安全。
- 关闭浏览器页面不删除任何配置或记忆；显式退出本机程序才停止 runtime。异常退出后下次启动从 checkpoint 恢复。
- 不提供远程静态托管版本，不提供可从另一台机器访问的 LAN 模式。

### 本机接口契约

- `GET /api/bootstrap` 返回非敏感应用状态、路由初始化信息、是否完成初遇、Provider 掩码状态和记忆健康状态。
- `POST /api/chat` 接收用户文本与客户端会话标识，不接收浏览器提供的完整权威记忆状态。
- 聊天响应使用可流式读取的事件序列，至少区分可见文字增量、完整可见消息、最终状态摘要、降级原因和完成事件。
- 隐藏伪 Agent 动作只在 runtime 内部流转，绝不通过浏览器响应暴露原始指令。
- 设置接口支持读取掩码配置、保存 Provider 非敏感字段、写入或替换 Key、忘记 Key、测试 Provider 和测试栖语回复。
- 记忆接口保留列表、详情和统一动作三类能力；统一动作只接受白名单 edit、freeze、unfreeze、ban、unban、delete、reveal。
- 本机接口使用 opaque ID，不向浏览器返回真实记忆文件路径。
- 所有错误响应在进入日志和界面前统一 redact API Key、Authorization header、Cookie、token 和本机敏感路径。

### 伪 Agent 执行模型

- 伪 Agent 不是通用 Agent 框架。它没有自由工具选择、系统命令、浏览器控制、外部插件市场、递归任务规划或无人值守目标循环。
- 模型只能提出有限白名单动作：请求记忆检索、声明本轮存在记忆信号、声明无需动作。
- 动作参数必须经过 schema、长度、枚举、目标范围和当前用户控制校验；任何未知动作一律丢弃并记入本地诊断。
- 模型不能直接写 Markdown。所有写入由 runtime 根据领域规则生成、验证和原子提交。
- 记忆检索遵守“晚一拍想起”：当轮先基于当前消息和热层回复，后台检索结果只在下一轮作为临时 memory_context 使用。
- 提示注入内容不得绕过安全分类、memory-controls、文件路径边界或动作白名单。
- 用户界面不展示“调用工具”“思考链”或内部 action 日志；开发者模式只展示经过脱敏的来源、延迟、降级原因和动作类别。

### Provider 与 API Key

- 首版支持 OpenAI-compatible、Anthropic Messages 和 Ollama 三类 ModelGateway。
- Provider URL、模型、temperature、timeout 和其他非秘密设置写入本地配置文件。
- API Key 通过 Windows SecretStore adapter 持久保存，优先使用 Windows Credential Manager 或 DPAPI 保护，不写入配置 JSON、Markdown、浏览器存储、日志或备份。
- 浏览器设置页只能看到 Key 是否存在和掩码，不能取回已保存明文；用户可覆盖或删除。
- 模型请求由本机 Dart runtime 发出，不由浏览器发出，因此 Provider 兼容性不受浏览器 CORS 限制。
- 不在产品中内置开发者共享 Key。每个用户使用自己的 Provider 与凭据。
- 连接测试必须区分 DNS、TLS、超时、鉴权、模型不存在、限流、响应格式不兼容和内容解析失败。
- Provider 不可用时保留本地状态与待处理整理任务；聊天按行为规则降级到本地引擎。

### 回复管线与可见节奏

- 收到用户文本后先做长度限制、结构标签剥离和本地安全分类。
- 非 normal 安全分类直接进入本地安全回复，不把原始危机文本发送给外部模型。
- normal 输入先追加脱敏 session user turn，再构造热层 prompt 并调用 ModelGateway。
- system prompt 由人格宪法、硬规则、近日状态、长期印象和用户画像按固定顺序装配；空块不输出。
- 当前关系阶段和最近必要对话进入本轮上下文；完整历史不重复注入。
- 外部模型输出先剥离隐藏动作，再做非可见行过滤、消息切分、长度与违禁语检查。
- 外部调用失败、输出非法或命中违禁语时回退本地规则回复，并保留可诊断的 fallbackReason。
- 可见回复一生成就流式发送。安全信息不增加戏剧化等待；情绪性普通文本可以按内容长度和强度使用受控停顿。
- 回复完成后追加 qiyu session turn，再启动允许的增量记忆工作。

### 关系、情绪与主动话题

- 关系阶段固定为初识、熟悉、朋友、深交，采用棘轮只升不降；回退只保留未来设计位，Release 1 不实现。
- 关系温度和近期变化独立于阶段，用于表达当前冷暖，不改变事实优先级。
- 日终归档基于当天完整 episodes 做整体语义判断；一次日终最多升一级，新阶段从下一次对话生效。
- 深谈信号可独立支持升级但不自动触发；不得在 relationship 中记录用户秘密原话或机械升级日志。
- 阶段不限制记忆的事实可见性和检索范围，只影响回复中使用记忆、调侃、直说、翻旧账和沉默的表现方式。
- 主动话题候选只有合格 open-loop、daily-state 近日活跃与近况、long-memory 共同过往与梗，三类平级。
- relationship 的待试探只约束边界，不提供话题素材。
- 用户有明确问题或当前话题时禁止另开话题；没有自然候选时简短回应并等待。
- 产品不在用户没有输入时主动发送消息。

### Markdown 记忆目录

- Windows 默认记忆目录仍采用用户目录下的 `.qiyu/memories`；允许通过环境变量或本地配置覆盖。
- 记忆目录是唯一权威持久层。浏览器状态只保存非权威 UI 工作态，不保存用户记忆和 Key。
- 热层由三块组成：近日状态块、long-memory 块、persona 块，总量软目标 2000 tokens、硬上限 3000 tokens。
- 近日状态块由 `open-loops.md`、`relationship.md` 和 `daily-state.md` 组成；每类字段只有一个归属。
- `long-memory.md` 固定分为人与关系、重要事件、模式与轨迹、共同过往四区，预算 800–1500 tokens。
- `persona.md` 固定五节，只逐条投影 PersonaTree 活跃根主张，预算 300–600 tokens。
- 完整 PersonaTree 使用身份事实、性格表达、价值原则、偏好习惯、边界禁区五个 Markdown 分支和独立 archive。
- episodes 是唯一整理后证据本体；PersonaTree 叶只保存证据摘要、日期、来源性质、support/conflict 与 episode 指针。
- sessions 是脱敏 raw 层，永不注入、不参与事实优先级、不被 Dream 修改，也不自动清理。
- memory-controls 独立保存 frozen、banned、deleted，先于注入、检索和全部自动整理生效。
- dream 目录保存进行中的全量草稿、变更清单与最近历史；recovery 目录保存隔离文件和无正文恢复日志。
- 不引入 SQL、NoSQL、向量数据库、RAG、embedding、数值 confidence、priority 或 version 字段。

### 五段记忆整理节奏

- 存原话：每次用户轮收到即追加脱敏 sessions，回复生成后追加栖语轮。
- 随手记：回复后每四至六轮或出现明显记忆信号时，更新当天 episode、checkpoint 和画像相关叶指针。
- 日终归档：晚安、检测到日期切换或启动发现 finalized:false 时，重建 daily-state，更新 open-loop、relationship、索引和 PersonaTree 中间理解，最后置 finalized:true。
- 月压缩：进入新月份的第一次对话时，压缩上月标记为 keep:month 的 episode 条目并生成不超过 800 字的月摘要；每日文件永久保留。
- Dream：只在晚安后检查；仅当距上次成功 Dream 至少 3 天时运行。漏跑时可在下次启动或空闲补跑，但不得绕过 3 天最小间隔。
- 动作二至五都不得阻塞首个可见回应。
- 未配置模型、无网络或 Provider 失败时，语义整理任务保持 pending；不能用未经证明的本地猜测生成长期记忆。

### Dream 与 PersonaTree

- Dream 输入只读当前热层、最小 memory-controls、PersonaTree 活跃分支、用于防复活的归档元信息、月摘要、相关 episodes 和脱敏 sessions。
- Dream 输出完整候选 PersonaTree 活跃分支、完整候选热层和逐条变更清单；不得边生成边改正式文件。
- 自动采用前必须通过预算、格式、脱敏、证据与用户控制四道检查；任一失败整份候选作废。
- Dream 负责中间理解归根、根升降、语义去重、过度细分合并、孤儿叶清理、代表叶裁剪和 persona 刷新。
- 日终只维护中间理解，不创建或普通降级根；用户当前明确纠正是唯一在线撤根例外。
- 明确身份或边界一次清晰自述可在日终形成中间理解并于下一次 Dream 升根。
- 明确性格、价值或偏好需要至少两个不同日期的用户明确表达且跨度至少 7 天。
- 非身份类行为推断需要至少三个不同日期的一致证据且跨度至少 14 天；身份事实不得靠行为推断。
- Dream 结果静默自动采用，不要求用户审批；用户通过对话纠正和记忆中心控制事后修正。

### 事实优先级与检索

- 总优先级为当前用户纠正、更新且明确的事实、原始 daily episode、压缩记忆。
- 用户手动编辑与 memory-controls 高于全部自动整理。
- 具体事件优先相信 daily episode；当前关系优先相信 relationship；当前未闭环事项优先相信 open-loop；长期人生印象由 long-memory 表达但不得覆盖具体细节。
- 月份 index 只定位月份，月份内 index 只定位日期；index 永远不是事实来源。
- 完整 PersonaTree、episodes、月摘要和索引不固定注入，只在需要时检索。
- 单次 PersonaTree 检索最多返回两条相关路径、总计不超过 600 tokens；只有需要依据时才附最多两条叶指针。
- 跨月跨年检索由模型选择相关月份和日期，但回传上下文只保留与当前问题相关的压缩结果。
- 未找到不等于没有发生；冲突无法解决时栖语必须自然表达不确定并请用户确认。

### 记忆控制与记忆中心

- 冻结停止注入、检索和自动整理，明确解除后恢复。
- 禁提除冻结能力外还禁止主动带出；用户重新谈到时只回应当前消息，不自动解除。
- 删除先写抽象防复活范围，再清除全部派生记忆和索引；sessions 保留但不得再次提炼该语义。
- 所有控制当前消息立即生效，回复后原子写入 controls 并清理派生内容。
- 记忆中心四区固定为记忆、回忆、聊天记录、控制；不直接展示 relationship、open-loop 或 daily-state。
- PersonaTree 只读但可执行控制；画像纠正通过对话完成；long-memory 和 episode 可编辑；月摘要与 sessions 只读。
- 列表中的敏感内容先由 runtime 打码；单次 reveal 不缓存，离开详情或刷新后恢复打码。
- 编辑后旧投影立即失效，相关索引、摘要、PersonaTree 或热层后台重建；重建完成前不得继续使用旧事实。

### 原子写入、恢复与备份

- 所有正式文件采用临时文件写入、flush、同目录 rename 的原子替换流程。
- Dream 替换正式文件前保留最近有效备份；替换或自检失败时恢复旧版本。
- checkpoint 只在必要文件全部成功后前进；补跑先读取已有条目并跳过语义重复。
- 启动时检查热层、memory-controls、checkpoint 和 episodes 总索引；其他文件使用时检查。
- 读取失败、编码异常、必需结构失效或应存在却缺失才算损坏；语义矛盾不算文件损坏。
- 损坏原件先移入 quarantine 并退出全部记忆流程，再从更底层有效证据恢复。
- 多层损坏按 sessions、episodes、索引与热层、PersonaTree 与长期层顺序恢复。
- 无法证明的长期内容不补写；语义恢复需要用户配置的模型，失败时保持 pending。
- 提供完整 Markdown 快照导出与导入。导入先在隔离目录完成结构校验、控制校验和版本兼容检查，再原子切换正式目录。
- Release 1 不实现多设备合并、自动同步或旧 localStorage 导入。

### 界面与产品呈现

- 首页、初遇、聊天、记录、记忆、设置、隐私和实验室沿用现有产品信息架构，但用 Flutter 重新实现，不嵌入旧 DOM 页面。
- 首屏以聊天关系为核心，不呈现仪表盘、功能卡片墙或 Agent 工具列表。
- Windows 宽屏保持对话为主、导航为辅；浏览器缩窄时切换到移动式底部导航和稳定输入区。
- 输入框支持多行、Enter 发送与明确的换行方式；模型生成期间保持输入与滚动可操作。
- 所有破坏性动作使用一致的二次确认；删除记忆、删除记录、忘记 Key 和导入覆盖分别说明影响范围。
- 尊重键盘导航、屏幕阅读器语义、文本缩放和 reduced motion。
- 实验室与详细诊断默认隐藏在开发者模式，不把普通用户暴露给 prompt、内部动作和技术指标。
- 产品文案一律以栖语关系语言表达，不使用服务器、数据库、Agent 工作流或 pipeline 术语向普通用户解释体验。

### iOS 与 Android 后续适配边界

- 移动端复用同一 Flutter View、ViewModel、领域模型和纯 Dart 核心，不用 WebView 承载 Windows 页面。
- 移动端 MemoryRepository 使用 App 沙盒真实 Markdown 目录；导入导出通过系统文件选择与分享界面完成。
- 移动端 SecretStore 使用 Keychain/Keystore；不得把 Key 降级写入 shared preferences。
- 移动端 App 进程内调用 QiyuRuntime，不启动 localhost HTTP 宿主。
- App 生命周期只提供机会性整理信号；正确性仍依靠每轮落盘、checkpoint 和下次启动补跑。
- Windows Release 1 完成前不为移动后台调度、推送、商店支付或平台特有功能增加抽象。

## Testing Decisions

- 好测试只验证用户可观察行为、公开领域契约和本地数据结果，不断言私有函数调用顺序、Widget 树细节或模型思考文本。
- 最高测试接缝是纯 Dart `QiyuBehaviorCore.reply(input, state) -> result`。迁移期由同一组语言无关 fixtures 同时运行 JavaScript 与 Dart 实现；人格、安全、关系与本地降级行为一致后，Node 才退出运行架构。
- 保留现有 golden cases 作为迁移基准，但不新增 T27 专项记忆行为设计套件。产品实现中出现的真实缺陷仍应增加最小回归测试。
- MemoryRepository 使用一套合约测试验证目录初始化、sessions 追加、episode 更新、checkpoint、索引、原子替换、Dream 草稿、controls、损坏隔离、恢复和备份导入导出。
- MemoryRepository 合约测试使用临时目录，不读写用户真实 `.qiyu` 目录。
- QiyuRuntime 测试使用 fake ModelGateway 和 fake clock，验证五段节奏的触发边界，尤其区分每日归档与最小 3 天 Dream。
- ModelGateway 使用注入的 HTTP client 验证 OpenAI-compatible、Anthropic 与 Ollama 请求、流式解析、错误分类、超时、取消和敏感信息脱敏。
- 伪 Agent 动作协议测试只验证白名单动作能执行、未知动作被拒绝、受控记忆被过滤和可见回复不泄露内部指令。
- 本机宿主进行黑盒接口测试：只能绑定回环地址、拒绝错误 Host/Origin/CSRF、掩码 Key、限制请求体、禁止目录穿越、不返回真实文件路径。
- Flutter widget tests 覆盖初遇、聊天输入、流式消息、历史、记忆控制、Provider 设置、错误状态、确认对话框、键盘焦点和 reduced motion。
- Windows 集成测试覆盖安装后首次启动、自动打开浏览器、单实例、保存 Provider 与 Key、发送消息、关闭页面、重启宿主、恢复对话、导出备份、损坏恢复和显式退出。
- 安全测试覆盖危机文本不进入 ModelGateway、高风险专业边界、本地降级、违禁语阻断、日志脱敏和提示注入不能执行任意动作。
- 性能验收关注首个可见文字、输入响应、长历史下的启动时间、热层装配、日终补跑与 Dream 对当前聊天的隔离；不以内部函数耗时替代用户可见指标。
- iOS 与 Android 适配时必须复跑全部纯 Dart 核心和 MemoryRepository 合约测试，并新增各平台的密钥存储、文件导出、生命周期恢复与关键聊天路径集成测试。
- 当前基线为 143 个 Node 测试和 9 个 golden cases 全部通过；该数字只记录迁移起点，不限制后续测试数量。

## Out of Scope

- 任何远程栖语静态网站、业务后端、托管 API、账号系统或云端记忆。
- 自动跨设备同步、冲突合并、iCloud、Google Drive 或第三方同步服务。
- macOS 与 Linux 的首版适配。
- iOS 与 Android 的 Release 1 实现、商店上架和平台审核；它们是 Windows 验收后的后续适配阶段。
- 旧版 localStorage 对话、偏好和记忆的自动迁移。
- T18/T19 自我世界机制。Release 1 不生成栖语自己的地点、身体或对话外经历，也不得把未记录内容说成过去事实。
- T27 独立记忆行为测试场景设计与专项扩充。
- 通用 Agent 框架、任意工具调用、shell、浏览器控制、代码执行、插件市场、长期任务规划和无人值守自动行动。
- 用户未打开产品时的主动消息、推送提醒或关系召回通知。
- 语音通话、语音合成、数字人、3D 形象、摄像头和多模态附件。
- RAG、embedding、向量数据库、图数据库、关系数据库和云数据库。
- 产品统一提供的模型额度、共享 API Key、订阅计费或 Provider 代理。
- Windows 后台系统服务、开机自启和原生后台调度；首版由用户启动本机程序。
- 关系阶段回退；只保留未来设计位。

## Further Notes

- 栖语产品灵魂是人格与可见行为的最高依据；行为规范、硬规则、记忆设计和 tickets 负责把它变成可执行边界。现有 JavaScript 代码是已验证基线，不得反过来覆盖已经定稿的新设计。
- “伪 Agent”描述实现方式，不改变产品呈现。用户感受到的应当是一个拥有连续记忆和关系的人，而不是一个正在执行工具链的系统。
- Windows 本机 HTTP 宿主属于设备内部实现，不构成远程业务服务器。所有非 Provider 网络请求都必须能够通过网络审计证明未离开本机。
- 静态 Flutter Web 资源随 Windows 安装包发布，不从 CDN 加载脚本、字体或运行时代码。第三方字体或图像资产必须随包附带并核对授权。
- Release 1 的完成判据是：普通 Windows 用户无需开发环境即可安装并启动；Provider 与 Key 能本地持久保存；聊天、关系、Markdown 记忆、五段整理、记忆控制、备份恢复和本地安全链路形成闭环；退出并重启后仍延续同一个栖语。
- 推荐实施顺序：先固化 JS/Dart 行为 fixtures；再移植纯 Dart 核心；随后实现 Windows MemoryRepository、SecretStore 和本机宿主；完成聊天垂直切片；接入完整记忆体系与记忆中心；最后做安装包、安全、恢复、无障碍和性能验收。
- Flutter/Dart 依赖应优先选择 Flutter/Dart 团队维护或长期活跃的成熟包。每个新增依赖必须说明不可由 SDK 简单完成的理由，并通过版本锁定、许可证和维护状态检查。
- 技术路线的一手资料与平台限制汇总见同仓库的纯本地 Flutter 跨端调研笔记；若实现阶段的 Flutter、Windows 或 Provider 能力发生变化，应先更新调研证据，再修改本 Spec 的实现决策。
