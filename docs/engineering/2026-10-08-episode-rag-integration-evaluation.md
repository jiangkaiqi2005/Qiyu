## 二、发现并修复的整合缺陷（归票 02 模块，票 08 集成检查发现）

**现象**：用真实配置的 embedding 服务（OpenAI-compatible `/embeddings`）执行首次完整构建，183 条条目 0 条完成，状态落「暂不可用」，诊断 `incompatibleResponse`：「记忆召回服务返回了重复的向量序号」。单条连接测试此前一直通过——缺陷只在批量请求暴露。

**根因**：`packages/qiyu_local_host/lib/src/embedding_gateway.dart` 的响应解析把「data[].index 全等」判为畸形。真实服务（百炼 compatible-mode，2026-10-04 实验实测、本次真服务复核确认）批量响应的 index **恒为 0**，属于「无有效编号、按返回顺序落位」的合法形态；产品网关只处理了 0..n-1 排列形态。票 02 的测试把全 0 序号锁成了拒绝行为，恰好与真实服务相反。

**修复**（`embedding_gateway.dart:_parseEmbeddingResponse`）：按实验实测的三种真实行为落位——排列按 index 重排、全等编号与缺 index 按返回顺序、其余重复/混排仍拒绝（空占位不得出仓）。回归测试更新于 `test/embedding_gateway_test.dart`：新增「完全一致的编号视为无有效编号」真服务形态用例，原「重复序号拒绝」用例改为非全等重复（0、1、1）。修复后真实服务完整构建成功（183 条就绪、0 待处理）。

## 三、同题对照评测方法

- **评测台**：本机 Dart 工具（`.scratch/episode-rag-recall/eval/harness/`，本地资产不入库），驱动产品公共入口 `RecallOrchestrator`（文字轮内召回与实时查找的共享编排），不复制实现、不打内部调用桩。
- **记忆快照**：`~/.qiyu/memories` 只读拷贝（99 个文件）；RAG 派生索引写入快照目录内，真实记忆目录零改动。两个条目数口径不同、均如实保留：**179** 是评测台出题枚举的口径（只取普通记忆信号 `kind=memory` 的非空摘要条目）；**183** 是产品 RAG 实际索引语料——按既有条目有效性规则（`episode_index.dart` 的 `validEpisodeEntries`：排除空摘要、`open_loop_event` 簿记与 `relationship_signal` 关系信号，`open_loop_candidate` 属有效 episodes 可入索引），差集即 4 条 open-loop 候选条目。
- **同口径**：同一快照、同一聊天模型（`qwen3.8-flash`，用户 DashScope 账号下与其配置的 realtime 模型同代）、同一 embedding 服务（`qwen3.7-text-embedding-flash`，1024 维）、同一评测时点连续完成（2026-10-08 单轮）。索引先完整构建（183 条就绪，口径见上）再开新臂查询。
- **样本**：39 条（票面「约 40」），全部按类别出题并标注金标条目引用：换说法 10、指代 8、模糊时间 6、摘要未保留细节 3、无答案 4、部分答案 4、新旧纠正 4。出题由模型在本地生成（原实验同方法），无答案题经「与真实摘要片段相撞」校验筛除。
- **协议**：每题两臂。旧臂=未启用 RAG 的目录召回（定位探针 `lookupForRealtime` + 组织运行 `runTurnRecall`）；新臂=启用 RAG（定位探针 `locate` + 组织运行 `runTurnRecall`）。逐题记录：定位命中、组织回执、三态结论（组织/拒绝/未判断/未命中/失败）、评审结论、耗时、调用次数。
- **判分**：定位金标命中（新臂按条目 ID 精确匹配；旧臂按金标日期出现在选中日期，标注为近似口径）；组织结果由同账号模型按统一评分细则评审，**全部「错误自信」判定经人工逐条对照真实条目复核修正**（9 处误判改判，含把真实原话引用判成编造、把正确日期判成错误等）。
- **费用**：无法取得该服务的计费口径，按票面要求报告请求次数与输入规模，不编造价格。

### 4. 明确展示的失败与边界（不新增 supersedes，按 Spec 如实披露）

- **纠正漏召回（新旧纠正，4 题）**：两臂定位金标均 2/4；评审+复核后旧臂 2 有据/2 部分有据，新臂 3 部分有据/1 错误自信。向量把「过时说法」与「更正」一并召回时，回答模型可能沿用旧事实（如附和被用户自己更正过的名字）。这是 Spec 决策 9 明确保留的边界：同 ID hash 之外的语义纠正不由本功能保证。
- **摘要未保留细节（3 题）**：新臂定位金标 0/3（向量只嵌日期+摘要，摘录细节不可定位）；旧臂 1/3（关键词碰中）。两臂回答质量都差（原话细节既答不出也不该编）——这是嵌入单元边界的直接观测，不是回归。
- **模型随机性**：每题两臂各跑一次，逐题波动真实存在（同一题在两臂的定位/组织结论不同）。39 条的小样本只支持方向性结论，不构成普遍保证。
- **旧臂口径近似**：旧臂定位命中按「金标日期被选中」计（其条目级回执只在组织未拒绝时可见）；旧目录与 episodes-only 的语料范围差异如实说明：旧路径另含画像树路径检索，新臂不含（Spec 决策：启用后语义定位整体替换目录选择）。
- **实时入口探针**（Omni 同源）：6 题两臂经 `lookupForRealtime` 验证三态不互相冒充——新臂 6/6 返回候选（4/6 金标片段命中），旧臂 5/6 命中/1 未命中（2/6 金标片段命中，近似口径）。

### 6. 合成示例（非真实语料，仅示意判分口径）

- 换说法命中：问「那家总排长队的面馆后来还开着吗？」，金标条目「用户常去巷口一家很火的牛肉面馆」；组织回答引用该条 → 记「有据」。
- 错误自信（真实发生过的型态）：问「现在几点了？」，模型以旧记忆里「下午四点」作答 → 记「错误自信」，两臂各一例。
- 拒绝（正确行为）：问一件从未发生过的事，模型对召回的相似候选明确回「不是这件事」，不补气泡 → 三态中的「明确拒绝」，不算失败。
