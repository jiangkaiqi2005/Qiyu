# 称呼住 persona.md 受保护设定行，而非独立文件或画像根

称呼功能需要给栖语一个用户自填的「怎么叫你」的名称（2026-09-03 定稿，见设计笔记 `栖语记忆/Memory.md` 的「称呼」一节）。决定：称呼存放在 persona.md 总览内的一行**受保护用户设定行**，不经 PersonaTree 证据链；Dream 刷新、日常维护与记忆损坏恢复必须原样保留该行，恢复时先从隔离原件抢救。理由：用户明确希望称呼与画像同住 persona.md、随总览每轮注入免费拿到，且不想为称呼给 PersonaTree 新增根来源类型；代价是 persona.md 首次包含非证据内容，所有写入路径都必须保护这一行。

## Considered Options

- 独立小文件（如 appellation.md）：恢复天然安全、各写入路径零感知，被否——称呼与画像分居两地，记忆中心要多一个管理位。
- PersonaTree 固定身份事实新增「用户自述」根来源：恢复链路自动成立，被否——用户不愿为称呼扩展树的生命周期。
- 仅在 prompt 注入层映射、记忆文件不写称呼：被否——记忆中心展示的就是文件本体，文件不写称呼就达不到目的。

## Consequences

- persona.md 从纯投影变成「投影＋一行用户设定」；凡写 persona.md 的代码路径（Dream 刷新、日终维护、记忆损坏恢复）都必须圆桩该行，遗漏即丢称呼。
- 称呼一旦进入记忆文件内容（episodes、总览等），回退此决策需要重写记忆内容，成本高——有意接受。
- 设计笔记「隐私优先」原则同步豁免称呼（主动提供、用途明示）；其余私密标识不存原值的规则不变。
