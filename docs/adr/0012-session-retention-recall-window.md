# 会话本地永久保留，180 天定义为召回候选窗口

2026-09-19 发布审计拷问裁定：`activeSessionHistoryWindow`（180 天）在仓库里只有常量定义与 UI 元数据上报，既无清理实现也无召回过滤——是死声明，且与 AGENTS.md「活动窗口 180 天」的记载矛盾。裁定其语义为：**会话存储永久保留**（唯一删除途径是用户手动删段或清除产品数据），**180 天重定义为召回候选窗口**——召回的日期目录候选与日终理解材料只取窗口内的会话；把窗口真正接进召回逻辑排发布后（接线会改变模型可召回范围，需要测试）。AGENTS.md 措辞同步修正，消除「180 天」被读成存储清理的空间。

## Considered Options

- **按 180 天物理清理/归档**：需要一整套删除安全设计（备份前置、防复活、用户告知），且自动删除用户对话与「数据只在我手机上」的陪伴预期相悖。被否决。
- **直接删除 180 天说法**：零成本、最诚实，但失去将来接线的锚点。被否决。

## Consequences

- 会话文件随使用年限无限增长（磁盘占用与列表长度），是授权取舍；性能债（每轮全量扫描 sessions 目录）已知，排发布后。
- 召回接线后，模型无法召回 180 天前的会话内容——届时旧对话仍在磁盘上，只是不进上下文。
