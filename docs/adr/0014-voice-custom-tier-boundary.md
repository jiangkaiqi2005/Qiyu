# 语音服务通用自定义档的边界与下载跳的内网校验延伸

语音输入与朗读各新增千问专用档与自定义通用档（Spec `voice-qwen-custom`）。本 ADR 记录两个新决定与一处 Spec 冲突裁决：自定义通用档只兜「朴素 HTTP POST + JSON 请求体 + Bearer 类鉴权」形状的服务，签名鉴权、WebSocket 实时协议、数组下标响应明确门外；合成服务只返回音频地址时的下载跳，与合成请求过同一套语音出网内网校验。两个决定与 ADR 0001（Host 中介：浏览器永不直连语音服务、Key 不出本机）、ADR 0002（整段合成、音频内存即焚）同族。

## Context & Decision

1. **自定义通用档的能力边界：朴素 HTTP JSON + Bearer 类鉴权。** 覆盖形状收敛为三件事：HTTP POST、JSON 请求体、可配的 Bearer 类鉴权头。用户填完整地址即可用（不拼后缀），这是通用档的全部价值——「填地址就能用」的低门槛。
   - 转写侧（`custom`）：multipart 表单上传，与 OpenAI 兼容档同一份构造（`file` 字段带文件名与 content-type、`model`、`language=zh`），webm/mp4 录音原样上送不转换；高级参数作额外表单字段。鉴权头可配：配置存整行头名（如 `Authorization: Bearer`、`X-Api-Key`），冒号前是头名、冒号后是 scheme 前缀，无冒号时整行作头名、Key 直送；留空（含纯空白）回落缺省 `Authorization: Bearer`——语音流量不允许无鉴权出网；`Content-Type`、`Content-Length`、`Host`、`Transfer-Encoding`、`Connection` 这类保留头名（网关自写或 dart:io 自管，撞名会静默掉鉴权头或写出畸形请求）与不可见脏字符在保存前人话驳回。响应两形态：`json_path` 点号路径取文本（缺省 `text`）与 `sse` 逐行 `data:` 事件拼 content delta。
   - 合成侧（`custom`）：请求体固定 `{model, input}`，高级参数深合并进 `input`。响应三形态：`raw_bytes`（响应体原样当音频）、`json_field`（字段缺省 `data`，取 base64；值以 `http://`/`https://` 开头则转下载跳）、`json_lines`（字段缺省 `data`，逐行 JSON 的 base64 按序拼接）。
   - 门外清单，由将来的专用网关覆盖，通用档不凑：签名鉴权类服务（讯飞、腾讯云那类）；WebSocket 实时协议；响应文本在数组下标的服务（点号路径覆盖不到）。
   - 理由：请求体模板化与签名适配一旦进通用档，适配成本转嫁给每个用户（每人一份厂商字段文档），且每接一个新服务就是一次特例，成本无法收敛；专用网关把成本收回仓库侧，是签名类厂商的正解。同期千问专用档即此策略的另一半：协议形状固定就写死，不给旋钮。

2. **下载跳的内网校验延伸。** 千问朗读（非流式）与自定义合成 URL 形态都是两个请求拿一个完整文件：合成响应只给公网音频地址（千问 24 小时有效 URL），Host 再发一次 GET。这一跳与合成请求同权：
   - 下载入口限定 http(s)（下载是 HTTP GET；`speechOutboundRefusalReason` 放行 ws/wss 是给豆包流式转写档的，下载不需要），内网判定与该函数同一套：拒绝本机与内网字面量——服务端返回的地址同样受约束，被返回恶意内网地址时不出网；
   - 不发鉴权头：服务端返回的是无需密钥的公网 OSS 类地址，且防止已保存 Key 随下载请求泄给第三方域名；
   - 不跟随重定向：跟跳会让重定向目标成为绕开下载前校验的第二个地址；
   - 超时预算与合成请求同级（60 秒）；
   - 音频只在内存、播完即焚，不落盘、不进 sessions/记忆——ADR 0002 的整段合成语义不变。
   - 整条链路仍是 ADR 0001 的 Host 中介：浏览器永不直连语音服务，下载由 Host 发起，Key 不出本机。

3. **Spec 冲突的裁决留痕。** Spec `voice-qwen-custom` 决策 6 字面称「`qwen_tts` 档不落盘 extraParams」，与同句括注「extraParams 仅合成侧对千问生效」及用户故事 18（千问档用高级参数传 `instructions`）自相矛盾；决策 8 字面称高级参数面板「选中自定义档才露出」，同样与故事 18 冲突。裁决取不破坏既有功能的一边：
   - 千问档 extraParams 照常透传保存、深合并进 `input`（千问的 instructions 类字段本就在 input 下，故事 18 成立）；
   - 高级参数面板对合成侧全档显示：合成侧 extraParams 是既有全档能力（豆包 `audio_params`、千问 `instructions`、OpenAI `response_format`，见 ADR 0003），为自定义档把它收成仅自定义可见是能力回退；
   - 转写侧的高级参数仅自定义档露出与保存：转写侧本是本专题新功能，无存量行为要保；
   - 通用档旋钮（`authHeader`/`responseShape`/`responseField`）仍只在 `custom` 档落盘与露出，千问档不落盘——这部分与决策 6/8 不冲突，维持原样。
   - 将来修订 Spec 时以本条为准。

## Consequences

- 通用档的能力面可预期：签名类、实时协议、数组下标响应明确不做，用户不会在通用档里反复撞适配墙；门外清单同时是维护者的路标——每接一个此类厂商，答案是一个专用网关实现加一处分派 case，服务层调用面零变化。
- 下载跳与合成请求同一套内网判定、同一超时预算、同样不夹带凭据，语音出网防护面不因「两个请求」出现缺口。
- 千问档 extraParams 与合成侧全档高级参数面板保持既有能力不破；转写侧高级参数收在自定义档，请求形状固定的档界面不出现调了不动的旋钮。
- 若千问音频 URL 形态变化（如需鉴权、走重定向），下载通道是集中修改点，不动上层。
