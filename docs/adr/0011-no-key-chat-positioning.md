# 无 Key 聊天定位：引导优先，试聊保留为次

2026-09-19 发布审计拷问裁定：`behavior-spec.md`「首次运行不试聊」「兜底而非首屏」与首见页实际行为（未配置时主按钮「先聊聊」直接进聊天，本地规则引擎对绝大多数输入只回「嗯？」）长期矛盾，裁定对调主次按钮收口——「先去连上模型」升为主按钮，「先聊聊」保留为次按钮并如实标注「不连模型也能聊，只是回复会简单一些」。规范同步微调：试聊入口允许存在，但始终不作为首屏推荐。本地规则引擎保持极简（golden 锁定的三分支），扩充规则库改善无 Key 体验排发布后——与「少回应」「一致性高于聪明」的人格基调相比，机械扩充规则库的风险大于收益。

## Considered Options

- **规范对齐现实（承认试聊为主）**：接受第一印象是「嗯？」循环的风险。被否决：睡前陪伴第一晚的印象决定去留。
- **强化规则库到可用水平**：工作量大且与少回应基调有张力。被否决，排发布后再议。

## Consequences

- 首见页两个按钮对调；`first_meeting_view` 与相关测试同步。
- `behavior-spec.md:103`「不提供试聊输入框」改为「试聊不作为首屏推荐」。
- 无 Key 用户聊天体验保持现状（「嗯？」循环），这是授权接受的取舍，不是缺陷。
