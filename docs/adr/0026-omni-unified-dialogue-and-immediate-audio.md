# Omni 接管文字与语音对话，音频生成后直接播放

2026-10-02 双工对话设计访谈 Q1–Q23 已定决策，待整体共同理解确认后实施。用户选择 Omni 作为对话模型后，文字与语音都由该模型直接理解和回答，共用栖语人格与本机记忆；不再由另一文字模型预先写稿后交给 Omni 朗读。未选择 Omni 的既有对话路径继续保留。

Omni 音频生成后直接播放，不等待本地输出审核。用户明确将实时交谈置于本地内容裁决之前；不为 Omni 恢复或新增内容裁决，也不新增异步内容裁决。现有处理代码保留，不借本次接入顺手清除。本决定针对模型回复内容的放行时机，不修改本机凭据、请求鉴权、记忆控制或脱敏约定；这些边界不等同于回复内容审核。

## 取舍与裁定范围

完整回复缓存后检查再播放会损害实时体验，本次不采用。直接播放意味着已经说出口的内容无法通过后续检查撤回，人格约束由完整提示词和模型自身执行。上述取舍替代 ADR 0024 第二阶段关于输出审核必须先行裁定的阻塞项；ADR 0025 放弃逐字朗读的结论继续有效，旧朗读接入票不复活。

核查时发现 ADR 0017 已取消人格及违禁话术裁决，ADR 0018 已采用增量文字与语音交付；旧设计笔记《栖语语音》仍有完整检查后朗读的描述，与代码及后续 ADR 存在差异。访谈上一轮使用了过时的整轮审核前提，现予以订正；本次不擅自改写旧笔记或删改既有处理实现。

## 实时目标与通话入口

访谈第二轮裁定：普通对话从用户说完最后一个字到实际听见栖语开始回应，通常不超过 1 秒、绝大多数不超过 2 秒；计时包含轮次结束判断、网络与模型等待。不得以固定播放占位语冒充模型已回应。记忆检索与联网工具等待单独观察；这些数字是原型验收目标，不是已经测得的能力承诺。实施 spec 将 P50 ≤1 秒、P95 ≤2 秒作为默认测量口径，同时报告样本量、首轮和异常，不借筛除慢轮掩盖等待。

通话入口分两次交付。第一次只实现用户主动开始通话：通话期间持续采集，结束即关闭麦克风；选中 Omni 或进入聊天页本身不自动开麦。第二次在设置提供「手动开始／进入聊天页自动开始」两个选项，默认手动，一期不出现未接通的二期控件。主动挂断后本次使用不自动重开，去设置再回聊天页、切后台回前台或刷新网页均保持结束，用户仍可手动开始；关闭页面重新打开或真正重启 App 才恢复所选自动方式。首次选择自动时申请麦克风权限，此时不开始通话，授权后下次进入聊天页生效。Q15、Q19–Q23 分别确认阶段、入口、挂断边界与首次权限；此前将未讨论的推荐细节直接记为已确认的写法已纠正。

## 回忆保留晚一拍

旧事召回不阻塞首个自然回应，不假装已经找到证据；检索在后台进行，找到后再补充。用户在此期间可以继续说话，新一轮不因旧召回而被锁住。不能将原有召回等待窗口照搬成双工对话的串行阻塞。晚到结果不抢话：等待用户说完、当前回应结束，再结合当前话题判断是否仍相关；相关才自然补充，无关暂留，不把检索完成当成必须播出的通知。官方工具调用能否直接实现此顺序尚待原型核验，不能将协议具备工具能力等同于交谈时序已经成立。

## 文字记录与后台通话

通话以转录文字进入现有聊天记录与 Markdown 记忆流程，用户输入及栖语输出音频均只在内存流转，用完丢弃，不新增音频持久化、导出或备份。历史重听沿用 TTS 读记录文字，不承诺还原当时音色与语气，也不再让 Omni 自由改写历史原话。

用户主动开始的通话在锁屏、切到其他 App 时继续听和说，直到明确结束；切后台本身不结束通话。Android 使用官方允许的前台服务保持正在进行的通话，提供系统要求的服务提示；这不授权从后台静默启动新通话。Windows 网页与当前浏览器壳的后台及锁屏须分别真机验证，不承诺电脑休眠期间持续通话。系统中断与设备失效的具体接线在实施时沿用平台要求。

## 打断采用模型原生能力

附和与插话尽量区分：附和语允许栖语继续，新的表达或明确要求停下则打断。以 Omni 原生 `semantic_vad` 为第一选择，由本机停止播放器、清空未播放块并处理服务端响应终止；不额外维护附和词表，不新增本地语音意图分类器或另一模型判断器。具体参数用原型和真机确定，不增加用户配置面。原生能力能否达到预期要实测，不把误判问题默认为新增判断系统的理由。依据：[官方 VAD 配置](https://help.aliyun.com/zh/model-studio/client-events)。

被打断时保留截至打断已显示的文字，标记「被打断」，丢弃后续未交付部分；不撤销整条已交谈的回复。文字可能略早于声音，接受这一差异，不构建逐字音频对齐，不宣称记录恰好等于用户实际听到的每一个字。当前官方资料未确认支持音频时间裁剪会话项，不能保证服务端上下文同步截断到实际听到的位置。

## 沉默与连接恢复

用户沉默时栖语安静陪伴，不增加定时催促或主动找话机制；通话继续保持，直到用户明确结束或无法恢复的系统/服务异常。

短暂断线自动做有界的重连尝试，使用当前人格与本机文字上下文恢复，成功后继续交谈；恢复失败才提示通话结束。不重播旧回复，不在用户已结束后自行重开。重试次数、间隔和服务时限属于工程默认值，不增加配置项。

## 界面与文字发声

通话沿用现有聊天页，转录继续显示在普通聊天记录中，允许通话期间打字；不单独建设通话页。Q17／Q18 明确：Omni 输入区的录音入口改为电话图标，通话期间输入框上方显示简短状态栏，文字输入保持可用；结束用挂断电话图标，闭麦用带斜杠的麦克风，闭麦仍可听回答。非 Omni 保持原录音入口。Q21 明确：通话中进入记忆、历史、设置等其他页面时，底部保留同语义简短通话条，点击状态返回聊天页，不增加悬浮球。

通话外打字沿用现有朗读开关：开启时由 Omni 同时生成声音及对应文字，关闭时只回复文字，麦克风保持关闭。新回复不由文字模型预写再交给 Omni 朗读。用户进一步要求核实声音与文字能否逐字一致，已完成官方资料调研，未做推理实测。

有音频时使用同一回复中 `response.audio_transcript.delta/done` 作为显示与记录来源，不并行生成另一份文字稿；纯文字时使用 `response.text.delta/done`。官方调用指南明确两种输出形态，服务端事件把前者定义为音频对应文本。[调用指南](https://help.aliyun.com/zh/model-studio/realtime)、[服务端事件](https://help.aliyun.com/zh/model-studio/server-events)。

Qwen3.8 自身技术报告说明 Thinker 生成文字、Talker 接收流式表示生成声音，具有文字与语音对齐设计；但官方语音评测的内容错误率并非零，也未找到 API 对每次声音与伴随文字逐字零差异的保证。评测错误率不能直接套作栖语实时对话错误率，也未公开证明 `audio_transcript` 字段的内部生成方式。原型需核验正常回复的漏词、加词、改词与读音；本期不增加实时 ASR 回读、强制对齐或另一审查链路。[Qwen3.8 官方技术报告第 7 节](https://arxiv.org/html/2609.25611v1#S7)。

同步输出指同一回复的两种输出，不承诺字幕逐字随发音显示。用户已接受打断时保留屏幕文字及标记，不能把服务端完整 transcript 当成客户端已经全部播完的证据。Q16 已接受原生配对输出的能力边界，按推荐方案实施原型，以实际听感和内容核对判断是否合用；这不等同于接受未经实测就宣布效果达标。
