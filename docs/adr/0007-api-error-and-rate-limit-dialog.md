# 接口限流与 40x 异常弹窗：与本地规则兜底共存、流式落定后弹出且会话内同类错误单次频控

线上模型与语音调用遇到 429 限流或 40x 鉴权/配置故障时用户缺乏感知（2026-09-07 定稿，grill-with-docs 拷问六题）。决定：
1. **与本地规则兜底共存**：主聊天发生 429 或 40x 时，依然完整交付本地规则回复，守住睡前陪伴不中断的底线；在本地回复完整流式输出并落盘（`done` 事件）后，才向用户弹出居中暗夜风模态提示窗口（`AlertDialog`）。
2. **精准语义分流与双按钮引导**：文案精准区分 429 限流、401/403 鉴权失败、404 模型未找到及语音链路故障；提供【前往设置】（强调位深紫按钮）直达修复，并提供【知道了】（次按钮）允许用户留在当前会话继续以本地模式交流。
3. **会话级去重频控**：同类错误在当前会话内仅弹窗打扰一次，后续同类错误保留在输入框上方状态行以轻量文字呈现，避免打字连续受挫时遭遇弹窗轰炸。
4. **排除设计内降级与网络抖动**：`safety`（安全拦截）与 `no_llm_config`（未配置模型）是设计内降级，绝不弹窗；网络超时断开走轻提示，不误导用户改动正确配置。

## Considered Options

- **直接阻断聊天流，不生成兜底回复，仅报错弹窗**：被否——违背栖语核心哲学。栖语在断网或 Provider 异常时，本地规则引擎就是产品形态，绝不能把沉浸式睡前对话变成冷冰冰的 IDE 报错中断。
- **无条件每次失败都弹出模态弹窗**：被否——当用户账号欠费或遭遇严重限流时，用户连续发送几句话就会连续被全屏遮罩打断，产生严重的负面体验与打扰感。
- **顶部非模态浮层（Toast / Banner）**：被否——401（Key 失效）和 404（模型拼错）属于需要用户介入排查的硬阻碍，模态弹窗配合直达设置页能确保用户明确知晓并快速解决。
- **在收到错误判定瞬间立刻截断打字并弹窗**：被否——视觉上会造成文字正在流式输出却突然被灰色遮罩盖住的割裂感；等本轮回复从容落定后再弹窗，节奏最稳重。

## Consequences

- 前端在 `LocalChatView` 与 `LocalChatViewModel` 中维护会话级错误弹窗去重集合，并在 `LocalChatEventKind.done` 到达且本轮包含符合条件的 `fallbackReason` 时触发弹窗。
- 语音 STT 与 TTS 在遇到 429 或 40x 时，分别即时触发对应的服务异常弹窗，并提供前往设置的导航通路。
- 换页前往设置时严格遵守 ADR 0002 执行语音无条件停播（`voiceOutput.stopAll()`）。
- 词汇表增补「服务异常弹窗」，明确其与设计内降级的严格界限。
