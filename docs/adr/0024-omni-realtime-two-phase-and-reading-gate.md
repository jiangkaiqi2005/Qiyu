# Omni Realtime 两阶段划分与第一阶段的朗读准入门

2026-10-01。要接的是 `qwen3.8-omni-flash-realtime`——一个语音与文字都能进、语音与文字都能出的全双工模型，动机是让栖语的声音听起来像真人而不是念稿。本 ADR 记三件事：把这个能力切成两阶段并固定术语；第二阶段本次不实现，以及它开工前必须先裁定的清单；第一阶段（omni 只当朗读者）的准入门与判死条件。术语与 `CONTEXT.md` 的「流式朗读会话」「双工语音对话」两条同源。可执行形态另有一份 spec 与拆票，但那是本机资产（`.scratch/voice-omni-reading/`，在忽略规则里、不入库），因此**本文自足**：判据、破坏面边界与前置裁定全部写在正文，不依赖那份 spec 才读得懂。

## 一个词曾经指两件事

仓库里「Realtime 会话」原本只有一个意思：ADR 0019 建立的**文字进、语音出、持续喂文本**的朗读供给方式（千问 TTS Realtime 与豆包双向 WS）。omni 进来以后同一个词会指两种完全不同的东西——omni 的名字里带 realtime，型号名也以 `-realtime` 结尾，但它在第一阶段是当嗓子用的，第二阶段才是真的双工对话。CONTEXT.md 因此把前者定名为「流式朗读会话」，后者定名为「双工语音对话」，并在「型号驱动」条上加了一条 `_Avoid_`：**不能把「型号名带 realtime」当成双工语音对话的判据**。这条不是文字洁癖——型号驱动规则（`-realtime` 后缀走 WS）恰恰是靠名字分派的，而 omni 正好命中这个后缀却属于另一种能力。

## 第一阶段：omni 只当朗读者

第一阶段 omni 的职责被限死为**朗读已经定稿、已经过完清洗与人格边界校验的文字**。它不参与理解、不参与生成、不拿到人格宪法。用户写的那些 system prompt 一字不动，照旧进文字 LLM。这样做的全部理由是保住两条既有不变量：**文字永远是唯一真相源**（音频说的和落盘的必须是同一段话，重听不会听到另一个版本），以及**页面绝不能听到未经安全校验的原始输出**。omni 一旦有权改稿，链路末端就出现了第二个不受人格宪法约束的作者。

omni 的 `instructions` 字段官方支持且无独立长度限制（只受该型号 196608 输入 Token 上限约束），但第一阶段**只放朗读指令**（逐字朗读、不改写、不增删、不回应内容），不放人格摘要。取舍是：放人格可能让它更想「演」而不是「念」，不放则可能念成中性 TTS 腔、使「情绪跟随」这条判据落空。选后者，把风险交给准入门去量；若实测证明念得平，回退路径是把人格基调摘要加进 `instructions`，那是一次独立裁定。

**型号固定 `qwen3.8-omni-flash-realtime`，不同时评估 `qwen3-omni-flash-realtime`。** 已知代价：`session.smooth_output`（输出平滑开关）**仅 `qwen3-omni-flash-realtime` 独有**，选 3.8 就等于放弃了唯一能显式关掉输出平滑管线的手段。改写风险因此只剩三道闸：`instructions` 措辞、`temperature`、以及事后判死的 diff。

**端点不写死进代码。** WS 地址继续由 Host 从用户填的 baseUrl 派生（ADR 0019 已建立的语义），官方形状是 `wss://dashscope.aliyuncs.com/api-ws/v1/realtime?model=<model>`。用户侧另有千问 AI 平台入口，其 API Key 与百炼通用；该平台归属未查到 aliyun.com 域内的一手声明，故不在代码里预设任何非官方域名。

**不引第三方依赖。** pub.dev 无任何 DashScope / Qwen-Omni-Realtime 的 Dart 包；`openai_realtime_dart` 等三个 OpenAI Realtime 协议的 Dart 包虽在维护，但 omni 的 schema 有结构性差异（音频配置嵌套在 `session.audio.output.format.{type,sample_rate}`，扁平写法已标 Deprecated；`temperature` 等生成参数挂在与 `session` 同级的根层；有 `input_text_buffer.*` 与 `session.finish`），直接套用会跑不通。自写 adapter，复用既有 WS 抽象与会话骨架。

**破坏面边界**：行为不变；允许在 TTS 网关与档位注册表里加新档位分支与新接口方法；**不允许**动交付编排与安全校验顺序。凡必须碰交付编排的改动（见下面的危机兜底豁免），一律推迟到正式实施单，独立裁定、独立 ADR。

## 准入门

第一阶段能否成立，由五条判据裁定。任一条不过即**放弃第一阶段**，朗读退回 `qwen3-tts-flash-realtime`，omni 只留给第二阶段。

1. **逐字性**：omni 的文字转录（`response.audio_transcript.delta` 增量 / `.done` 全量，字段名 `transcript`）归一化后必须与原文**完全相同**。归一化 = 去标点、折叠空白、全半角统一、中文数字与阿拉伯数字互转（「23:40」↔「二十三点四十」）。归一化后**任何实词的增、删、改一律判失败**，不用相似度阈值——95% 相似的「我想了想……还是想问你」与「我想了想，嗯，还是想问你呀」体感完全不同，而这条门要挡的正是后者。归一化规则命中的每一条都要打印出来，不做黑盒函数。
2. **首音延迟**：omni 首音 ≤ **1.5×** 现有 `qwen3-tts-flash-realtime` 首音。两个原始数字都要打印，不只打通过/失败。这条只在**流式朗读会话**路径上有意义——整段合成路径结构上产不出「首音」，所以原型不能只接设置页试听。
3. **热线红线**：危机兜底回复（中文含 **12356**、英文含 **988**）列必测样本，且**号码读法靠人耳听、不信 diff**。归一化会把「一二三五六」与「一万二千三百五十六」都判成通过，而它们对危机中的人是天壤之别。这条兜底文本由本地规则引擎产生、绕过模型，system prompt 管不到它。
4. **纯停顿回复**：「……」「（等了一会儿）」这类只有省略号或停顿标记的回复是栖语的**合法输出形态**（行为核心有专门的正则识别它们，「少回应」写在产品灵魂里）。列必测；**omni 对这类输入自己加实词 = 直接判第一阶段失败**。
5. **标点停顿、英文、称呼**：标点全去，但**省略号与破折号单独记为人工听感检查项**（迟疑感被念成平铺直叙，diff 看不出来）；英文按小写折叠比对；**称呼被吞掉或念错单独标红**（称呼是 CONTEXT.md 里的受保护用户设定行，不经证据链）。

**样本来源**：行为核心的 golden 只锁得住**六条兜底话术**（危机三行、医疗、法律、金融），够覆盖判据 3，覆盖不了其余五类。极短句、带称呼的安慰句、迟疑句、中英混排、多句段这五类从人格宪法的示例话术或真实 sessions 取，**取来的必须标注出处**——现编的样本容易编成「AI 腔的温柔」，用假样本测韵律自然度得出的结论不可信。

**已知代价**：`temperature` 不作扫描维度，只用官方默认 **0.6**（该默认值是为对话调的，不是为朗读调的）。后果是若判据 1 判死，**无法区分「模型不老实」与「温度过高」**——届时补测 temperature 是第一步，不是直接放弃 A。

**音色靠矩阵挑，不靠推断**：官方音色表约 60 个，名字之外没有任何可核验的听感凭据，因此原型输出音色矩阵（6–8 个候选，含 3.8 默认 `Tina` 与 `Zane`/`Cici`/`longanlingxin` 三个 3.8 独占音色，每个念同两条文字）由人耳挑。挑出的精选集落进档位映射表的数据行（CONTEXT.md：「新模型发版靠加数据行而非写代码」），并**按型号过滤不可用音色**（`Zane`/`Cici`/`longanlingxin` 仅 3.8；`Sunnybobi`/`Ethan`/`Harvey` 仅 3.5 系）——ADR 0019 有明文「禁止展示尚不可用的选项」，用户选了型号 A 配音色 B 会失败，与 ADR 0015 的「模型与接口不匹配」同族。

## 第二阶段：本次不实现，代码零占位

双工语音对话（麦克风常驻、模型直接听懂并开口）本次**不实现，且代码里不留任何占位**：不留形状 id、不留接口、设置页不露置灰选项。依据是 ADR 0019 的既有裁定「禁止展示尚不可用的选项——两个协议都接通后才露出」与仓库「不做半成品实现」。它只以本文的前置裁定清单形式存在。

### 开工前必须先裁定的清单

- **安全审核窗口（最硬的一条）**：双工音频直接从模型出来，**没有「先审后放」的窗口**，与「页面绝不能看到未经安全校验的原始 token」正面冲突。三种裁法各有代价——文字转录先到并过审再放行对应音频段（首音延迟回到秒级）、音频先播异步校验命中即掐断（话收不回）、或仅在受限指令集下允许先播。**这一条不裁定，第二阶段不能开工。**
- **否掉 WebRTC，走 WS + 自写采集。** 官方浏览器路径是 WebRTC + DataChannel（`oai-events` 与 `txt` 两条通道，SDP 经业务侧代理换取），WS 路径官方只给了 Python 示例。而 Host 是纯 Dart 进程、没有 WebRTC 媒体栈：前端直连云会**暴露 API Key**，Host 自建媒体中继在 Dart 侧无可用轮子。故走 WS + AudioWorklet 自写上行采集（仓库已有 AudioWorklet 播放与 16 kHz 单声道录音桩，安卓侧有对应的原生录音实现）。**否掉 WebRTC 的唯一理由是密钥不能出 Host**——将来若 Dart 侧出现可用的 WebRTC 媒体中继方案，这条要重新评估。
- **`<memory_recall>` 隐藏块须改 function calling。** omni 支持 `session.tools`（function 与远程 MCP 两种条目），但非自然语言标记在语音模态下大概率被输出平滑管线吞掉；且官方 SDK 文档写明**命中工具调用时模型只返回参数、不出音频**，召回瞬间会静音，这段体感要单独设计。另：**`tools` 与 `enable_search` 互斥**，第二阶段的联网搜索与记忆召回不能同时开。
- **会话上限口径不同**：单次会话最长 120 分钟；音频最多 100 轮 / 累计 600 秒，超限自动丢弃较旧轮次。与 ADR 0019 的「绝对截止 10 分钟」不是一回事，不能沿用。跨连接的会话恢复机制未查到官方文档，多轮上下文只在连接内保持。
- **上行音频规格**：pcm 16-bit 单声道 **16 kHz**，base64 放在 JSON 文本帧的 `audio` 字段（未查到二进制帧通道），官方建议每包 100 ms，手动模式缓冲上限 15 MiB。轮次控制靠 `session.turn_detection`（`server_vad` 默认 / `semantic_vad` 仅 3.5 与 3.8 / 设 `null` 关 VAD 改手动 commit），有 `interrupt_response`（默认 true），但**不存在 `response.cancelled` 事件**——取消与中断统一由 `response.done` 的 `response.status` 表达，「半句不当完整回复」的不变量要基于它实现。

## 顺带发现的两个既存问题

1. **ADR 0019 引用了不可核验的凭据**：其正文以 `.scratch/streaming-delivery/spec.md` 作为 spec 出处，而 `.scratch/` 在忽略规则里，那份文件从未入库。与「引用文件须入库」的惯例冲突。本文不重演——判据直接写在正文。0019 那处是既存的，本次不改。
2. **纯停顿输入无测试覆盖**：现有 `qwen3-tts-flash-realtime` 遇到「……」这类输入的行为，仓库里没有任何测试锁定。由此派生一条**独立于 omni 的既有行为修正**：纯停顿与只有标点的回复**不应送朗读**——沉默被念出来本身就是错的，与用哪个 TTS 无关。该修正单独一个小改动 + 测试，不混进 omni 接入。

## Consequences

- 第一阶段的成败完全由准入门裁定，不由听感裁定。这是刻意的：omni 的声音很可能确实更像真人，而那恰恰会让人忽略它改了稿。
- 原型先于实现。原型产物是 wav、并列的延迟原始数字、归一化 diff 明细与音色矩阵，不是代码；原型脚本放忽略目录，用完即弃。原型通过后才写 adapter 与档位映射行，结论另写一篇 ADR（通过则记「接入为流式朗读会话的新形状」，判死则记「评估后放弃 omni 朗读、只留给第二阶段」——两篇完全不同，故不预写）。
- 危机兜底的朗读豁免在原型期只做人工听，代码级豁免推迟到正式实施单，因为它必然要碰交付编排、超出本文划定的破坏面边界。
- 采样率存在官方文档自相矛盾（一处枚举 `8000/16000/24000/48000` 可配，另一处写「默认 pcm 24 kHz、暂不支持自定义采样率」），原型须实测确认；下行默认 24 kHz 与既有播放栈按块携带采样率的形状相容。
