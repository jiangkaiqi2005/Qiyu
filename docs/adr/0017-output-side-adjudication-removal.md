# 输出侧裁决退场：文字流式输出与失败留半句

2026-09-23 流式传输三票之票一（spec `.scratch/streaming-delivery/spec.md`，对齐台账决定 1/2/3）。原交付形态是「模型整段生成完 → Host 完整缓存 → 六关校验 → 通过后按 12 runes/70ms 分片吐字」：首字延迟等于整轮生成时间，思考档模型下用户对着空气等十几秒；更贵的代价是模型只是轻微不端（漏一句客服腔、写一句越界话）时整段回复被扔掉换成本地兜底——用户看到的是「话说到一半被换成了生硬的罐头」。本 ADR 记录输出侧裁决的整体退场：两张判决名单（客服腔违禁词、人格边界正则）删除，人格约束回到提示词层由模型自判断；交付改为「增量卫生处理 + 活前缀边收边送 + 终局落盘」；协议失败分叉为「无可见文字走本地兜底 / 已有可见文字留半句」。

## Considered Options

- **保留名单、只加分片提前**：把违禁词/人格边界判决挪到流式前缀上（前缀命中即整段回退）。被否决：回退仍旧发生，「半句被换成罐头」的体验原样保留，且前缀级判决会让同一段回复在不同网络速度下得到不同结果——判决本身变得不确定。
- **只删名单、不改造交付**：回到「整段缓存 + 清洗 + 分片」。被否决：首字延迟问题原样保留，而删掉终校判决后整段缓存已无判决可做，缓存只剩纯成本。
- **删名单 + 流式交付 + 失败留半句（本裁定）**：输出侧只保留协议与格式卫生，人格约束交回提示词层；协议失败时已显示的部分如实落盘。

## Decisions

- **两张名单整体退场，连坐清除干净**：`_forbiddenPhrases`（11 句客服腔）与 `_personaBoundaryPatterns`（12 条人格边界正则）删除，`FallbackReason.forbiddenPhrases` / `personaBoundary` 两个枚举值、行为契约 golden 事件、约 10 处测试断言、Flutter 兜底展示分支一并清除，不留诊断旁路。笔记无人需改：规则本身在《人格宪法》与《产品灵魂》里继续靠提示词层生效，删的只是 Host 强制执行。
- **保留的卫生检查**（协议与格式，不是人格判断）：隐藏结构剥离（思维链与动作块闭合前整块扣住，绝不上屏）、控制模式（可见区出现 XML 标签或动作键/值形态即一票否决）、逐行清洗（说话人前缀/代码围栏/纯省略号行/舞台提示行/行首时刻前缀）、2000 runes 上限、空回复走本地兜底。
- **一份实现两条路**：增量卫生处理器 `CandidateReplyStream`（行为核心）同时供批处理校验 `_validateCandidateReply` 与 Host 流式交付使用，清洗规则（隐藏结构剥离、控制模式、逐行清洗、长度上限）完全一致；两条路的终局策略不同——批处理一律否决，流式由调用方按「有没有可见文字」决定本地兜底还是留半句。已吐出的文本只会是最终可见文本的前缀：未完结行只吐「确定性前缀」——还可能被整行丢弃、被剥掉行首前缀、被 trim 掉行尾空白、或改写形态（未落定尖括号、未闭合花括号、控制词前缀）的一律扣住不吐。**唯一例外**：控制模式否决时，受污染行此前已吐出的确定性前缀随整行撤回（细粒度增量下真实发生）——那行本来就不是合格回复，撤回比留着半截控制构造诚实；撤回点恒在行边界，此前已完成的行不受影响。若受污染行是本轮唯一行且连同行内干净文字一起撤空，可见文本为空，走本地兜底分叉（与批处理一致）。
- **节奏不变，数据源更换**：仍走 12 runes/70ms 匀速分片（`_deliveryChunkRunes` / `_deliveryChunkPause` 为唯一真源，流式活前缀与本地兜底/召回 bubble 共用），只是数据源从「整段校验完的文本」换成「边收边送的活前缀」；敏感输入（危机/医疗/法律/金融）沿用现状不分片停顿。
- **协议失败分叉**：取消（用户主动）沿用现状——在途显示清空、无栖语 turn 落盘、用户 turn 保持可重试。协议失败与输出卫生否决（可见区出现控制模式、超过 2000 runes 上限）走同一个分叉：尚未产生任何可见文字时走今天的本地兜底路径（含错误提示现状）；已产生可见文字时把已显示部分作为该轮最终回复落盘并交付，消息带「未完成」标记（message 事件新增可选字段，不新增事件种类）。标记语义是「该轮未完整交付」——协议失败与卫生否决两类半句都带它：前者是模型没说完，后者是模型说完了但后半被拒，两者都已显示的部分都如实保留，不弹错误框、不追加兜底话术，失败原因进本机诊断。半句轮的隐藏动作不提交、不触发轮内召回——文本如实落盘，动作不落地。
- **契约同步**：`contracts/qiyu_behavior_contracts.json` 删除两个兜底 golden 事件，`deliveryEvents` 补「未完成」message 线格式，新增 `streamingDeliveryCases`（增量早于终止、提前 EOF 留半句、原生 error 留半句、无可见文字本地兜底、取消撤回、隐藏块不上屏、控制结构三种时机：同行工具调用标签留半句、同行 JSON 载荷整行撤回走本地兜底、无可见文字的控制载荷走本地兜底），由进程内 Host 测试直接消费，不以实现内常量或单端自测替代。

## Consequences

- 首字延迟从「整轮生成时间」降到「首个通过卫生检查的增量到达时间」；思考档模型下用户立刻看到栖语开始打字。
- 模型轻微不端不再触发整段回退：漏一句客服腔照常显示，回复损失从「整段」降到「零」。
- 「不能把半句当完整回复」的旧口径反转为「半句可如实落盘，不补全不伪装」：故障是诚实的，不再被兜底话术粉饰。
- 「未完成」标记只活在直播流的 message 事件上，不落盘——刷新或恢复后标记消失，半句文本本身照常保留（Markdown 会话格式不变）。
- 输出侧不再有人格/话术判决，人格一致性完全依赖提示词层；若将来要恢复 Host 侧强制，需重新立决定并同步契约与 ADR。
- 语音侧（票二/票三）的流式交付架构另立 ADR；本 ADR 只覆盖文字输出侧。
