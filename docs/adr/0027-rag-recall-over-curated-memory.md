# 用 RAG 定位 episodes，保留现有记忆体系

保留 Markdown 文件职责、五段整理节奏和热层直接使用，RAG 的唯一索引语料为整理后的 episodes。月摘要与 PersonaTree 保留原有用途，不进入向量索引；原始 sessions 同样不索引。用户以较小接入与维护范围换取这一边界，取消跨层向量、画像路径展开和派生依赖管理；该取舍以 2026-10-08 访谈 Q16 为最终裁定。首要目标仍是改善旧事召回，原始 sessions 实验不能替代 episodes 及最终回答的产品评测。

模型仍通过 `memory_recall{query}` 按需发起召回，只将能表达已知对象、事情与时间线索的语义 query 发送给 embedding；不拼接最近对话全文，不增加日期范围字段或硬过滤。文字补气泡／下一轮临时上下文与 Omni 工具回填保留现有交付节奏，首响不强制等待检索。由已有回答调用判断候选，不新增独立评分或重排；明确拒绝的候选不进入下一轮，未完成判断不冒充无结果。

用户明确配置兼容服务地址、模型和独立 Key 并了解发送范围后启用外部 embedding；保存配置与启用分开，首次完整建索引后开放 RAG。未启用时保留旧目录召回及其协议兼容；启用后故障或准备状态不自动回退。新增 episode 后台增量进入索引，编辑、删除、禁提、冻结或失效条目立即停用；不等待重新 embedding 才停止使用旧内容。月摘要与画像不在本次新检索的失效适配范围，不宣称现有旧派生问题已修复。

更换服务或模型身份后，旧索引停止用于新查询，显示需要重建，由用户明确发起后台重建；同一作用域内仅更换 Key 不重算向量。设置页与聊天均提供独立简短状态提示，不将状态当作模型回复或历史 turn。自动回归之外，必须用同题对照检查最终回答并报告等待与费用；没有改善不宣称达标，私有材料保留本机。

每条 episode 仅以日期与摘要生成一个向量；命中后重读当前摘要与证据摘录，摘录不进入 embedding。后续产品接入只移植需要的客户端、向量逻辑与测试，不合入整个实验目录；已建立新工作树 `codex/episode-rag-recall` 供后续使用。

既有本地 develop 提交已按 Q22 推送，远端与新工作树基线一致。Q23 决定不新增跨 episode 的纠正关系：源内容哈希仅验证同一条目，漏召回最新语义纠正作为评测限制，由当前消息、热层、近期对话和模型判断处理。

全部访谈决策已综合为 ready-for-agent Specs，当前只交付本地规格，不实施产品代码或创建 PR，也未改写旧设计笔记定稿。完整规格见 `docs/specs/2026-10-08-rag-memory-recall.md`。
