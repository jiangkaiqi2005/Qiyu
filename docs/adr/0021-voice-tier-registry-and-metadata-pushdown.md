# 语音档位归口与元数据下推

本 ADR 记录档位知识收口专题（票 08）的决定：把「一个档位 = 请求形状 + 端点 + 鉴权 + 能力 + 缺省配置」在宿主侧收成一处可枚举的档位归口（`voice_tier_registry.dart`），三张合成分派表退化为查表结果，档位元数据经既有设置 HTTP 接口下推，设置页按数据渲染。与 ADR 0020（档位映射与地址派形状）、ADR 0018/0019（流式交付与连续供给）同族；是「单一真相在 Host、界面只消费」这一方向（ADR 0020 映射表边界第 3 条）的收尾。

## Context & Decision

1. **档位归口一处可枚举。** 票 08 之前，同一个档位的知识散在四处：合成网关三张分派表（整段/流式/开会话的 `switch`）、设置页的档位目录与缺省值表（`_ttsProviderChoices`、`_ttsProtocolDefaults` 等）、设置客户端与宿主包同名同值的缺省常量（千问两族共五组双源）、以及映射表与网关里的档位判定。四处的任何一处改动都要人肉同步其余三处。归口把每个档位收成一行 `VoiceTierDescriptor`：身份（族 + wire 名）、设置页元数据（标签、简介、模型框标签与支持范围说明）、端点与缺省配置（缺省地址/型号/音色与输入提示）、能力（传输选项、自定义旋钮、语速滑条、音色形态、实时形态后缀、允许 scheme、鉴权头缺省）与请求形状行（`TtsTierShape`，按分派优先级排列）。新档位发版＝加一份数据行；复用既有请求形状的档位到此为止，新协议形状才需要配一个新网关实现（形状行的工厂直接引用它）。

2. **三张分派表退化为查表，一致性由构造保证。** `TtsModelGateway` 的整段、流式、开会话三张 `switch` 表合并为一次 `resolveSynthesisShape(config)` 查表：按档位行的形状排列取首个命中行，三种能力（整段/流式/会话）各自的处理网关都挂在同一形状行上。三张表共用同一次解析，不再可能各落各的形状；千问档「型号驱动先于地址判定」（ADR 0020 补篇）与豆包档「WebSocket 双向先于 HTTP 分块」的优先级由行序表达。退化前后的语义落差逐条对拍锁定（`voice_tier_registry_test.dart` 的能力矩阵、`tts_session_dispatch_test.dart` 的端到端对拍）：实时形状没有句级流式通道，其流式回落行是现行 multimodal 网关（会话开不了时整轮不开语音，D1 口径不变）；豆包双向形状的流式回落行是 HTTP 分块网关（E1 回落，流式分派不看传输）；开会话表此前零测试的缺口由端到端对拍闭合。如实登记一处与旧表的流式落点差：「realtime 型号配 wss 推理地址」组合，旧表按地址判型落 WS 推理网关，新表按型号驱动落实时形状、句级流式随之走现行 multimodal——该组合产品链路不可达（realtime 恒先开会话且 D1 下不回落分句），落点差没有行为后果，现行为由对拍测试锁死。转写分派表不在本票范围（单一表、无形状分派），保持原状。

3. **档位元数据随既有设置接口下推，界面按数据渲染。** `GET /api/provider/stt` 与 `GET /api/provider/tts` 的快照新增 `tiers` 字段：宿主归口按族导出的元数据行集（能力/形状/端点缺省/文案，**绝无密钥**——载荷字段收在允许清单里并有遍历测试锁定）。设置页不再自备档位知识：服务类型下拉按行集渲染、简介与说明文案随行下推、缺省回填读行内端点/型号/音色、切档的地址兼容判定读行内允许 scheme、传输下拉/自定义旋钮/语速滑条/实时形态禁用全部读行内能力开关。设置分区里的档位 switch、目录表与缺省值表随之删除；票 04 留下的实时档镜像判定 getter（`isQwenRealtimeTier` 里对千问档的点名）随本票退役——实时形态由元数据的后缀规则驱动，档位不再被界面点名。

4. **双源缺省常量退役，降为旧宿主降级数据。** 千问两族五组「宿主常量 ↔ 界面同名常量」双源同值的缺省常量（`qwenTtsDefaultEndpoint/Model/Voice`、`qwenAsrDefaultEndpoint/Model`）与新版通道两组（`qwenTtsWsInferenceEndpoint`、maas 地址模板）从界面主链路退役：主链路的缺省值来自下推元数据，界面常量只剩两个消费方——旧版宿主的内置降级目录（见下条）与既有测试的参照值。降级目录与测试参照引用同一批常量，同源不同步即不可能。

5. **旧版宿主降级形态：内置最小缺省目录。** 快照缺 `tiers` 字段（旧版 Host）时，界面回落 `builtinTtsTierCatalog`/`builtinSttTierCatalog`：冻结在今天已知的档位集合，可用、与升级前渲染一字不差，但不新增档位知识——新档位只能经下发行集进来。降级形态写入本 ADR 并配测试（快照无 `tiers` → 表单按降级目录回填与渲染）。同族兜底：快照带 `tiers` 但缺当前档行、或查询目标不在下发与降级行集时，档位查询回退到「未知档最小可用行」（标签即 wire 名、无缺省知识、HTTP 家族语义）——不崩溃、不静默丢档；换档建议的目标档不在行集里时维持保守不回填（确认制兜底，与 ADR 0020 决策 11 同律）。

6. **未知档位的身份保全。** 界面档位集可以比界面枚举（`TtsServiceKind`/`SttServiceKind`）大：快照里的原始 provider wire 名保留在 `providerWire` 字段（类型化视图的防御回落口径不变），表单按 wire 名持有选择、按元数据渲染，保存草稿对枚举外的档位上送原始 wire 名（`providerWireName`）——未知档位的类型化视图按缺省档呈现（既有防御口径），身份不因界面枚举封闭而丢失。两个界面枚举按评审裁定保留原位：它们是既有设置测试断言的契约面，也是类型化视图的载体，本票不删（若将来归口元数据长出替代契约，另票处置）。配置层的协议枚举（`TtsProviderKind`/`SttProviderKind`）是封闭集合：宿主自己接受一个新档位的保存，仍以配置层认识它的 wire 名为前提（新档位发版随版本发布，两端同版即达成）。

7. **provider.json 的文件格式契约不搬。** 配置校验与落盘里的档位条件（scheme 白名单、自定义旋钮只对 custom 档校验与落盘、传输只对豆包档落盘）是 provider.json 的文件格式契约，消费方只有配置层自身；把它们搬进归口只会让宿主配置解析依赖整个网关世界。归口收的是「请求形状 + 端点 + 鉴权缺省 + 能力（下推）+ 缺省配置」，文件格式契约留在 `provider_config.dart`。

8. **预设音色目录保留界面侧（有意识的呈现层边界）。** 豆包与 OpenAI 兼容两族的预设音色库留在 `provider_catalog.dart` 随界面版本发布：目录是展示资产、非协议知识，归口元数据只带 `voiceMode` 与缺省音色，不做目录下推。边界代价如实登记：`presets` 音色形态的新档位需要界面补一行目录，归口加行不再单独完整；且该形态的未知档位在界面侧会按类型化视图回落误挂 OpenAI 目录（类型化视图按缺省档呈现的既有口径，仅影响展示不涉协议与凭据）。非 presets 音色形态的档位（自由输入、无音色位）不受此边界影响。

## Consequences

- 「新增档位＝加数据行」达成：归口一行（形状行 + 元数据）随版本发布，三张分派表、两个设置页与下推载荷零改动自动跟上——该「零改动」按决定 8 限定为非 presets 音色形态的档位；`presets` 形态的新档位还需界面在 `provider_catalog.dart` 补一行音色目录。测试面收敛为归口遍历断言加一处演示用例（宿主加行 → 快照 `tiers` 带上 → 设置页出现）。
- 双源漂移面收缩至如实边界：主链路的档位文案、缺省值与能力开关与宿主同源下发，降级目录是冻结快照、只服务旧版宿主，漂移不进主链路。界面代码如实残留两处档位知识：`wantsWavAudio` 仍在 `stt_settings_client.dart` 以枚举判档位能力并被语音输入链路消费（录音是否转 WAV 的协议级能力，归口元数据暂无该能力字段——登记为后续票候选，届时随归口加能力字段下推）；预设音色目录在 `provider_catalog.dart`（决定 8 的呈现层边界）。
- 界面档位集与宿主解耦：宿主先于界面升级时，新档位经下推出现在设置页并可用（能力元数据齐全）；界面先于宿主升级时，无 `tiers` 字段即走降级形态，行为与升级前一致。
- 元数据载荷随快照全量下发（每族四行，数 KB 量级），随版本发布、无运行时拉取（ADR 0020 映射表边界同律：表决定端点与档位，可被替换的表即密钥外泄面）。
- 分派回归面收敛：三张表的对拍测试（形状 id 能力矩阵 + 会话端到端）替代「改分派要脑内跑三张表」；既有 2400+ 行 WS 协议测试与各网关用例零改动通过，协议实现不受归口影响。
