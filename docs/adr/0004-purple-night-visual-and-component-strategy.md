# 紫夜视觉方向与组件策略

2026-08-27 定稿。栖语 Web（Flutter）的视觉方向定为偏紫暗夜色调，组件策略定为「Material 3 内置组件 + 栖语薄包装层、零第三方 UI 依赖」，字体全局思源宋体（Noto Serif SC）。规范全文见 `docs/product/design-system.md`，此处只记决策与理由。

放弃旧 design-system 的暖金黑夜色方向与霞鹜文楷：那是已退役旧 Web 产品线的定稿，与用户 2026-08-27 的定案（偏紫）冲突，已由用户亲自裁定废弃。

## Considered Options

- **强调色用 M3 自动派生的淡紫**：被拒。实际界面验证（发送按钮）显示粉嫩、低对比、不高级；改为深鸢尾紫 `#55489c → #463a85` 微渐变 + 近白图标，状态色另用亮紫 `#9d8fe0`。渐变的唯一目的就是去粉嫩感，不是装饰。
- **引入第三方 Flutter UI 组件库**：被拒。生态质量与维护堪忧，「不重复造轮子」的正确落地是复用 M3 组件的交互状态机（焦点、无障碍、按压），只包一层 token 与造型。
- **全局黑体（Noto Sans SC / HarmonyOS Sans）**：被拒。用户要求「静谧高级」，衬线宋体的书房感是产品与 AI 工具拉开距离的关键；单字族 + 子集化控制体积。
- **导航全端统一（全常驻侧边栏或全汉堡抽屉）**：被拒。桌面常驻 240px 毛玻璃侧边栏、窄屏汉堡抽屉（约 2/3 宽），两端壳不同但页面核心相同。

## Consequences

- 组件与主题一旦按此实现，改色板/字族成本显著，视觉返工应先回到本 ADR 与 design-system.md 重新裁定。
- 首页背景图（美术馆参考图）的暖黄与紫夜混色经用户裁定为可接受，验收时不得以色温不一致为由返工。

## 后续修正（2026-08-28 原型验证）

原型迭代进一步收紧了紫的使用范围：表面色（底色/面板/描边/气泡）全面中性化去紫味，选中态从亮紫改为中性表达，亮紫收窄为仅焦点/键盘导航；新增暗红 `#cc9999` 为破坏性操作专属色。最终形成「三色纪律」，见 design-system.md 与 frontend-design-decisions.md。

## 后续修订（2026-08-28 待定项收口）

- **连接状态呈现**：侧边栏/抽屉底部 6px 中性小圆点 + 13px `muted`「栖语在本机」，仅 Host 健康探测失败时圆点与文案同转 danger 并可点重试。正常态不着紫、不用 danger——三色纪律延伸到状态指示，不为其开口子。
- **背景图资产**：入库只压尺寸（宽 1600、JPEG 质量 65，由 `scripts/prepare-visual-assets.ps1` 纯 PowerShell + System.Drawing 一次性生成，不引入 Node 构建依赖），虚化与调色全部运行时施加——代价是接受一次全屏 `ImageFiltered` 的开销，换取调参不重新出图；掉帧时改预烘焙，属实现期可回退项。
- **字体子集化**：由「构建时子集化」改为一次性裁静态子集随包入库（发布门禁不依赖 Node/npm，构建期子集化做不到）；完整思源宋体改子集后体积约 3.5–4.5MB，仍远小于原黑体完整字族 17.7MB，「单字族 + 子集化控制体积」的原结论成立，旧 `NotoSansSC-QiyuBaseline.ttf` 与其 OFL 同提交删除。
- **保留 `Roboto` 别名**：asset 换成宋体子集但别名不删——它是 2026-08 修「字体回退卡死」时为防止未随包字族触发远程回退而设，删掉即重新引入同一 bug。
