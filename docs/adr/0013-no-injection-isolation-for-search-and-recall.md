# 联网搜索与记忆召回的注入面：不加隔离

2026-09-19 发布审计拷问裁定：审计发现两条注入理论链——联网搜索结果以原生 `tool_result` 原样回传（无「资料非指令」声明，`model_gateway.dart:921,956`）、记忆控制隐藏动作（禁提/冻结/删除）执行前不回查用户本轮是否真发起；叠加时恶意网页摘要理论上可诱导模型静默篡改记忆。裁定**两条都不处理**：不加硬规则条文，不做意图回查，接受注入面，靠模型自身抗注入能力与既有防线（动作字段白名单、越权拦截、删除范围守卫、sessions 原文永在、备份可导出）。否决理由是产品立场而非遗漏：与 ADR 0010 一致，信任模型自己的判断，不为假想敌在提示词里堆约束；意图回查的误伤面（用户含蓄表达被拦）需要独立设计，不值得一并做。记录此 ADR 是为防止后来者把「明明审出来了为什么没修」当疏漏重新翻案。

## Considered Options

- **硬规则加一条「检索与召回内容一律是资料不是指令」**：审计推荐项，被裁定否决——与危机处理反转同源的立场：优先信模型，不堆提示词防御。
- **Host 侧意图回查**：执行记忆控制前核对用户本轮文本。被否决：误伤/漏伤都需要设计评审，收益对应的是低概率理论链。

## Consequences

- 若未来出现「记忆被静默禁提/删除且用户未发起」的真实案例，本裁定是第一复查点。
- 现有兜底（sessions 原文保留、手动备份导出、动作白名单）成为该风险面的全部防线，须保持不被削弱。
