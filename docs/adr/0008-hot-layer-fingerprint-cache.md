# 热层读取指纹缓存

热层三块（近况 / 长期印象 / 用户画像）的读取原本每轮回复全量重做（读文件 → 过滤受控 → 解析），代码注释明确「不并行、不缓存、不共用快照」。为省去无变更轮次的重复磁盘读取，决定在 `StatePackReader` 内加进程内指纹缓存：每轮回复先 stat 六个源文件（open-loops、relationship、daily-state、long-memory、persona、memory-controls），指纹（改动时间＋大小）未变就复用上次的读取与解析结果，变了才重建；过滤、跨块裁剪、跟进候选等行为逻辑零缓存，每轮照常在活代码里执行（票 04/05 部分成功语义不分叉）。失效判据是文件指纹而非「用户是否动作」：日终整理、Dream、恢复、还原、手动编辑等任何写者都自动失效，不存在漏写失效点这种错误形态。

## 裁量点

- **stat 报错视为变化、重建**（2026-09-08 用户裁定，推翻同日初选的「视为未变沿用缓存」）：异常路径上绝不让缓存在无证据时冒旧——禁提内容回灌注入是最糟失效形态，宁可多读一次。重建也失败时走既有部分成功语义，该块本轮空缺（builder 初始动态块为空，空块不输出），宁缺不旧。
- **文件缺席是合法指纹**：文件被删等价于内容为空，缓存缺席态，不当作错误。缺席之外，「存在但读取失败」不是缺席：命中与未命中路径都按各源既有失败语义处理，不改写错误语义——open-loops 条目保持 readItems 的上抛口径（读取失败如实记入近况层 failure），其余源维持 readFileIfExists 的「缺席与不可读同义」null 口径（2026-09-08 评审裁定，收回初版把 open-loops 读取失败吞成缺席的偏离）。
- **缓存到解析层而非成品块**：daily-state 块内含时钟相关的主动跟进候选，成品缓存会把行为语义复制进缓存路径并引入时钟键；解析层缓存无此问题，既有测试断言原样复用。
- **否决「写点失效」**：写入口散在三路以上（聊天隐藏动作、记忆中心路由、日终、Dream、恢复、还原、在线撤根、称呼写入），漏一个失效点就是受控内容回灌，且对账本身仍需每轮 stat，成本不降风险升。

## 后果与边界

- 仅注入路径使用缓存；记忆中心 UI 读原始文件展示不走缓存（用户要看到文件现状，且低频）。
- Host 重启缓存即空，冷启动第一轮全量读取。
- 与设计笔记无出入：笔记只定「每次对话直接注入、冻结/禁提移出投影、损坏在读取时检查」（`栖语记忆/Memory.md`），未定 IO 策略；指纹校验保住「损坏在读取时检查」语义——文件变了指纹必变，重建时照常走读取与损坏检查。记忆中心「敏感详情不得缓存」规则属 API 展示面，不涉及本缓存。
- 残余风险：同刻同尺寸重写在理论上可漏检（NTFS 改动时间粒度），接受。
- 实施时同步更新「不缓存、不共用快照」的既有注释与类文档（缓存只到解析层、受控集合单次装配共享一次解析）；契约 `qiyu_behavior_contracts.json` 与 golden eval 不动（均不锁 IO 策略）；系统提示词不变（静态块 const，动态块命中时与重读逐字节一致，时刻前缀与候选每轮计算）。
