# Spec：复制键跟随时刻显隐与聊天页划选（copy-button-follow-moment）

状态：定稿（2026-09-21）。grill-with-docs 五题拷问全部对齐（结论见「实现决策」第 1、13 条）。第一部分（复制键跟随时刻显隐 + 范围扩到栖语）已提交 264e371，807 个测试全绿。第二部分（聊天页划选）结论已写入本 Spec，**代码待用户放行才动手**；动手时将连带撤掉 264e371 里的触屏长按复制菜单（用户裁定：触屏长按归划选）。放行后待办：实现 → design-system.md 决策日志补登 → 全量门禁 → 提交。

## 问题陈述

用户气泡里的复制钮常驻在消息旁边，任何时候都在——它和消息正文一样重，却没有时刻那样的显隐纪律，界面平白多出一排常驻按钮。而时刻早有一套成熟机制：桌面悬停同显同隐、触屏常驻淡显、滚动不乱闪。复制是低频动作，本该搭这趟车，而不是自己发明第二套。另两件事堵在一起：此前只给用户消息配复制，栖语回复里想存一句话，只能手动划选——而聊天页的文字根本划不动（Flutter Web 的文字画在 canvas 里，浏览器原生划选无效，划选要应用自己提供选择区；聊天页一直没包，整页可选中只做在历史回看页）。想存一句话，两条路都堵着。

## 方案

复制键从气泡里搬出来，落进时刻那一行，与时刻同一个显隐开关。桌面鼠标路径：悬停整条消息，时刻在左、复制在右同一行出现，用户消息整行贴气泡尾缘（栖语靠左），移开一起收起；时刻行现有的一切逻辑——80ms 显现延迟阀、列表层 `QiyuHoverGate` 滚动/行进抑制、滚动开始即隐、时刻位常驻预留槽位零位移——原样复用，不新开机制。划选能力补进聊天页：消息列表外补选择区，与历史回看页同款同位置——桌面按住左键拖动就能划选两边消息的文字，触屏长按起选、拖手柄、工具条点复制；滚轮、滚动条与触屏竖向拖动照旧滚列表。用户消息与栖语的消息一视同仁；历史回看页整页可选中复制，保持不给复制钮。

## 用户故事

1. 作为桌面用户，我想鼠标悬停某条消息时复制键和时刻一起出现，以便平时界面干净、要复制时伸手就有。
2. 作为桌面用户，我想鼠标移开后复制键和时刻一起消失，以便它不回来挡住阅读。
3. 作为桌面用户，我想复制键就落在时刻右边同一行、用户消息整行贴气泡尾缘，以便一眼看出它属于哪条消息。
4. 作为桌面用户，我想悬停显现复制键不改变气泡与列表的任何尺寸和位置，以便悬停时界面不跳。
5. 作为桌面用户，我想滚动列表时消息滑到静止光标下也不闪现复制键，以便滚动不受干扰。
6. 作为桌面用户，我想快速移动鼠标扫过消息时复制键不闪，以便只有真正停下来的悬停才唤出它。
7. 作为触屏用户，我想长按消息就能起选文字（和所有手机 App 一样），以便自由划取任意片段，不只整条。
8. 作为触屏用户，我想长按起选后拖动两端手柄调整范围，以便划多划少由我定。
9. 作为触屏用户，我想划完在工具条上点「复制」（或全选后复制），以便把选中的文字带走。
10. 作为触屏用户，我想长按起手后改成上下滑动（滚动列表）时不起选，以免滚动和划选打架。
11. 作为触屏用户，我想时刻行原本的常驻淡显完全不受影响，以便加划选不改变已有的时刻体验。
12. 作为刚发完消息的用户，我想一键复制自己这句话的全文，以便流式输出中断后不必凭记忆重打。
13. 作为读到金句的用户，我想一键复制栖语回复的全文，以便随时存走，不用手动划选。
14. 作为手机用户，我想栖语回复和我说的话一样可划可复制，以便两端体验一致。
15. 作为历史回看用户，我想整页可选中复制、页面上没有复制钮，以免回看页冒出多余的浮动按钮。
16. 作为读屏用户，我想复制钮带语义标签、时刻照常进语义树，以便看不见图标也知道那是什么。
17. 作为只用键盘的用户，我接受复制没有独立 Tab 焦点路径（登记为已知边界：消息本身没有键盘操作动作，不为每条消息增加 Tab 站）。
18. 作为遇到时刻数据缺失的用户（生产链路不会发生），我想复制钮退化为消息下方常驻一枚，以免入口彻底丢失。
19. 作为维护者，我想复制钮的画法（尺寸、tooltip、语义标签）与重听钮钉在同一处，以免两个小钮各画各的、慢慢漂移。
20. 作为用户，我想复制的就是这条消息的全文、一字不丢（含换行），以便复制品可直接他用。
21. 作为产品调性的维护者，我想这个入口静默完成、不弹提示不邀功，以便复制不变成新的打扰。
22. 作为桌面用户，我想在对话里按住左键拖动就能选中两边消息的文字，以便像在普通网页上一样直接划取片段。
23. 作为桌面用户，我想划选和悬停显现、复制键互不干扰，以便两种取用文字的方式能共存。
24. 作为触屏用户，我接受长按归划选（一键复制菜单让位），以便一个手势只对应一件事，划选比只能整条复制更自由。
25. 作为正在打字的用户，我想输入框不受选择区影响（它有自己的光标与选区），以便打字体验不变。
26. 作为桌面用户，我想鼠标拖动变成划选之后，滚动依然顺手（滚轮、滚动条，触屏上竖向拖动），以便划选能力不以牺牲滚动为代价。

## 实现决策

拷问定案与实现口径：

1. **入口重划（grill-with-docs 拷问后更改，覆盖 264e371 的对应部分）**：复制入口从「悬停钮 + 触屏长按菜单」两条指针路径，改为「悬停钮 + 原生划选」。桌面鼠标悬停整条消息，时刻在左、复制在右同一行出现（用户消息贴气泡尾缘、栖语靠左），点它复制本条全文；划选覆盖两个平台——桌面拖动、触屏长按起选。**撤掉触屏长按复制菜单**：长按在竞技场里只有一个胜出者，用户裁定归划选；菜单相关代码（长按回调、菜单构造、菜单返回值）整组删除，「复制这条消息」这份文案仍服务于悬停钮与防御路径钮。触屏行内不放常驻复制钮（用户早前裁定），触屏复制 = 长按起选 → 工具条复制。
2. **复制范围扩到栖语**（用户追加，已在 264e371）：用户消息与栖语消息都给。时刻行的复制钮不看说话人；at 为 null 的防御路径同步放开。栖语的时刻行靠左，复制钮落在时刻右侧同一行、随行左对齐；用户消息整行贴气泡尾缘。
3. **时刻位常驻预留槽高 21→30px**：2px 显隐间隙 + 28px 复制钮高（悬停位行内最大子项）。槽位仍静态取高——纯触屏路径行内只有 19px 时刻文字，指针类型切换不让布局漂移；显现零位移不变。`docs/product/design-system.md` 决策日志第 9/10 条记的 21px 由新登条目取代。
4. **几何保真**：时刻与复制钮同行顶对齐，时刻文字顶恒为气泡/文本块底 + 2px，与无复制钮时的几何一致。
5. **剪贴板即发即忘**（悬停钮与防御路径钮）：写剪贴板没有可恢复的失败动作（浏览器拒绝授权时保持安静）。
6. **无障碍**：复制钮的 tooltip 与图标语义标签共用一份文案「复制这条消息」（IconButton 只把 tooltip 写进语义节点的 tooltip 属性，label 仍空，触屏没有 hover，故图标自带 semanticLabel）；时刻照常进语义树，视觉弱化不丢信息。选择区的手势识别器标了不进语义树，划选不污染语义。
7. **键盘路径登记为已知边界**：不为消息块加焦点路径——消息本身没有键盘操作动作；选区的 Ctrl+C 复制由选择区开箱提供。
8. **复用不开新缝**：显隐开关、80ms 延迟阀、`QiyuHoverGate` 门控、小动作钮画法全部原样复用。
9. **布局基线**：composer 长高回归锁的滚动范围基线随栖语消息也走防御路径而变化（8278→9198，已在 264e371 更新，注释写清构成）。
10. **契约不动**：`contracts/qiyu_behavior_contracts.json`、本地规则引擎、Host 协议与 DTO 一概不碰——纯 UI 入口改动，回复内容零变化。
11. **与「操作入口常驻」原则的界线**：design-system 里「操作入口常驻、不藏进菜单」那条约束记忆条目的控制权（编辑/冻结/禁提/删除是信任承诺）；复制是低频便利动作，不属控制权，按用户裁定跟随时刻显隐。
12. **聊天页划选（grill-with-docs 五题定案，2026-09-21）**：
    - **位置**：消息列表外补选择区，与历史回看页同款同位置（选择区在最外、悬停门控在内、消息列表在内）；输入框与问候层不进选区（输入框有自带选区，包进去只会打架）。选区内容 = 两边消息正文、消息时刻行、流式增量文本——与历史回看页同口径，时刻行小字可划走，点空白即散。
    - **鼠标拖动与滚动的交换（题一，A）**：选择区的划选是竞技场里的 pan 识别器、命中半透明覆盖整个列表区域，且比列表滚动器深——鼠标在列表里按住拖动 = 划选，拖动滚动让位。滚动靠三条路：鼠标滚轮、右侧滚动条、触屏竖向拖动（触屏路径只注册横向拖动与长按，竖向拖动照旧滚列表）。
    - **触屏长按归划选（题二，A）**：撤掉已提交的触屏复制菜单后，选择区的长按胜出——长按起选、拖手柄调整、工具条复制；长按起手改滑动（超出触摸 slop）长按被否决、滚动胜出，不起选。横向/斜向拖动在触屏上会起选（选择区固有行为），接受为小边界：竖着聊天的列表里左右划少见，误划上了点空白即散，主路径（长按起选、竖向滚动）一寸不变。
    - **复制出口全用原生默认（题四，A）**：选区工具条（桌面「复制/全选」、触屏工具条）、Ctrl+C、网页右键上下文菜单，全部开箱行为，不自建工具条、不加提示。注意「全选」选中的是整个对话（选择区 = 整条消息列表），是选择区的标准语义。
    - **焦点行为全盘接受原生（题五，A）**：起选聚焦选区；网页上点选区外（如点输入框）选区解散；打字中抬手划选会移开焦点（手机输入法可能收起）；滚动时选区跟着文字走。不做自定义焦点管理。
    - **附带现象（已核实，登记备查）**：拖动途中鼠标扫过的消息照常悬停显现时刻与复制钮（既有悬停行为，非新问题），划完待鼠标移出才收起。选择区与消息块轻点识别器共存时的多击选词等开箱行为，和**历史回看页现状完全同构**（那页早有「选择区 + 消息块手势」的组合），聊天页不单独承诺、以历史页同样口径核对。

## 测试决策

只测外部行为，不测实现细节。缝仍是 widget 层那一口（气泡组件测试）与真实聊天页那一口，不开新缝：

1. **桌面悬停**：用户与栖语各一条——悬停各自出复制钮；几何锁（复制钮在时刻右侧、用户消息整行右缘贴气泡尾缘、栖语消息行靠左）；移开一起收；未悬停两者都不在树里。
2. **划选（替换 264e371 的长按菜单用例组）**：真实聊天页消息列表 seam——鼠标拖动跨消息后选区成立（经选择区状态读选区端点，起止落在拖动起止两点两侧；官方测试同款 `onSelectionChanged` 缝可作备选）；**触屏长按起选而非出菜单**（撤掉菜单后选择区的长按胜出——264e371 的「触屏长按弹出复制菜单」用例组随之作废重写，这是本次最重的一条回归锁）；触屏长按起手滑动 = 滚动不起选；滚轮滚动、悬停显现、单击轻点确认不受影响。
3. **负向与防御**：默认不给（历史回看档整页可选中）；at 为 null 时用户与栖语都落消息下方常驻一枚。
4. **回归基线**：composer 长高用例的滚动范围基线 9198（264e371 已更新）。
5. **变异实验**（仓库惯例，实跑复核锁的咬合）：复制钮条件恒真 → 几何锁翻红；选择区不包消息列表 → 划选锁翻红；把触屏长按菜单加回来 → 「触屏长按起选」锁翻红。

## 范围外

- 不自定义选区工具条与复制出口（原生默认已覆盖）。
- 不保「划选时输入框不失焦」（原生焦点语义全盘接受）。
- 不加复制成功的提示与反馈（静默完成是既定取舍）。
- 不做键盘焦点路径（已知边界，如实登记不假装解决）；Ctrl+C 复制选区由选择区开箱提供。
- 不改时刻行任何既有逻辑（80ms 延迟阀、门控抑制、触屏常驻淡显、槽位零位移全部原样）。
- 不动行为契约、本地规则引擎、Host 与协议。
- 不迁移、不触碰任何旧轨道残留。
