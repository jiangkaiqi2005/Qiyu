# Spec：称呼与首见引导（appellation-onboarding）

状态：定稿待放行（2026-09-03，grill-with-docs 拷问十题定案）。设计笔记定稿见 `E:\Note\Agent\栖语\栖语记忆\Memory.md`「称呼（2026-09-03 定稿）」节与「隐私优先」例外；词汇表 `CONTEXT.md`「称呼」「persona.md 总览」条目；ADR `docs/adr/0005-appellation-protected-line.md`。**用户放行前不写码。**

## 问题陈述

栖语的记忆文件通篇用「用户」指称使用者：记忆中心里读到的都是「用户道早安」「用户改完了前端代码」，像一份病历，不像一段关系。名字明明已经被记住（persona.md 里有身份事实），却没有一个「栖语怎么叫我」的正式设定；新用户从第一次见面到被记住名字，全靠对话里碰运气。

## 方案

引入「称呼」：用户自填的名称（名字、昵称、代号均可，不要求真名）。首见引导用栖语口吻问一句、给一个可跳过的输入框；称呼存进 persona.md 总览的受保护设定行，记忆文件指称用户与栖语对话称呼一律用它，不再写「用户」。三个写入口（引导、记忆中心、对话自述），没设就维持现状。

## 用户故事

1. 作为新用户，我想在第一次见面时被栖语问一句「怎么称呼你」，以便栖语从一开始就用我喜欢的方式叫我。
2. 作为新用户，我想跳过这个问题直接开始聊天，以便不被任何表单挡在产品外。
3. 作为新用户，我想只回答这一个问题时不被追问生日、职业等其他信息，以便见面像聊天而不像注册。
4. 作为老用户，我想在记忆中心看到栖语当前怎么称呼我并能修改，以便称呼始终由我掌握。
5. 作为老用户，我想在对话里直接说「以后叫我老王」就生效，以便不必去翻设置。
6. 作为老用户，我在记忆中心读自己的记忆时，希望看到「凯奇道早安」而不是「用户道早安」，以便读起来像自己的故事。
7. 作为老用户，我希望栖语在打招呼、重要时刻自然地叫我的称呼，以便感到被记住；也希望它不每轮都叫我名字，以免像客服。
8. 作为老用户，我希望切换称呼后旧的记忆不被篡改，以便记忆保持诚实；新内容自然用新称呼。
9. 作为没设称呼的用户，我希望记忆和对话维持原来的样子（「用户」「你」），以便体验没有任何退化。
10. 作为没设称呼的用户，我不希望栖语自作主张给我起昵称，以便称呼权完全在我。
11. 作为在意隐私的用户，我希望除称呼外的手机号、证件号、住址等仍按原规则脱敏，以便称呼豁免不扩大成隐私放松。
12. 作为在意隐私的用户，我希望称呼是我主动给的、用途明说的一项，以便我理解它为什么可以原值保存。
13. 作为遇到 persona.md 损坏的用户，我希望恢复流程把称呼行从原件里抢救出来，以便不因为一次文件损坏就被叫错。
14. 作为遇到最坏损坏的用户，即使称呼行救不回来，我也希望系统退回「未设置」而不是编一个称呼，并能在记忆中心重设。
15. 作为使用记忆整理功能（日终、Dream、月压缩）的用户，我希望整理出的新内容自动用我的称呼，以便一致性无需我操心。
16. 作为输入奇怪称呼（梗、代号）的用户，我希望只受格式限制不受语义审查，以便称呼自由是我的自由。
17. 作为输入含换行或超长文本的用户，我希望被格式校验拦下，以便 persona.md 结构和 prompt 装配不被破坏。
18. 作为看过首见页的用户，我希望引导文案仍是栖语的口吻（「嗨。我是栖语。」那一页），以便加输入框不变成贴注册表单。
19. 作为关掉引导直接聊天的用户，我希望之后仍可在记忆中心补设称呼，以便错过首见也有入口。
20. 作为多设备场景（换记忆目录）的用户，我希望称呼随 persona.md 走、随记忆备份走，以便不因目录迁移丢失。

## 实现决策

拷问定案（十条）：

1. **范围**：记忆文件指称用户＋栖语对话称呼用户，都用称呼；记忆文件不再写「用户」。
2. **定义**：称呼是用户自填名称，非结构化姓名（不分姓／名），不要求真名。
3. **收集项**：引导只收称呼一项；作息、生日等一律靠 PersonaTree 自然学。
4. **引导形式**：现有首见页加可跳过输入框，文案用栖语口吻；不阻塞进入聊天；Host 端 onboarding API 扩展接收称呼。
5. **隐私豁免**：修订设计笔记隐私原则——称呼（主动提供、用途明示）可原值保存并进入记忆文件与 prompt；其余私密标识不存原值规则不变。笔记已改。
6. **存储**：persona.md 总览内一行受保护用户设定行（如「称呼：凯奇」）。不属于 PersonaTree 画像、不经证据链；所有写 persona.md 的路径（Dream 总览刷新、日终维护、记忆损坏恢复）必须原样保留该行；恢复先从隔离原件抢救，救不回则退回未设置。已立 ADR 0005。
7. **写入口**：首见引导、记忆中心（Persona 区展示并可改）、对话中明确自述（当轮生效）。对话自述的在线写路径复用「用户明确纠正」的既有在线例外机制的精神，具体挂接点实现期定。
8. **旧记忆**：episodes 证据不动（保持「用户」）；每日状态包每日重建、persona 总览与 long-memory 下次 Dream、月压缩下月首次对话，投影按各自节奏自然换称呼；不做批量改写。
9. **兜底**：称呼未设置时维持现状惯例（记忆写「用户」、对话用「你」）；不替用户编昵称；互动中自然形成的昵称仍按共同过往既有规则。
10. **校验**：仅格式校验——非空、去首尾空白、限长约 20 字、禁换行与控制字符；不做语义审查。

改动面：

- Host：onboarding 状态与路由扩展（称呼字段）；persona.md 读写与全部写入路径的设定行圆桩；记忆损坏恢复的抢救逻辑；记忆整理各段 prompt（episode 整理、日终理解、PersonaTree 提炼、月压缩、Dream、每日状态包、memory_recall 相关表述规则）从「用户」惯例切换为「有称呼用称呼、无称呼用用户」。
- Flutter：首见页输入框与文案；onboarding 客户端与视图模型；记忆中心 Persona 区展示与编辑称呼。
- prompt 装配：称呼随 persona.md 总览的 persona 块每轮注入，装配器无需新增注入源；需保证受保护行格式不破坏装配。
- **契约不动**：本地规则引擎（行为基准、golden 锁定输出）的回复不改称谓，称呼的自然使用由模型回复层承担；`contracts/qiyu_behavior_contracts.json` 与 Core 消费测试无需变更。

## 测试决策

只测外部行为，不测实现细节。三条既有缝，不开新缝：

1. **Host 服务层**（最高缝）：注入式测试——onboarding 读写称呼；Dream/日终/恢复各路径写 persona.md 后设定行原样保留；损坏恢复能从隔离原件抢救称呼行、抢救不出退回未设置。先例：local_chat_service、memory_recovery 的注入式测试模式。
2. **HTTP 面**：onboarding 路由请求携带称呼的验收与格式校验（非空／超长／换行被拒），以及未带称呼的向后兼容。
3. **Flutter widget 层**：首见页输入→完成、跳过→完成两路；记忆中心 Persona 区查看与修改称呼。先例：现有 widget 测试模式。

prompt 惯例切换用 prompt builder 单测断言指令文本包含称呼规则；门禁按仓库惯例跑全量 verify-release-baseline。

## 范围外

- 不引导收集生日、作息、性别、年龄、职业等任何其他信息。
- 不做称呼的语义审查或禁语拦截。
- 不批量改写既有记忆内容（含 sessions 层）。
- 本地规则引擎兜底回复不插入称呼，golden 与契约不变。
- 不做栖语主动追问称呼（跳过后聊天里自然补问的行为留待后续设计）。
- 不迁移旧 localStorage / 旧 Node 轨道（早已退役）。
