# Episode RAG 按需记忆召回 Specs

## 问题陈述

栖语已经通过 Markdown 保存会话、episodes、日常状态、月摘要及 PersonaTree，并按既有五段节奏整理记忆。用户希望保留这些文件及其职责，同时改善对旧事的召回：当同一件事换了说法、使用指代或只有模糊时间线索时，模型先选择目录索引、再选择记忆文件的定位过程可能漏掉相关证据。

现有两阶段 RAG 是实验，索引原始 sessions；实验沙箱展示候选，没有调用聊天模型验证最终回答，也没有完成与旧召回的同题对照。因此不能直接把实验接入视为产品效果已经改善。产品需要以整理后的 episodes 为唯一 RAG 语料，补齐启用、有效性、隐私、后台同步、失败状态与双端接入。

## 解决方案

模型仍通过 `memory_recall{query}` 表达已知对象、事情和时间线索。用户明确配置并启用独立 embedding 服务后，由 RAG 直接定位 episodes，命中后回读当前摘要与证据，交给已有回答模型决定是否使用。

每条有效 episode 只用日期与摘要生成一个向量。原话摘录不参与 embedding，sessions、月摘要及 PersonaTree 不进入 RAG 索引；其他记忆文件、五段整理节奏和热层每轮直接使用保持现有职责。向量索引是可丢弃、可重建的本机派生缓存，Markdown 仍是事实来源。

未启用 RAG 时保留现有目录召回。启用后，准备、失败和需重建状态明确展示，不静默切回旧召回。正常聊天首响不等待检索，文字与 Omni 延续现有交付方式。以同题最终回答对照检验旧事召回是否改善，同时报告时间类查询、摘要缺失细节及纠正漏召回的限制。

## 实施决策

### 记忆职责与模块边界

- “记忆分层”与“五段节奏”沿用领域词汇表，不新增同时指代两者的“五层”概念。Markdown 为事实来源；向量不得用于恢复、改写或补造记忆事实。
- RAG 的唯一语料是有效 episodes，沿用既有条目有效性规则，排除空条目、簿记及关系信号条目。月摘要、PersonaTree、sessions 和归档画像不进入 RAG；热层直接使用。
- 在平台无关本机 Host 中提供 episode RAG 模块，收拢 embedding 请求、索引、来源校验及后台更新。Host 组合根创建一个实例，共享召回编排同时供文字和 Omni 使用。
- 以现有召回编排的定位入口替换启用后的目录选择过程，保留未启用时的旧定位适配。客户端只负责配置和状态，不持有主持久化、原始 Key 或向量实现。
- 只复用实验中必要的客户端、向量计算及有效测试思路；原实验保留，不将完整实验、私人语料或实验凭据策略引入产品。

### 隐藏动作与回答交付

- 保留初始 `memory_recall{query}`。query 是可独立理解的语义查找目标，可用已知语境消解指代，不编造细节；沿用 100 runes 上限。
- 查询 embedding 只接收脱敏后的 query。不拼接最近对话全文，不增加独立 query 改写调用、日期字段、时间解析器或硬日期过滤。
- 中英文隐藏协议与 Omni 工具说明同步改为语义查询。旧 `months/dates/paths` 选择字段保留解析，供未启用路径使用；`entries` 是组织回答时的证据回执，不与定位字段一并删除。
- 检索只产生候选。文字复用已有组织回答调用，Omni 由收到工具结果的回答模型判断；首版不增加独立 grader、reranker 或固定相似度阈值。
- 文字结果区分明确使用、明确拒绝和未完成判断。明确拒绝不补气泡、不建立下一轮候选；明确使用只接受本轮有效条目引用，不把空、无效或缺失回执统一扩成全部候选。
- 调用异常或解析失败属于未完成判断，不能冒充明确拒绝或没有候选。未判断材料可按现有规则作为下一用户轮一次性临时候选，消费前重新核对来源、控制规则及脱敏；本次拒绝不生成永久拒绝记忆。
- Omni 工具结果区分有候选、无有效候选和暂不可用。有候选不表示已确认相关或答案已成立。
- 文字首响不强制等待 RAG，保留现有 8 秒补气泡窗口及下一轮一次性临时上下文。Omni 沿用静默工具轮、用户抢话、取消与续答门控；候选进入既有临时记忆上下文，不成为持久 system 内容。
- 不改变 Provider 终止校验、可见输出安全校验、requestId 幂等、取消保留可重试用户 turn 或本地降级话术。

### 索引格式与工程默认值

| 项目 | 首版约定 |
| --- | --- |
| 嵌入单元 | 每条有效 episode 一个向量 |
| episode 输入 | 日期、换行、当前摘要；发送前执行控制过滤与秘密脱敏 |
| 不发送为 episode embedding 的内容 | 证据摘录、条目 ID、来源引用、输入 hash、原始 sessions |
| 本机记录 | 日期、稳定条目 ID、输入 SHA-256、Float32 向量；不缓存私人 query 或原话摘录 |
| 索引身份 | 规范化服务地址、模型、输入格式版本、实际维度，不包含 Key |
| 存储 | 本机单一 NDJSON 派生索引，首行记录格式及模型身份；临时文件完整写入后原子替换 |
| 排名 | 精确余弦，最多 10 条当前有效候选；按日期与稳定 ID 去重，并确定性处理同分 |
| 回读 | 用日期与稳定 ID 读取当前摘要及已有证据摘录，再过滤、脱敏与裁剪 |
| 上下文预算 | 沿用既有条目裁剪与 1200 runes 临时上下文预算 |
| 查询时限 | embedding 10 秒；不延长文字 8 秒补气泡窗口 |
| 后台构建 | 每批最多 10 条、每批 30 秒；首次失败不发布部分索引 |
| 增量失败 | 已有有效索引可用，失败条目保留待处理并显示失败，允许明确重试 |
| 缓存异常 | 缺失、损坏或身份不符显示需重建，用户明确发起后重建 |

这些是首版工程默认值，不是实测性能或费用承诺。输入、向量和响应需校验非空、条目数量、维度一致性、有限数值及可计算性；不合法响应不可进入有效索引。首版不增加数据库、平台原生向量库、Node 运行时或用户调参面板。

摘要未保留的细节不能用于向量定位；命中后有证据摘录也不保证能找到只在摘录中出现的词。空语料的完整构建可完成为零条就绪索引，查询返回无有效候选。

### 来源有效性、同步与维护

1. 明确启用后枚举当前有效 episodes，完成过滤、脱敏与完整构建，成功前不开放首次查询。
2. episode 成功写入后只调度后台同步，网络请求在记忆锁之外进行，不阻塞写入或可见回复。发布结果前重新核对来源与控制状态。
3. 摘要或日期改变使旧输入 hash 不匹配，旧向量立即不可用，新向量完成后恢复；只改证据摘录不重算向量，回答始终回读当前证据。
4. 删除、禁提、冻结及无效条目先停止使用，再清理派生记录。新增条目接受后台延迟；增量期间只检索仍有效的旧条目。
5. 启动、后台同步、查询发送、候选回读与下一轮消费共用来源有效性规则。手工文件变化即使未触发写入回调，也须由当前来源检查发现；不承诺外部编辑器与 Host 具有跨文件原子事务。
6. 恢复扫描、隔离、重建或来源缺失纳入有效性核对，不只追加新 ID。解除控制后仍需按当前来源验证，不自动绕过既有解除规则。
7. 索引任务加入现有维护入口的暂停与排空，覆盖备份导入、回滚及清除。维护完成后不得发布旧来源的在途结果，缓存失效并显示明确重建状态。
8. 向量缓存同时排除于备份导出和本机快照，清除产品数据时一并清除；不从向量恢复记忆事实。
9. 不新增跨 episode 的 supersedes 或语义纠正关系。不同 ID 的新条目纠正旧条目不会自动改变旧条目 hash；沿用当前消息、热层和近期对话的事实优先级，由回答模型判断。漏召回最新纠正是明确的评测限制。

### 配置、凭据与操作契约

- 首版支持独立 OpenAI-compatible embedding 地址、模型及 API Key，不增加服务商预设和模型目录。
- 配置与 Key 沿用本机 Host 现有独立设置分段及读改写事务，写入不得覆盖聊天、语音或未知设置段。不借用聊天凭据；用户可以主动填写相同 Key。
- 凭据作用域由协议与规范化服务地址确定。换地址不得沿用旧 Key；同一作用域留空可沿用已有 Key，明确忘记后清除。模型变化影响向量身份，不单独改变凭据作用域。
- 读取配置及状态只返回地址、模型、启用情况、`keySet`、构建进度、待更新数量及允许列表诊断，不返回明文 Key。
- 操作契约包含读取、保存、连接测试、启用、停用、重建、重试及忘记 Key。保存不启用、不自动重建；测试只发送固定非私人文本。
- 首次启用前说明历史有效 episode 的日期及摘要会发送至所配置服务，查询发送语义 query，费用按该服务计费。证据摘录不会发给 embedding，但会按现有候选外发规则供配置的回答模型使用。
- 更换地址、模型或其他向量身份后旧索引停止查询，显示需重建，由用户明确重建。仅换同作用域 Key 不重算索引。
- 未启用时使用旧目录召回；明确停用后返回旧路径。已启用但准备中、失败、需重建或忘记 Key 时不自动停用或回退。
- 复用 Host 会话、同源 Origin 与 CSRF 规则，设置及诊断沿用秘密脱敏、允许列表错误输出；不返回第三方错误原文或本机路径。

### 设置与聊天状态

设置页在聊天模型配置后增加独立“记忆召回”分节，提供地址、模型、Key 输入及上述操作。Windows 网页版、Windows App 和 Android 使用相同配置与状态语义，不增加远程记忆服务。

| 状态 | 含义与行为 |
| --- | --- |
| 未启用 | 使用旧目录召回；保存配置不改变此状态 |
| 准备中 | 首次完整构建进行中，显示完成量；正常聊天继续，RAG 不查询 |
| 已就绪 | 当前身份下的有效索引可查询；空库允许零条就绪 |
| 更新中 | 新增或变更条目处理中，显示待处理量；仍有效的已有条目可查询 |
| 需重建 | 身份变化、缓存缺失或损坏、维护后失效，等待明确重建 |
| 暂不可用 | 启用后的凭据、请求或构建失败；显示简短原因及合适的重试入口 |

索引持久状态与单次查询失败分别表达：一次查询失败不谎称记忆为空，不无理由销毁仍有效的索引。设置页展示完整状态，聊天输入附近展示简短独立状态；状态不作为气泡或 turn，不写入 sessions，不遮挡 Omni 通话栏。按可见页面生命周期刷新，离开页面或应用进入后台时停止刷新，不增加永久全局轮询器。

## 测试决策

### 测试入口与既有先例

- 测试外部可观察行为：模型收到什么候选、用户看到什么回复与状态、控制后的内容是否消失、维护后是否有旧结果重新出现、配置是否泄露或覆盖。避免只断言内部调用顺序、私有容器或与实现同形的计算。
- 主要集成入口沿用共享召回编排，文字与 Omni 用相同合成记忆及可控 embedding／Provider 返回验证；复用现有临时上下文、组织气泡、禁提和 realtime 工具测试。
- 配置通过现有 Host 设置 API 测试入口验证，参照独立 STT／TTS 设置的保存、测试、Key scope、忘记凭据和分段保留用例。
- 生命周期通过现有维护、恢复、备份与清除入口验证；网络、时钟、Provider、存储及原子写入沿用已有依赖注入能力。新增 seam 仅限 embedding 外部请求及必要的后台完成控制，不为测试重塑产品接口。
- Flutter 使用现有设置 gateway／view model 和聊天 widget 测试入口检查操作、状态及展示，不把 Host 网络实现复制进界面测试。
- 小规模固定向量用例仅验证精确余弦排名、同分稳定性和输入校验；整体接入效果以公共编排入口为准。

### 自动化覆盖

| 场景 | 必须验证的行为 |
| --- | --- |
| 未启用与明确停用 | 旧召回可用；启用后的故障不能进入旧路径 |
| 空库与首次构建 | 零条完整索引可就绪；首次失败或未完成不发布部分索引 |
| embedding 响应 | 正常请求可用；空向量、数量错误、零范数、非有限值、维度不符等不能发布 |
| 请求失败 | 授权失败、限流、网络、原生错误和超时均为真实不可用；不冒充没有候选 |
| 索引身份 | 同维度不同模型仍使旧索引不可用；缺失、损坏或身份变化需明确重建 |
| 凭据与事务 | 聊天 Key 不借用；换作用域不沿用旧 Key；同作用域换 Key 不重算；其他配置段不丢失 |
| 增量与编辑 | 新增不阻塞回复；摘要编辑立即停用旧向量；证据编辑回读新内容且无需重复 embedding |
| 控制与文件变化 | 删除、禁提、冻结、手工编辑及来源消失在出仓和下轮消费前生效 |
| 后台竞争 | 在途请求完成后来源已改变，不得重新发布旧条目；失败可明确重试，不无限立即重试 |
| 维护与备份 | 导入、回滚、恢复和清除后不复活旧候选；向量不进导出或本机快照 |
| 文字结果 | 明确使用、明确拒绝、未判断分开；空或无效回执不扩成全部候选；拒绝后无 pending |
| 文字时间 | 首响不等待；8 秒内按现有规则补气泡；晚到候选下一用户轮只消费一次且重验 |
| Omni | 有候选、无有效候选、暂不可用区分；抢话、取消、停用和迟到结果遵守续答门控 |
| 隐私 | query、embedding 输入、回读证据、临时上下文与错误均过滤脱敏；API 不返回明文 Key |
| UI 与双端 | 设置操作和状态一致；状态不进消息历史；Windows Web／App 与 Android 共用行为 |
| 原有交付 | Provider 完成、安全校验、幂等、取消、晚安与本地降级相关回归不变 |

### 同题最终回答对照

- 默认准备约 40 条本机评测问题，覆盖换说法、指代、模糊时间、无答案、部分答案及纠正场景，并标注正确证据引用。
- 新旧使用同一记忆快照、聊天模型及评测时点。新方案只索引 episodes，按事实报告与旧目录语料的覆盖差异；不删除不利样本。
- 每题分别记录证据命中、最终回答是否有来源依据、是否错误自信、等待时间、请求次数及实际可得费用。不能取得费用时报告请求与输入规模，不编造价格。
- 重点披露摘要未覆盖原话细节、时间判断和漏召回最新纠正的失败。模型有随机性，逐题展示变化，不将小样本解释为普遍保证。
- 通过口径：确定的隐私、有效性、幂等及交付回归全部通过；换说法、指代和时间三类目标题有可核查的净改善，并分别报告表现；无答案／部分答案没有新增系统性的错误自信。
- 原始 sessions 实验 recall 数字与只打印候选的沙箱不能替代上述产品验收。若实测未支持目标，记录未达标并按证据调整，不宣称改善。
- 私人语料和原始敏感对话只留本机，规格及可分享报告使用合成或脱敏材料。
